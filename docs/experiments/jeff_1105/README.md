# jeff_1105: 로컬 결정 모델 `jeff` 오프라인 측정 (dev)

> 측정 **전에** 쓴다. dev 전용이고 운영을 바꾸지 않는다. 사용자 결정(11-05): `Jev` 컨셉을 개발용으로 따로 빼서 지금 시험한다. 진짜 `Jev` 는 키가 없어 같은 API 를 구현한 로컬 서버 `jeff` 로 먼저 잰다.

## 1. 왜

- 지금 손실이 큰 곳은 거르기와 판정이다. 9B 거르기는 상위 5편에서 정밀도 49.3% · 재현율 82.6% 이고, 판정 '없음' 22건 중 11건이 거짓이었다.
- 문서마다 따로 판정하는 안은 호출이 1번에서 15번으로 늘어 9B 로는 미뤘다(`filter_input_1104`). 결정 모델은 문서마다 예/아니오 확률만 내므로 이 자리에 맞다.
- `Jev` 는 가중치가 비공개라 로컬로 못 돌린다. `jeff`(`logan-markewich/jeff`, MIT)는 같은 `POST /v1/systemone` 을 `GLiFormer`(`knowledgator/gliformer-large-v1`, 400M 파라미터)로 구현한다.
- **사전 정보:** `jeff` 저장소가 옮긴 JevBench v1.2.2 공식 실행에서 judge 61.6%(Jev 94.5%) · hard 37.7%(Jev 74.1%)다. 모델 카드는 영어 과제만 평가했다고 밝히는데 우리 질문은 한국어다. 미달할 가능성이 크다. **`jeff` 미달은 `Jev` 미달의 근거가 아니다.**

## 2. 분리

- 코드 · venv · 가중치는 맥미니 내장 `~/dev/jeff_1105/` 에 둔다. 저장소에 넣지 않는다. 코드 커밋 `34b32f99`, 가중치 리비전은 `models/gliformer-large-v1.revision`, 패키지는 `logs/pip_freeze.txt` 에 남긴다.
- 서버는 `127.0.0.1:8090` 에서만 받고, `.env` 없는 깨끗한 환경으로 띄우며, `HF_HUB_OFFLINE=1` 이다. launchd 에 등록하지 않고 측정이 끝나면 끈다.
- 운영 `.venv` 는 평가 스크립트 실행에만 쓰고 패키지를 더하지 않는다. `.env` · 봇 코드는 바꾸지 않고 **Chroma 호출은 0** 이다. 입력은 저장된 파일뿐이다.
- `pytorch_model.bin` 은 pickle 이라 불러오기 전에 `check_weights.py` 로 import 목록을 본다. 허용 목록 밖이 하나라도 있으면 중단한다. `gliformer` 로더 코드도 실행 전에 읽는다.
- 메모리 보호: 스크립트가 25건마다 여유 메모리와 스왑을 본다. 여유가 12% 미만이면 기다리고, 스왑이 6GB 를 넘으면 멈춘다(이어 하기 가능).
- 실사용 질문은 `SYS1_URL` 이 로컬일 때만 쓰고, 결과에는 해시만 남긴다.

## 3. 입력과 질문 (측정 전 고정)

`noul` 질문 하나를 세 자리 중 거르기 · 판정에 함께 쓴다. 문구는 [`run.py`](run.py) 의 `INSTR` · `CRIT` 이고, 판정 `OPEN_TAIL` 의 뜻을 옮겼다.

```
Does this paper mainly address the topic of the request below? Request: {요청}
true: the paper's main subject is this topic, even if its methods or wording differ
false: it only shares some words or the broad field, and its main subject is a different problem
```

**문턱은 `noul ≥ 0.5` 로 고정한다.** `jeff` 의 온도 보정은 0.5 를 넘는지 여부를 바꾸지 않는다.

| 자리 | 입력 | 결정 |
|---|---|---|
| 거르기 | `topic_filter_1104/pool_hu.jsonl` 116줄의 상위 5편 = 580건. 요청은 주제 줄 `line`(모두 영어), 문서는 9B 와 같은 `_brief`(제목 + 본문 600자) | 0.5 이상 남김. 9B 와 같은 후처리: 하나도 안 남으면 5편 유지, 질문 속 고유 이름이 제목에 든 문서 보호 |
| 판정 K (주 지표) | `open_judge_1103/oj_dev.jsonl` 167문항의 저장 컨텍스트 문서 전부. 요청은 한국어 질문 원문, 문서는 9B 가 본 블록 그대로 | 0.5 이상이 하나도 없으면 '없음' |
| 판정 E (보고) | 같은 문항. 요청만 저장된 영어 검색어 `rag_queries` | K 와 같음. K 가 결정당 중앙 1.5초를 넘으면 라벨 달린 33문항만 |
| 분기 (보고) | 합성 25(`router_open_1103/proto.py` 의 지킬 17 · RAG 8), real40 중 RAG 경로 34, 실사용 고유 71 | `choice` 4갈래(`paper_research` · `chat` · `tool` · `coding`) |

새 라벨은 달지 않는다. 라벨은 기존 `labels_hu.tsv` · `labels_pool.tsv` · `open_judge_1103/labels*.tsv` 를 그대로 쓴다. held-out 은 쓰지 않는다.

## 5. 결정 규칙

- **거르기 · 판정 K 둘 다 통과:** `jeff` 를 꺼 둔 플래그로 거르기 자리에 붙여 `eval_e2e_ko.py` dev 라운드를 따로 사전 등록한다.
- **하나라도 미달:** `jeff` 는 운영 후보에서 뺀다. `run.py` 는 진짜 `Jev` · 새 맥미니 비교에 그대로 쓴다.
- 문턱이나 문구를 바꾸면 통과하더라도 같은 데이터로 통과 처리하지 않고 힌트로만 적는다.
- E 만 통과하면 언어 문제로 적고, 결정은 K 기준으로 한다.
- 운영 변화는 어느 경우에도 없다.

이미 여러 라운드에서 본 dev 라벨이고, 라벨은 Claude 한 명이 달았다. 거르기 입력은 영어 주제 줄이라 운영의 한국어 질문과 다르다. 판정 라벨은 저장 '없음' 33문항뿐이라 G1 · G2 표본이 작다(F 23 · T 3 · ? 7).

## 7. 결과

측정 11-05 21:07–21:30(2,180건). `jeff` 커밋 `34b32f99`, 가중치 리비전 `d0a4e53d`, `gliformer` 0.1.4 · `torch` 2.15.0 · `transformers` 5.22.1, `mps` · fp32. pickle 검사 통과(`OrderedDict` · `FloatStorage` · `_rebuild_tensor_v2` 만)이고 `gliner` 로더는 `weights_only=True` 다. 서버 오류와 HTTP 오류는 0 이다. 지표는 `run.py` 와 별도로 원본 파일에서 다시 계산해 일치를 확인했다.

| 기준 | `jeff` | 9B | 결과 |
|---|---|---|---|
| 거르기 정밀도 ≥ 60% | **38.5%** | 49.3% | **미달** |
| 거르기 재현율 ≥ 78% | 95.5% | 82.6% | 통과 |
| 판정 K G1 F 회복 ≥ 70% | 23/23 | 19/23 | 통과 |
| 판정 K G2 T · ? 바뀜 ≤ 20% | **10/10** | 4/10 | **미달** |
| 판정 K G3 새 '없음' ≤ 3 | 1/134 | 0/134 | 통과 |

**결정:** 규칙대로 `jeff` 는 운영 후보에서 뺀다. 운영 변화는 없다. `run.py` 는 진짜 `Jev` · 새 맥미니 비교에 그대로 쓴다.

**본 것**
- **구별을 못 한다.** 580건 중 556건을 남겼다. 정밀도 38.5% 는 풀의 주제 안 비율 38.6% 와 같아 다 남기는 것과 차이가 없다. AUC 0.635, 주제 안 중앙 0.768 · 주제 밖 중앙 0.713 이다. 문턱을 올려도 0.7 에서 P 42.6% · R 75.9% 다.
- **'없음'을 거의 내지 않는다.** 167문항 중 K 1 · E 0 이다. G1 100% 는 실력이 아니라 늘 '있음'이라서 나온 값이다.
- **언어만의 문제가 아니다.** 거르기 입력은 영어 주제 줄이고, 판정 E(영어 검색어)도 K 와 같았다(G1 23/23 · G2 10/10 · G3 0/134). 한국어 성능은 이 측정으로 가릴 수 없다.
- **분기(보고):** 합성 지킴 11/17 · 합성 RAG 4/8 · real40 24/34 · 실사용 1단계 기준 37/49. 합성 지킴에서 `tool` 을 한 번도 고르지 않았다(`chat` 11 · `paper_research` 6). 지금 라우터를 대신할 수준이 아니다.
- **속도:** 결정당 중앙 거르기 0.33초 · 판정 0.72초 · 분기 0.27초. 5편이면 약 1.7초로 9B 호출 중앙 5.75초보다 빠르다.
- **메모리:** 서버를 올리면 여유가 78% 에서 54% 로 줄었다. 스왑은 2.69GB 에서 5.17GB 로 늘었고 서버를 꺼도 바로 줄지 않는다(§2 의 6GB 멈춤은 발동하지 않았다).
- **§2 와 다른 점:** 분기의 실사용 기준값을 만드는 `router_step1_hard_rules` 가 `is_academic_query_full` 로 운영 Ollama 의 `yunsur_v13` 를 불렀다(21:29 에 47회). 모델이 메모리에 올라와 스왑이 2.69GB 에서 3.83GB 로 뛴 때가 이때다. 진짜 `Jev` 로 잴 때는 `run.py router` 를 돌려도 실사용 문항을 빼므로 이 호출이 없다. 측정 중 봇 작업은 0건이었다(마지막 작업은 3일 전).
- **`router_open_1103` 보정:** 그 문서는 1단계를 'LLM 흔들림 없는 하드룰'이라 적었지만, 이 경로에는 LLM 호출이 들어 있다.

**본 뒤에 더한 점검(사전 등록 아님, 통과 판정에 쓰지 않음)**
- **배관 점검(`run.py control`):** 무관해야 할 짝에서도 '예'가 많다. 다른 문항 주제 줄 47/50(중앙 0.665), 분야가 전혀 다른 요청 31/50(중앙 0.529).
- **단순 문구 v2(`Is this paper about: {요청}?`, 조건 설명 없음):** P 38.5% · R 93.3% · AUC 0.599, 분야가 다른 요청 38/50. 문구 탓이 아니다.
- **설치 점검(`repro.py`):** 잠금 파일보다 새 패키지를 깔았으므로 저자의 공개 자료를 재현했다. sst2 · boolq 각 200건에서 저자 저장 결과 `large/default` 와 상관 1.0000 · 0.5 일치 200/200 · AUROC 0.991 · 0.750 으로 같다. 설치 문제가 아니다.
- 같은 저장 파일의 진짜 `Jev` 출력은 sst2 0.996 · boolq 0.954 다. `jeff` 와의 차이는 독해형 예/아니오에서 크다. 이 값은 공개 영어 자료이고 우리 과제에 대한 값이 아니다.

**해석:** `jeff` 는 긍정 · 부정처럼 글 자체의 성질을 묻는 질문은 잘하지만(sst2 0.991), 글과 요청이 맞는지 따지는 질문은 약하다(boolq 0.750). 우리 거르기 · 판정은 뒤쪽이고, 후보가 모두 검색으로 뽑힌 이웃 문서라 더 어렵다. **이 결과는 `Jev` 미달의 근거가 아니다.** `Jev` 는 키가 생기면 `SYS1_URL` · `SYS1_KEY` · `SYS1_LABEL` 만 바꿔 같은 스크립트로 잰다. 외부 전송이 되므로 그때 입력에 실사용에서 온 질문이 있는지 먼저 확인한다(`run.py` 는 로컬이 아니면 실사용 질문을 뺀다).

**남은 것:** `~/dev/jeff_1105`(코드 · venv · 가중치)는 지우지 않았다. launchd 등록은 없고 서버는 꺼져 있다.

## 8. 진짜 `Jev` 로 잴 때 (측정 전 고정, 사용자 결정 11-05: 키 신청)

`jeff` 와 같은 입력 · 문구 · 문턱 0.5 · 기준 · 결정 규칙을 쓴다(§3–§5). 모델은 `jev-1.14.0` 으로 고정한다.

- **밖으로 나가는 것:** dev 평가 질문, 공개 논문의 제목 · 초록 · 발췌, 합성 분기 문장. 서버는 미국이다. 입력을 학습에 쓰지 않는다고 하지만 보관 기간은 공개되어 있지 않다.
- **보내지 않는 것:** 브리지 DB 의 실사용 질문과 글자가 같은 문항, 실사용을 넣은 `jn_dev` 10문항 전부. 그래서 판정은 157문항이고, 표에는 9B 도 같은 157문항으로 다시 계산해 적는다.
- **키:** 맥미니 `~/dev/jeff_1105/jev.key`(권한 600)에만 둔다. 채팅 · `.env` · 저장소에 넣지 않고 출력하지 않는다.
- **순서:** `smoke` 로 응답 형식과 모델 이름을 먼저 본다. 그다음 `filter` · `judge K` · `judge E` · `router` · `score` 다. 운영 Ollama 호출은 없다.

```bash
export SYS1_URL=https://api.typesafe.ai SYS1_KEY_FILE=~/dev/jeff_1105/jev.key SYS1_LABEL=jev SYS1_MODEL=jev-1.14.0
.venv/bin/python docs/experiments/jeff_1105/run.py smoke
```

**결정 규칙:** 거르기 · 판정 K 둘 다 통과하면 거르기 자리에 꺼 둔 플래그로 붙여 `eval_e2e_ko.py` dev 라운드를 따로 사전 등록한다. 이 경우 운영에는 외부 의존과 대체 경로(실패 시 9B)가 함께 들어가므로 사용자 결정을 받는다. 하나라도 미달이면 `Jev` 안을 접고 새 맥미니 모델 비교로 간다.

**한계:** 평가 라벨이 있는 표본이 작고(G1 · G2), 벤더 수치는 재지 않는다. 비용은 벤더 가격 기준 약 2,000건에 10센트 이하로 추정한다.
