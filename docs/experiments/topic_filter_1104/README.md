## 1. 바꿔 볼 것

질문 전체로 한 번 거르는 대신 **주제 줄마다 따로** 거른다. 원래 검색(질문 전체) 블록은 붙이지 않는다 — 그쪽을 다시 거르면 같은 문제가 생긴다. 모든 주제가 비면 지금 경로(대조)로 돌아간다.

| 판 | 주제마다 | '없음' 이면 |
|---|---|---|
| V0 | 상위 3편, 거르기 없음 (상한 확인용) | |
| V1 | 상위 5편 거르기 → 앞 3편 | 거르지 않은 앞 3편 (`filter_relevant` 지금 동작) |
| V2 | 상위 5편 거르기 → 앞 3편 | 그 주제를 버림 (DB 에 없는 주제의 잡음 — HU31) |
| V3 | 상위 3편 거르기 | 거르지 않은 3편 |

주제별 결과는 번갈아 합쳐 10편까지(`_interleave_topic_blocks` 와 같은 순서).

## 2. 방법

- **문항:** HU40(이제 dev). 대조 `ts0_hu` 그대로. HU40 은 안 나뉘어 동점. 주제 줄은 `ts1_hu` 기록 그대로 고정.
- **풀 먼저 라벨, 거르기는 나중에:** 줄마다 검색 상위 5편을 모은다(`pool.py pool`, 답 생성 없음). 라벨은 풀 전체에 단다. **거르기 호출(`pool.py filter`)은 라벨을 다 단 뒤에 돌린다** — 어느 문서가 남을지 모른 채 단다. 2차 dev 15:3 이 부푼 이유 중 하나를 막는다.
- **한계:** 새 문서는 풀에서만 나오므로 '대조 대 처리' 를 완전히 가리지는 못한다. 묶음에 이미 라벨 단 대조 문서를 문항마다 2편까지 섞어(`pool.py packet`) 옛 라벨을 보지 않고 다시 달아 일치율을 잰다. 일치가 낮으면 이 비교는 믿지 않는다.
- **라벨 기준:** 2차 §3 과 같다. `labels_pool.tsv`.
- 채점은 `pool.py score` — 문항별 덮은 주제 수 부호 검정, 주제 밖 비율, 3편 미만으로 준 문항.

## 3. 다음 단계로 가는 기준 (dev 관문)

어느 판이든 아래를 모두 만족해야 새 held-out 으로 간다. 아니면 이 방향은 접는다.

| 지표 | 기준 |
|---|---|
| 덮은 하위 주제 많음 : 적음 (대조 `ts0_hu` 대비) | **부호 검정 양측 p < 0.05**, 많음 > 적음 |
| 주제 밖 문서 비율 | 대조 + **10%p 이하** |
| 대조는 3편 이상인데 3편 미만으로 준 문항 | **≤ 4** |
| 라벨 일치(섞은 대조 문서) | **80% 이상** |

여럿이 통과하면 주제 밖 비율이 가장 낮은 판 하나만 held-out 으로 간다. 네 판을 비교하므로 dev 결과는 유리하게 나온다. 여기서 이겨도 채택 근거가 아니다.

재지 않는 것: 답 단계, 시간(거르기 호출 시간만 기록). 잘못 나뉘는 단일 주제(2차 보호 2b 미달)는 관문을 통과한 뒤 따로 고친다.
