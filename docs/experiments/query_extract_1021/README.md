# 검색어 추출 개선 — 전문 용어 · 조건 유지, 일반어 금지 (사전 등록, 2026-10-21)

> 측정 **전에** 쓴다. 출발점: 실제 사용(10-19~20) — 같은 질문이 앞의 "1." 유무만으로 다른 논문을 가져오고(1차: 맞는 논문 없음 → 2차: SURE-RAG), "인용(citation)"을 참고문헌 형식으로 해석했으며, 검색어에 일반어(research 49 · academic 42 · paper(s) 24 · keywords 10 …, N 질문 기준)가 붙었다. 외부 검색은 v3 에서 일반어를 빼 무관 32 → 26%, 직접 맞는 논문 60 → 80% 가 됐다 — 같은 문제가 DB 검색에도 있다.

## 1. 바꾸는 것 — `RAG_QUERY_V2` (기본 `0`)

`_extract_english_rag_query` 의 프롬프트와 후처리:
- 질문 앞 목록 번호(`1.` · `1)` · `①` 등)를 지우고 넘긴다.
- 프롬프트: "논문을 찾는 영어 검색어 한 줄, 4~10단어, 쉼표 없이. 질문의 **구체 기법 · 과제 · 조건을 유지**. 한국어 전문 용어는 **표준 영어 연구 용어로**(예: 근거·충실성 → faithfulness grounding, 인용 → citation attribution, 모른다고 답하기 → abstention unanswerable, 환각 → hallucination). **일반어 금지**(research, paper, academic, study, survey, keywords, method, approach, trends). 목록 번호 · '찾아줘/정리해줘' 같은 요청어는 무시."
- 후처리: 영문 · 숫자 · 하이픈만 남기고, 외부 검색 v3 와 **같은 일반어 목록**(`core/rag/external_search.clean_query`)으로 한 번 더 빼고, 12단어까지.
- 대화 맥락을 넣는 경우(이어지는 질문)도 같은 프롬프트. 비교 질문의 두 대상 추출은 바꾸지 않는다.
- 예시 용어 4개는 피드백 질문(직무 질문지 D01 · D02 · D03)에서 가져왔다 — 그래서 주 지표는 그 질문들이 아닌 **held-out 30** 으로 본다.

## 2. 방법 (맥미니, 검색만 — 판정 끔, 운영 설정 그대로)

대조 `qx0_*`(`RAG_QUERY_V2=0`) · 처리 `qx1_*`(`=1`): 162 · real40 · real2(정답 있는 세트) + corpus_seed 의 held-out 30(H) · 직무 질문 34(D). 번갈아 같은 시간대.
- 관련성: H · D 의 두 조건 컨텍스트 논문을 질문별로 합쳐, 이미 판정한 (질문, 논문) 쌍(corpus_seed `judged_*`)은 그 판정을 쓰고, **새로 나온 쌍만** 섞어서 조건을 모른 채 0 · 1 · 2 로 판정한다.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** held-out 30 — 질문별 컨텍스트 '2' 논문 수 | 처리 > 대조, 부호 검정(동점 제외) 양측 p < 0.05 |
| 부: held-out 30 — '2' 있는 질문 수 | 보고 |
| 참고: 직무 질문 34 — 같은 두 지표 | 보고(예시 용어가 나온 질문 포함) |
| 보호: 정답 있는 세트 검색 ok(162 + real40 + real2 = 236) | 처리가 대조보다 3 이상 낮지 않음(짝 비교) |
| 보호: 검색어에 한글이 남은 문항 | 처리 ≤ 대조 |
| 보호: 검색 시간 중앙(162) | ≤ 대조 + 2s |
| 보고: 검색어 예(대조 · 처리), 검색어 평균 단어 수, 일반어가 남은 검색어 수 | |

채택이면 **사용자 승인 후** 운영 `.env` `RAG_QUERY_V2=1` + 봇 재시작.

예상: held-out '2' 논문 늘어난 질문 10 : 줄어든 3 안팎, 정답 있는 세트 ±3.
