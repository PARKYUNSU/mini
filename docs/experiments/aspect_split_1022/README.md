## 1. 바꾸는 것 — `RAG_ASPECT_SPLIT` (기본 `0`)

`1` 이면 RAG 답변 경로에서(비교 질문 · 이어지는 질문 재사용이 아닐 때) 질문에 나열 표지(`…나 / 이나 / 또는 / 혹은 / 및 / 랑 / 이랑 / 와 / 과` + 공백)가 있으면:
- 보조 LLM(`get_rag_query_rewrite_llm`, 비교 분리와 같은 것)에 "질문이 or/and 로 이은 **서로 다른 조건**을 묻는가? 그렇다면 조건마다 공통 주제를 포함한 짧은 영어 학술 검색어를 한 줄씩(2~3줄), 그 조건에 연구자들이 쓰는 표준 용어가 있으면 그것으로; 조건이 하나면 NONE".
- 조건마다 검색(비교 분리와 같은 설정)해 각 상위 2블록을 원래 검색 블록 앞에 합친다(`_merge_rag_blocks`, 같은 논문 한 번). 이후 top-5 · 관련 문서 거르기 등은 그대로.
- 프롬프트에 **구체적 용어 예시를 넣지 않는다**(query_extract_1021: 예시 용어가 무관한 질문에 새어 들어 기각).
- 코드 `core/graph/agent_nodes.py` `_extract_aspects`, 테스트 `tests/unit/test_aspect_split.py`.

**왜 안 됐나(처리 쪽 로그)**
- **분리 판단이 거의 안 걸린다:** 나열 표지가 걸린 문항마다 보조 LLM(v13)에 물었지만 조건 세트 12 중 **4개만** 조건을 나눴다(M02 · M06 · M09 · M12). **출발점인 M01("순서나 개수")은 `NONE`**. 74문항에서는 2개(real40 N12 · R05)가 나뉘었는데 N12 는 질문을 엉뚱하게 둘로 쪼갰다("prompt engineering … versus OAT speed comparison in multi-agent systems").
- **나눠도 정답 커버가 안 바뀐다:** M12 는 이미지 워터마크 논문이 하나 더 들어왔지만 그 조건은 원래 커버돼 있었고, 텍스트 · 에이전트 조건은 여전히 0. M02 는 'Weight quantization' 검색이 2606.22249(가중치 양자화 이론)를 가져왔으나 이 논문은 정답 목록(RaanA · SPEAR)에 없다 — **정답 목록이 조건별로 불완전**해 지표가 이런 이득을 못 센다(사전 등록 때 적은 한계).
- **시간:** 표지가 걸린 문항마다 보조 호출이 붙고(대부분 `NONE` 으로 헛걸음), 나뉜 문항은 검색이 두 번 더 든다 — +8.7s.

**읽은 것** — "조건마다 따로 검색"이라는 처방 자체가 틀렸다기보다, **9B 보조 모델이 조건이 여러 개인지 판단하지 못한다**(12 중 4, 출발점 질문도 놓침). 판단을 LLM 에 맡기지 않는 방식(한국어 "A나 B" · "A랑 B" 구문을 규칙으로 갈라 각각 기존 검색어 추출에 넣기)이 다음 후보이지만, 정답 목록을 조건별로 더 채우지 않으면 효과를 재기 어렵다. 운영 반영하지 않는다.
