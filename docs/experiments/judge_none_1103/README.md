# 거짓 '없음' 진단 — 정답 유무 판정이 어디서 틀리나 (2026-11-03, dev 만 · 운영 변경 없음)

`judge_off_1102` §4 의 대안 ②다. 정답 유무 판정(`RAG_PRESENCE_JUDGE`)이 '없음'을 낼 때 맞는지, 틀리면 어떤 질문에서 틀리는지 본다.

## 1. 방법

- 문항: 판정이 도는 dev 문항 434(질문 유형 라벨 X · ? · 이어짐 뺌) 중 80개(`select.py`, 시드 1103).
  - 실사용 24는 전부 넣었다.
  - 정규식이 놓친 수치 · 비교 13도 전부 넣었다.
  - 목록 16 · '-' 27 은 무작위로 뽑았다.
- 실행: `eval_e2e_ko.py --save-context`(답 생성 없음)로 판정까지만 돌렸다. 운영 `.env` 그대로이고, 판정 뒤 단계인 외부 검색 · 결론 다시 쓰기만 껐다(`.cron/run_jn.sh`, 11-03 06:40–07:32).
  - 판정 결과는 새 평가 행 `trace` 의 `judge.pick` 이다.
- 라벨: '없음' 판정마다 질문과 컨텍스트 블록(블록당 앞 1000자, `packets.md`)을 보고 붙였다. 판정자는 Claude 1명이다.
  - F(거짓 '없음'): 찾는 연구, 또는 질문에 바로 답하는 문서가 있다. 열린 요청("추천" · "아무거나")이면 주제에 맞는 논문이 있으면 F다.
  - T(맞는 '없음'): 그런 문서가 없다.
  - ?: 일부만 맞는다.

## 2. 결과

- 판정: 80 중 문서 53 · **'없음' 22** · 판정 안 돎 3 · RAG 경로 아님 2. 판정이 돈 75 중 '없음'은 29%다.
- '없음' 22: **거짓 11(50%)** · 맞음 7 · 애매 4 (`labels.tsv`).
  - 실사용 8: 거짓 4 · 맞음 4.
  - 나머지 14: 거짓 7 · 맞음 3 · 애매 4.
- R6 다시 나누기(`judge_off_1102` §2)의 "거짓 약 1/3"보다 높다. 그때는 답 라벨이었고 문항 꼴도 달랐다.

| 꼴 | 거짓 | 맞음 | 애매 |
|---|---|---|---|
| 열린 요청("추천" · "아무거나" · "꼭 읽어야 할 세 편" · "최신 논문 찾아줘") | **5** | 1 | 1 |
| "…방법 있어?"(비슷한 방법 문서가 있음) | 3 | 2 | 0 |
| 주제 조사 | 1 | 1 | 0 |
| 비교(정규식 밖 "중에 뭘 쓰는 게 나아") | 1 | 0 | 1 |

| 이름 붙은 고전 논문(DB 에 없음) | 0 | 3 | 0 |

- **열린 요청**: 판정 프롬프트는 "사용자는 특정한 연구 하나를 찾고 있다"를 전제한다. 그래서 아무 논문이나 되는 요청에도 '없음'을 낸다. 목록 정규식(`_GATE_LIST`)은 "추천해줘" · "\d+편" · "뽑아줘" · "아무거나"를 못 잡는다. 예: d0802 "논문 6편 알려줘"(`\d+\s*개` 만 있음).
- **"방법 있어?" · 수치 · 비교**: "주제만 비슷하면 없음" 규칙이 엄해서 틀린다.
  - 비슷한 방법을 다룬 문서도 '없음'으로 본다.
  - 원논문이 있어도 초록에 묻는 숫자가 없으면 '없음'이다(Q_G03 Chinchilla).
  - 두 대상 논문이 다 있어도 '없음'이다(Q_H01).
- **맞는 '없음'**은 이름 붙은 고전 논문(Transformer · Attention Is All You Need — DB 에 없음)과 DB 에 없는 주제에서 나왔다. 이때 판정은 지어내기를 막는다.

## 3. 고칠 후보

1. **열린 요청 판정 건너뛰기**: 판정만 건너뛰고 목록 모드는 켜지 않는다. 목록 게이트를 넓히면 목록 모드 · 외부 검색까지 바뀌어 R6 처럼 무관 인용이 는다.
   - dev 초안 규칙: `추천\s*(해|좀|부탁)|아무거나|볼만한|읽어야\s*할|재밌는|재미있는|\d+\s*편|몇\s*편|뽑아\s*(줘|주)|최신\s*(논문|연구)`.
     - 처음 초안의 맨 "추천" · "뽑아"는 "추천 시스템" · "문제를 뽑아" 같은 주제어를 잡아 동사꼴로 좁혔다.
   - dev 효과: 판정 도는 dev 434 중 새로 건너뛰는 문항은 11(목록 10 · 열린 요청 1)이다. 위 '없음' 22 중 거짓 5/11 을 잡고, 맞음 1/7(Q_B06) · 애매 1/4 도 잡는다.
   - 판정이 문서를 고른 문항은 건너뛰어도 답 입력이 같다(`judge_off_1102` §1). 그래서 바뀌는 것은 '없음'이 나오던 문항뿐이다.
   - held-out 에서 걸리는 문항은 6뿐이다. 라운드를 하려면 이 꼴의 새 held-out 질문 ~40 이 필요하다(§2.5).
2. **판정 프롬프트 손보기**: "방법 있어?" · 수치 · 비교의 거짓 6 이 대상이다. 지금 프롬프트는 `presence_judge_1011` 에서 거짓 '없음' 3.6% 로 정한 글자라 바꾸면 오프라인 판정(`scripts/presence_judge.py`)부터 다시 잰다. 느슨하게 하면 맞는 '없음'(지어내기 막기)도 잃을 수 있어 1 보다 위험하다.
