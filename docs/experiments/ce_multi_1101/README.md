# 다국어 cross-encoder 논문 재순위 — dev 오프라인 비교 (사전 등록, 2026-11-01)

> 측정 **전에** 쓴다. 출발점: 방향 초안 R1(10-31). paper_ce_1023 은 영어 전용 `ms-marco-MiniLM-L-6-v2` 에 9B 영어 검색어를 넣어 상위 5 정답 8 : 2(p 0.11)로 접었다. 이번에는 한국어 질문 원문을 그대로 넣을 수 있는 다국어 모델 둘을 본다. 가설: 9B 영어 검색어는 질문을 줄이면서 조건 · 이름을 잃는다(name_lookup_1101 의 `factscore`). 원문으로 다시 매기면 상위 5 고르기가 낫다.

## 1. 바꾸는 것 (오프라인만 — 운영 코드 변경 없음)

- 운영 검색 `ChromaRAGTool.search(영어 검색어, top_k=15, name_query=질문)` 을 운영 `.env` 그대로 돌린다. 가벼운 재순위(`_light_rerank_paper_pool_by_embedding` — 영어 검색어와 제목 + 초록 + 청크의 MiniLM 임베딩 코사인, 상위 50편)가 낸 논문 순서를 가로챈다(monkeypatch, 반환값은 그대로).
- 그 순서의 **상위 30편**을 cross-encoder 로 (질문, 제목 + 초록 앞 1,500자) 점수 매겨 다시 줄 세운다. `max_length` 512. 31위 아래는 순서 그대로 뒤에 붙인다.
- 이름 찾기(`RAG_NAME_LOOKUP=1`)가 앞에 둔 논문은 운영처럼 맨 앞에 둔다. 그다음 15편까지 자른다.
- 갈래 10:
  - 모델: `BAAI/bge-reranker-v2-m3`(568M, fp16) · `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`(118M) · 참고 `cross-encoder/ms-marco-MiniLM-L-6-v2`(영어 전용 — `en` 만). 맥미니 MPS.
  - 질문: `ko` 사용자 질문 원문 · `en` 9B 영어 검색어(`rag_queries[0]`).
  - 합치기: `ce` CE 점수만 · `rrf` 운영 순위와 CE 순위의 RRF(k = 60).
- 대조 `base`: 운영 검색이 낸 15편 순서 그대로.

## 2. 세트 (dev 만 — held-out 은 안 쓴다)

- **주:** 정답 ID 가 있는 특정 논문 질문 227 — 162(159) · real40(34) · real2(34). paper_ce_1023 과 같은 문항이다. 영어 검색어는 `lv1_*` 행(10-30, 지금 코퍼스)의 `rag_queries[0]` 이다. 그 행에 없으면 같은 문항의 다른 실행 행에서 가져온다(검색어 LLM 은 temperature 0 · seed 고정).
- 보고: 조사형 sv_old 24(정답 여러 편) — 상위 5 안 정답 편수. 검색어는 `sg0_old`.

## 3. 지표

- **주:** 상위 5 안에 정답이 든 문항 수 — 갈래 대 `base`, 얻음 : 잃음.
- 보고: 상위 15 안 정답(관련 문서 거르기에 들어가는 15편) · 첫 정답 순위 역수 평균(MRR@15) · 상위 1.
- 시간: CE 30편 점수 시간 중앙(맥미니 MPS, 운영 봇과 같은 기계). 모델 메모리.
- 한계: 운영의 최종 5편은 15편을 관련 문서 거르기(9B)로 거른 뒤의 앞 5편이다. 이 비교는 거르기 전 순서만 본다. 거르기가 앞 순위의 무관 문서를 빼 주는 만큼 운영 효과는 여기보다 작을 수 있다. 목록 모드(10편) · 비교 분리 검색 경로는 안 탄다.

## 4. 고르는 규칙 (측정 전 고정)

- 갈래 10개 중 상위 5 **얻음 − 잃음**이 가장 큰 것을 고른다. 같으면 잃음이 적은 것, 그다음 빠른 것.
- 다음 단계로 가는 조건 (모두):
  1. 얻음 − 잃음 ≥ +5
  2. 얻음 ≥ 2 × 잃음 (protocol §2.5 가 가정한 2 : 1)
  3. CE 30편 점수 시간 중앙 ≤ 3s
- 하나라도 어기면 R1 을 접는다(운영 변경 없음). dev 표본이라 유의성은 주장하지 않는다.
- 통과하면 다음 단계를 따로 사전 등록한다: 플래그 뒤 구현 → 거르기를 포함한 운영 경로 검색 측정(dev) → held-out 판정(정답 없는 문항은 두 조건 컨텍스트를 섞어 조건을 모른 채 0 · 1 · 2 판정 — corpus_er_1029 방식).
- 보고(판정에 안 씀): 고른 갈래의 재순위 범위 15 · 50, 같은 모델의 `ko` 대 `en`, sv_old.

### 4.1 규칙 수정 (측정 전, 연기 시험 뒤)

- 연기 시험(세트마다 2문항, 8행 — `smoke.jsonl`)에서 bge 의 CE 30편 시간이 4.0–5.6s 였다. 조건 3(≤ 3s)을 못 맞춘다. mMiniLM 은 0.7–0.8s · ms-marco 0.3s.
- 원래 규칙대로면 bge 갈래가 가장 좋을 때 R1 전체를 접는다. 시간은 결과가 아니라 운영 제약이므로, 조건 3 을 **고르기 전 자격**으로 옮긴다:
  - 30편 시간 중앙 ≤ 3s 인 갈래(mm · msm 6개) 중에서 고른다. 고른 갈래에 조건 1 · 2 를 본다.
  - bge 갈래 4개는 보고한다. bge 가 고른 갈래보다 순 +3 이상 나으면, 시간(+~4s)을 쓸지는 사용자 결정으로 올린다.
- 연기 시험 행의 결과 지표(정답 순위)는 보지 않았다. 시간 · 가로챈 순서와 운영 15편 일치(8/8)만 봤다.

### 4.2 채점 전 확인 (행 수만 보고 · 결과 지표는 안 봄)

- 실행 결과 231행: 162 세트 161 · real40 34 · real2 34 · sv_old 2. 가로챈 순서와 운영 15편은 231행 모두 같았다(`base≠pool 0`). 가로챈 검색어도 모두 같았다.
- 162 세트가 사전 등록 숫자(159)보다 2개 많다. `A008` · `A068` 은 paper_ce_1023 이 쓴 `s18_162` 에 검색어가 없던 문항이다. 이번에는 `lv1_162` 에 검색어가 있어 들어왔다. §2 의 "227 · paper_ce_1023 과 같은 문항"을 따라 **판정은 227 로 한다**(162 는 `s18_162` 에 검색어가 있는 159). 두 문항은 따로 보고만 한다.
- real40 34 · real2 34 는 paper_ce_1023 의 `as1_real40` · `as1_real2` 정답 문항과 같다.
- sv_old 는 정답 목록(`relevant_papers`)이 있는 문항이 `as_M01` · `as_M10` 둘뿐이다. 나머지 22 는 빈 칸이다(pooled 판정 세트). 사전 등록의 "sv_old 24" 는 틀렸다. 보고는 2문항으로 한다.
