# 판정이 답변과 같은 앞부분을 읽게 — Ollama 프롬프트 캐시 (사전 등록, 2026-10-17)

> 측정 **전에** 쓴다. 선행: [`helper_model_1016/`](../helper_model_1016/) — 모델 교체를 없앤 뒤 문항당 중앙 56s. 그 진단(§0)에서 정답 유무 판정 ~14s 가 답변이 다시 읽는 같은 컨텍스트를 한 번 더 읽는 시간이었다.

## 0. 확인 (2026-10-17, `.cron/lat/cache_test.py` · 맥미니)

같은 system + 같은 user 앞부분(컨텍스트 끝까지) + 다른 꼬리로 두 번 부르면 llama-server 가 앞부분을 재사용한다: 두 번째 호출이 **891 토큰만 새로 읽음**(1,545 토큰은 checkpoint 복원, 로그 `restored context checkpoint … n_past = 1545`), 6.6s vs 첫 호출 16.7s. Qwen3.5 하이브리드 구조라 checkpoint 위치까지만 복원된다 — 전부가 아니라 ~2/3.

지금 판정 프롬프트는 `[질문]` 이 앞, `[참고 문서]` 가 뒤이고 system 이 없어 답변 프롬프트와 앞부분이 전혀 겹치지 않는다.

## 1. 바꾸는 것 — `RAG_JUDGE_SHARED_PREFIX` (기본 `0`)

`1` 이면 판정 호출을 **답변과 같은 메시지 앞부분**으로 보낸다:
- system = 답변 system 프롬프트(판정 힌트 붙이기 전), user = 답변 user 프롬프트를 `[사용자]` 앞에서 자른 앞부분(대화 맥락 · 참고 문서 · 직전 답변) + 판정 지시.
- 판정 지시 문구는 v1 `PROMPT` 의 규칙 그대로(특정 연구 하나 · 주제만 비슷하면 없음 · 가장 앞 번호 · `답: 문서 N` / `답: 없음` 한 줄) + `[질문]`. "답변을 쓰지 말고 판정 한 줄만" 을 덧붙인다.
- 답변 호출은 **바뀌지 않는다**(같은 프롬프트). 판정이 '없음'이면 system 에 힌트가 붙어 앞부분이 달라지므로 그 문항은 캐시를 못 쓴다.
- 이미지가 붙은 질문은 지금 판정을 쓴다.

- 예상보다 더 줄었다(−14s, 예상 −6~9s) — 판정과 답변 사이에 checkpoint 가 컨텍스트 끝 가까이 잡혀 답변 호출이 새로 읽는 토큰이 4~900 개뿐인 문항이 많았다.
- **판정도 좋아졌다**: 거짓 '없음' 7 → 1(대조만 틀린 6문항 A003 · A007 · A030 · A034 · C1_08 · C2_03, 처리만 틀린 문항 0), '없음' 재현 13 → 15. 판정이 답변과 같은 대화 맥락·문서 블록 형식을 보고, 질문을 문서 **뒤**에 읽는 것이 9B 에 더 쉬운 것으로 보인다(추정 — 원인은 따로 재지 않았다).
- 답변 프롬프트는 바뀌지 않았다. 답이 달라지는 것은 판정이 달라진 문항(15/155)뿐이고, 그 대부분은 거짓 '없음'이 고쳐진 쪽이다.
