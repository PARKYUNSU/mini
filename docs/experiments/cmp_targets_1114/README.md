# cmp_targets_1114 — 비교 대상 추출이 Gemini 로 넘어가 검색이 수백 초 멈추던 것 (사전 등록, 2026-11-14)

> 측정 **전에** 쓴다. "검색 지연 최대 ~280s" 의 원인 찾기 → 고치기.

## 0. 찾은 것 (Ollama 안 쓴 기록 분석 + 형식 재생)
- 최근 3 일 답 낸 평가 885 행: 전체 중앙 26s · p90 92s · 최대 341s. 운영 설정 실행의 느린 문항(H_D12 · H_G09 · H_C27, 검색 단계 190–300s)은 실행마다 바뀐다(H_C27 5s → 207s) — 문항이 아니라 간헐 현상.
- 오늘 새벽 측정 로그(cl0/cl1 6 세트): 60s 넘은 8 문항 중 **7 이 `[Gemini] … Rate limit` 문항**, 한도에 걸린 문항은 모두 ≥ 47s.
- 경로: `_extract_comparison_targets`(비교 분리 검색, RAG_COMPARE_SPLIT) 가 로컬 형식이 안 맞으면 `get_executor_llm()`(Gemini, `RotatingGeminiChat`) 로 넘어간다. Gemini 는 429 면 키 20 개를 1.5s 간격으로 돌고, **전부 429 면 900s 쉬고 끝없이 다시**.
- 로컬 형식 실패율: 질문 파일의 비교 질문 149 중 **67 (45%)** (`.cron/cmp_targets_1114.py`, Gemini 막음). 원인은 `repeat_penalty=1.18` — A 와 B 를 한 줄에 붙여 쓴다(`A: … B: …`). 같은 질문 1.0 이면 두 줄. 1.18 은 오늘 답 생성에서 한국어를 깨뜨려 1.0 으로 내린 값(penalty_1113)이다.

## 1. 바꾸는 것 (`_extract_comparison_targets` 만)
1. 이 호출만 `repeat_penalty=1.0`(검색어 추출 `_extract_english_rag_query` 는 그대로 1.18 — query_determinism_1009).
2. 한 줄에 붙은 `A: … B: …` 도 읽는다.
3. Gemini 폴백을 뺀다 — 실패하면 빈 목록(기존 검색만, 원래 설계).
- 플래그 없이 바꾼다(되돌리기: 커밋 되돌림). 아래 보호를 못 넘으면 운영에 안 올린다.
