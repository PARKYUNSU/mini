# 직무 분야 핵심 논문 추가 수집 (1단계) (사전 등록, 2026-10-20)

> 측정 **전에** 쓴다. 출발점: 실제 사용 피드백(10-19 · 20) — 질문에 딱 맞는 논문(RGB 2309.01431 · Sufficient Context 2411.06037 · Trust-Align 2409.11242)이 **DB 에 아예 없다**(DB 7,183편). 검색어를 고쳐도 없는 논문은 못 찾는다.
> orx 사용: 2026-10-20 사용자 승인(`ops/openresearch_policy.md` "승인된 추가 용도") — 후보 목록만 만들고 수집은 우리 파이프라인이 한다.

## 1. 바꾸는 것 — 코퍼스에 논문 추가 (코드 · 설정 변경 없음)

**후보 규칙 (측정 전 고정, 손으로 고르지 않는다)**
- 질문 34개(`discovery_questions.tsv` — 사용자 직무 질문지, 3열은 orx 용 영어 질의)마다 `orx discover embedding "<영어 질의>"` 를 `--prioritize popular --limit 8` 과 기본 정렬 `--limit 8` 두 번 부른다.
- 순서: popular 결과 → 기본 결과, 중복 제거, **이미 DB 에 있는 논문 제외**, 질문당 앞에서 **5편**.
- 사용자가 짚은 3편(RGB · Sufficient Context · Trust-Align)을 더한다.
- 원본 결과는 `raw/` 에 저장. 상한 34 × 5 + 3 = 173편.

**수집**: `apps/backfill/ingest_classics.py --ids …`(매일 수집과 같은 ArxivFetcher · PdfParser · RagProcessor) → 임베딩 캐시 재생성(`scripts/build_emb_cache.py`) → 봇 재시작(BM25 다시 만듦). 받지 못한 논문은 기록만 한다.

## 2. 측정 — 검색만(답변 없이), 수집 전 `cs0_*` · 수집 후 `cs1_*`

- 질문: **held-out 30개**(`heldout_questions.tsv` — 같은 직무 분야, 후보 찾기에 쓰지 않음, 이 사전 등록과 함께 먼저 작성) · 후보 찾기에 쓴 34개(참고, 표본 안이라 낙관적).
- `eval_e2e_ko.py --save-context`(운영 경로 그대로: 라우터 → 답변 노드 컨텍스트, 대화 기록 없음). 답변 모델이 보는 논문(번호표의 문서)을 잰다.
- **관련성 판정**: 두 조건의 (질문, 논문) 쌍을 합쳐 섞은 뒤 Claude 가 **조건을 모른 채** 제목 + 초록만 보고 3단계로 매긴다 — 2 질문에 직접 답하는 연구 · 1 같은 주제지만 질문의 조건과 다름 · 0 무관.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** held-out 30 — 컨텍스트에 '2' 논문이 1편 이상 있는 질문 수 | 수집 후 > 전, McNemar 양측 p < 0.05 |
| 부: held-out 30 — 질문당 '2' 논문 수 | 부호 검정, 보고 |
| 참고: 후보 찾기 34 — 같은 두 지표 | 보고(표본 안) |
| 보호: 검색 ok(정답 논문이 컨텍스트에) — 162 · real40 · real2 | 각 세트 수집 후가 전보다 2 이상 낮지 않음(짝 비교) |
| 보호: 검색 시간 중앙(162) | ≤ 전 + 3s |
| 보고: 후보 수 · 수집 성공 · 실패 · 추가 청크 수, 수집한 논문이 held-out 컨텍스트에 들어간 수 | |

채택이면(코드 변경이 없으므로) 수집분을 그대로 둔다. 기각이면 수집분을 지울지 사용자와 정한다.

예상: held-out 30 에서 '2' 논문 있는 질문 12 → 18~22. 정답 논문 검색 ok 는 ±2(새 논문이 일부 밀어낼 수 있음).
