# R8 열린 요청은 판정 건너뛰기 — 사전 등록 (2026-11-03)

## 0. 배경

- `judge_none_1103` 진단: 판정 '없음' 22 중 거짓이 11 이다. 그 절반(5)이 열린 요청이다("추천해줘" · "아무거나" · "꼭 읽어야 할 세 편" · "최신 논문 찾아줘").
- 판정 프롬프트는 "사용자는 특정한 연구 하나를 찾고 있다"를 전제한다. 그래서 주제에 맞는 논문이 있어도 '없음'을 낸다.
- 목록 게이트(`_GATE_LIST`)는 "추천해줘" · "N편" · "뽑아줘"를 못 잡는다.

## 1. 바꾸는 것 — `RAG_OPEN_GATE=1` (기본 0)

- `core/llm/presence_judge.should_judge`: `RAG_PRESENCE_GATE=1` 이고 `RAG_OPEN_GATE=1` 이면, 질문이 `_GATE_OPEN` 에 걸릴 때 판정을 건너뛴다.
- 목록 게이트 · 목록 모드 · 비교 분리는 그대로다. 목록 모드까지 켜면 R6 처럼 무관 인용이 는다.
- `_GATE_OPEN`(측정 전 고정): `추천\s*(해|좀|부탁)|아무\s*(거나|논문|연구)|볼\s*만한|읽어야\s*할|읽을\s*만한|재밌는|재미있는|괜찮은\s*(논문|연구)|좋은\s*(논문|연구)|\d+\s*편|몇\s*편|(두|세|네|다섯|여섯|일곱|여덟|아홉|열)\s*편|뽑아\s*(줘|주)|골라\s*(줘|주)|최신\s*(논문|연구)`
  - 동사꼴만 잡는다. "추천 시스템" · "문제를 뽑아" 같은 주제어나 "한편"은 안 잡는다.
- 판정이 문서를 골랐을 문항은 건너뛰어도 답 입력이 같다(`judge_off_1102` §1). 바뀌는 것은 대조에서 판정이 '없음'이던 문항뿐이다. 그 문항에서는 다음 셋이 함께 바뀐다:
  - `NO_DOC_HINT` 가 빠진다.
  - 결론 다시 쓰기를 한다(`RAG_NODOC_KEEP_CONCLUSION` 은 '없음'일 때만 건너뜀).
  - '없음' 때문에 돌던 외부 검색이 빠진다.
- 단위 테스트: `tests/unit/test_presence_gate.py::test_open_gate`.

## 2. dev 점검 (등록 전, held-out 안 봄)

- 판정이 도는 dev 434 중 새로 건너뛰는 문항은 12다(목록 라벨 11 · 열린 요청 1). 주제어 오탐은 0이다.
- `judge_none_1103` 의 '없음' 22 중 이 규칙에 걸리는 것: 거짓 5/11 · 맞음 1/7(Q_B06) · 애매 1/4.
- `judge_none_1103` 에서 열린 요청 꼴 dev 10문항 중 판정 '없음'은 7(70%)이다.

## 3. 문항 (held-out, 판정 전용)

- 새 held-out 50(`heldout_open.tsv`, O_01–O_50):
  - 열린 요청 꼴이다(추천 · 볼만한 · N편 · 아무거나 · 읽어야 할 · 최신 논문 · 골라줘).
  - 주제는 RAG · 에이전트 · 평가 · 안전 · 효율 · 학습 · 응용에 고르게 나눴다.
  - DB 를 보지 않고 썼다. 기존 질문(서로 다른 1,002개)과 SequenceMatcher 0.75 미만이다(넘은 O_01 · O_45 는 고쳐 썼다).
  - 목록 · 수치 · 비교 게이트에 안 걸려 대조에서는 판정이 돈다.
  - 46 이 규칙에 걸린다. 일부러 안 걸리게 쓴 꼴 4(O_46 "한 편만 소개해줘" · O_47 "입문용" · O_48 "괜찮은 거" · O_49 "골라서")는 재현율 보고용이다. 바뀌지 않아 판정에 안 들어간다.
- 기존 held-out 중 규칙에 걸리는 6: H_C07 · H_C16 · H_C24 · H_C31 · H_H03 · H_I04b(이어지는 질문 쌍 b).

## 4. 측정

### 4.1 1단계 — 판정만 (답 생성 없음)

- 대조(`RAG_OPEN_GATE=0`)로 `eval_e2e_ko.py --save-context` 를 돌린다. 대상은 새 50 + H_C07 · C16 · C24 · C31 · H03(`stage1_questions.tsv`)이다.
- 쌍 H_I04a · H_I04b 는 `--keep-session` 으로 돌린다.
- 판정 뒤 단계인 외부 검색 · 결론 다시 쓰기는 끈다(`judge_none_1103` 과 같음).
- **바뀌는 문항** = 규칙에 걸리고, 대조 판정(`trace` 의 `judge.pick`)이 '없음'인 문항이다.
- 보고: 판정 분포 · 규칙 재현율(새 50 중 걸린 수).

### 4.2 2단계 — 답 생성 · 판정

- 바뀌는 문항만 두 조건으로 답을 만든다: 대조 `og0_*`(`RAG_OPEN_GATE=0`) · 처리 `og1_*`(`=1`). 나머지는 운영 `.env` 그대로이고 `--answer --save-context` 로 돈다.
  - H_I04b 가 바뀌면 쌍째 `--keep-session` 으로 돌리고 b 만 판정한다.
- 판정 묶음에는 두 조건의 `answer_input` 이 다른 문항만 넣는다(protocol §2.5, 2026-11-03).
  - 대조가 2단계에서 다시 '없음'을 안 내면 입력이 같아 빠진다. 그 수는 보고한다.
- 답 끝 외부 검색 목록(📎)은 두 답 모두 잘라 낸다(R6 와 같음).
- 판정은 문항마다 두 답을 A/B 무작위로 섞어서 한다(시드 1103). 열쇠는 라벨을 다 쓴 뒤 연다. 판정자는 Claude 1명이다.

## 5. 판정 기준 — 측정 전 고정

순서대로 본다:
1. 사실 오류(인용 블록과 어긋나거나 블록에 없는 내용을 논문 결과로 쓴 문장)가 확연히 적은 쪽. 오류 차이가 1이고 그 오류가 결과의 뜻을 바꾸면 확연하다고 본다.
2. 같으면 질문에 맞게 답한 쪽. 열린 요청에는 주제에 맞는 논문을 고르게 소개한 답이 맞고, 맞는 논문이 정말 없으면 맞는 '없음' 고지가 맞다.
3. 같으면 인용 논문 관련성.
4. 그래도 같으면 동점.

답마다 다음을 같이 센다:
- 무관 인용 '0'.
- 거짓 '없음'(주제에 맞는 논문이 컨텍스트에 있는데 없다고 함).
- 거짓 '있음'(주제와 무관한 논문을 요청에 맞는 것처럼 소개하거나 없는 논문 · 결과를 지어냄).

| 지표 | 기준 |
|---|---|
| **주:** 판정한 문항 승패 | 처리 승 > 대조 승, 부호 검정(동점 제외) 양측 p < 0.05 |
| 보호 1: 거짓 '있음' 합 | 처리 ≤ 대조 + 2 |
| 보호 2: 무관 인용 '0' 합 | 처리 ≤ 대조 × 1.5 (대조가 0이면 ≤ 2) |
| 보호 3: 응답 시간 중앙(판정 문항) | 처리 ≤ 대조 + 20s |
| 보고: 거짓 '없음' 수 · 인용 편수 · 꼴별 승패 · 단계별 시간 · 규칙 재현율 | |

## 6. 문항 수 (protocol §2.5)

- 바뀌는 문항 예상: 새 46 × 70% ≈ 32, 기존 6 × 70% ≈ 4 → 약 36.
- 2단계에서 대조가 다시 '없음'을 안 내 빠지는 문항과 동점을 합쳐 20% 로 보면, 판정하는 문항은 약 29 다.
- dev 에서 걸린 '없음'은 거짓 5 · 맞음 1 이다. 예상 효과는 3:1 – 5:1 로, 동점 뺀 12–17 이면 된다. 2:1 이면 37 이 필요해 모자란다.

## 7. 채택 · 라운드 뒤

- 주 지표와 보호 1–3 을 모두 넘으면 **사용자 승인 뒤** 운영 `.env` 에 `RAG_OPEN_GATE=1` 을 넣고 봇을 재시작한다.
- 라운드 뒤 새 50 은 dev 로 옮긴다. 판정에 쓴 기존 held-out 6 은 실패를 보고 고치지 않으면 그대로 둔다.
