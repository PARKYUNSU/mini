## 결과
- 최근 결과 8 개(fv0/1 · qh2/1 · ex0/1b · irh0/1_h120)에서 본론 항목이 문장 끝 · 인용 없이 끝나거나 `[문서` 로 끝난 답: **7/614 (1.1%)**. 7 개 중 6 개가 이어지는 질문(FH · QH) — 대화 기록 · 직전 답이 프롬프트에 더 들어가는 턴. 결론 없이 끝난 것 5, 결론은 붙은 것 2(결론 다시 쓰기가 뒤에 붙임). 스크립트 `.cron/fu_1115/trunc.py`.
- 원인: 답 호출에 `num_ctx` 를 주지 않아 Ollama 앱 설정 `context_length=4096` 이 쓰인다(`n_ctx_slot = 4096`). 프롬프트 + 출력이 4096 토큰에 닿으면 생성이 멈춘다. Ollama 서버 로그: 호출 29,007 회 중 `stop processing: n_tokens ≥ 4090` 이 **11 회**(잘린 답 7 과 그 밖 보조 호출), 3,500 이상이 384 회. `num_predict`(4096)는 원인이 아니다.

## 고칠 안
- A (권함): Ollama 앱 `context_length` 4096 → **8192**. 9B 모델 KV 메모리 약 +0.5–1GB(64GB 기기), 같은 프롬프트의 속도는 거의 같다. 앱 설정 변경 · Ollama 재시작 필요(봇 잠깐 멈춤) → 사용자 승인.
- B: 답 호출에만 `num_ctx=8192` — 다른 호출(4096)과 달라 모델을 다시 올리게 되어 지연이 커진다. 비권장.
- C: 이어지는 질문의 대화 기록을 줄인다 — 답 질 영향이 있어 A/B 측정이 필요하다.
- 확인 방법(A 뒤): 같은 다회차 세트 `query_hist_1115` 80 턴을 다시 돌려 잘린 답 0 · 문항 시간 중앙 +5s 이내 · 서버 로그 `n_tokens ≥ 4090` 0.
