# 보조 호출도 답변 모델로 — 모델 교체 없애기 (사전 등록, 2026-10-16)

> 측정 **전에** 쓴다. 남은 약점: 응답 시간(중앙 ~60~70s, [`status_1015/`](../status_1015/)).

## 0. 진단 (2026-10-16, `.cron/lat/lat_profile.py` · 맥미니, 162 표본 20문항, 운영 `.env`)

단계별 시간(첫 문항 콜드 스타트 제외):

| 단계 | 평균 | 비율 | 속 |
|---|---|---|---|
| 답변 생성 (v13) | 38.1s | 53% | 프롬프트 읽기 ~15s(163 토큰/s × 2,400~3,200) + 생성 ~20s(16 토큰/s × 250~360) |
| 정답 유무 판정 (v13) | 19.2s | 27% | **모델 적재 ~5.5s** + 같은 컨텍스트 읽기 ~14s |

- 맥미니 메모리 16GB 에 `qwen3.5:9b`(6.3GB, 보조 호출: 검색어 추출 · 주제 게이트 · 라우터 분류 · 비교 대상 추출)와 `yunsur_v13`(5.9GB, 판정 · 답변)이 함께 올라가지 못해 **문항마다 두 번 갈아 끼운다**(Ollama 로그 "exceed available memory, evicting"; list_slots 측정 36문항에서 적재 75번). 문항당 ~11.5s.
- 보조 호출은 짧다(프롬프트 ~90 토큰, 출력 ≤ 24 토큰). 답변 모델로 돌려도 비용이 거의 같다.

## 1. 바꾸는 것 — `RAG_HELPER_MODEL` (기본 빈 값 = 지금처럼 `LOCAL_LLM_MODEL`)

값이 있으면 **검색어 재작성 LLM(`get_rag_query_rewrite_llm`: 검색어 추출 · 주제 게이트 · 비교 대상 추출)과 라우터 분류 LLM(`get_router_llm`)** 이 그 모델을 쓴다. 처리 = `yunsur_v13`(= `RAG_ANSWER_MODEL`). → 논문 질문 경로 전체가 v13 하나로 돈다.
- `LOCAL_LLM_MODEL` 은 바꾸지 않는다(잡담·계획·코딩 폴백은 그대로 base).
- 잡담·계획 질문은 라우터 분류(v13) 뒤 base 로 한 번 갈아 끼우게 된다(지금은 0번) — 그 질문들의 지연은 보고만 한다.

## 2. 방법 (운영 `.env` 그대로, 같은 DB · 같은 시간대, 대조 `hm0_*` 빈 값 · 처리 `hm1_*` = yunsur_v13)

1. **검색**: `eval_e2e_ko.py`(답변 없이) — 162 · real40 · real2. 검색어가 바뀌면 컨텍스트가 바뀐다.
2. **경로**: `eval_route_contamination.py` — chat 48 · planner 64 가 논문 경로(B)로 새는지. 그리고 1의 162 · real 세트가 B 로 가는지.
3. **지연**: 진단과 같은 20문항(+ 콜드 스타트 1문항, 판정에서 뺌)을 `lat_profile.py` 로 답변까지, 대조·처리 번갈아.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** 지연 20문항 문항별 전체 시간 | 처리 < 대조, 부호 검정 양측 p < 0.05 **그리고** 중앙 차 ≥ 5s |
| 보호: 검색 ok (컨텍스트에 정답) — 162 · real40 · real2 합 | McNemar 에서 처리가 유의하게(p < 0.05) 낮지 않고, 대조만 맞힌 문항 − 처리만 맞힌 문항 ≤ 5 |
| 보호: 경로 — chat · planner 가 B 로 샌 수 | 각각 처리 ≤ 대조 + 2 |
| 보호: 경로 — 162 · real 세트가 B 가 아닌 수 | 처리 ≤ 대조 + 2 |
| 보호: 검색어에 한글이 남은 문항(`fail=query_korean`) | 처리 ≤ 대조 + 2 |
| 보고: 단계별 시간, 검색어가 대조와 같은 문항 비율, chat · planner 경로 지연 | |

채택이면 **사용자 승인 후** 운영 `.env` `RAG_HELPER_MODEL=yunsur_v13` + 봇 재시작.

예상: 전체 중앙 67 → 55~57s(−10~12s). 검색 ok · 경로는 ±2 안. 검색어는 30~60% 문항에서 글자가 달라질 것(같은 키워드 다른 순서 포함).

다음 후보(이 라운드 뒤): 판정과 답변이 같은 컨텍스트를 두 번 읽는 ~14s — 판정 프롬프트를 답변 프롬프트와 같은 앞부분으로 맞춰 Ollama 프롬프트 캐시를 쓰게 한다(판정 정확도 재측정 필요).
