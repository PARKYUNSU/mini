# 목록 모드 블록을 "초록 앞 500자" 대신 "제안 · 결과 · 대상 문장"으로 — 답 재생성 평가 (사전 등록, 2026-10-23)

> 측정 **전에** 쓴다. 출발점: 실사용 점검(10-23 job 120 · 126) — 목록 질문 답의 본론 항목이 **논문의 배경 · 동기 문장**만 옮기고 무엇을 했는지 · 결과는 빠졌다. job 120 "Beyond the Reranker" 를 "여러 리랭커 개선 방법을 제시"로 반대로 설명(실제: 강한 리랭커가 있으면 다른 기법은 대부분 효과 없음), job 126 LightMem · TrustMem 항목이 문제 설명만. job 121(이어지는 질문 "두 번째 논문 자세히")도 같은 줄인 블록을 재사용해 얇았다.

## 0. 진단

목록 모드(`RAG_LIST_MODE`, list_mode_1016)는 n_ctx 4,096 안에 논문 10편을 넣으려고 `_compact_list_blocks` 로 블록마다 **초록 앞 500자**만 남긴다. 초록은 보통 배경 → 제안 → 결과 순이라 앞 500자에는 배경과 제안 앞부분만 들어간다(job 120 의 Beyond the Reranker 초록 1,400자 중 결과 "A strong cross-encoder reranker accounts for most …"는 800자 이후).

## 1. 바꾸는 것 — `RAG_LIST_FINDINGS` (기본 `0`)

`1` 이면 `_compact_list_blocks` 가 블록마다 머리 + **같은 500자 예산**으로 초록에서 문장을 골라 원래 순서로 잇는다: ① 제안 문장(we propose / present / introduce … 이 든 첫 문장) ② 결과 문장(conclusion_rewrite_1021 §8 `extract_findings` 의 점수 — 수치가 든 결과 > 결과 동사) ③ 대상 문장(데이터셋 · 도메인). 예산을 넘는 문장은 뺀다. 초록이 없는 블록은 지금처럼 본문 앞 500자. 코드 `core/llm/conclusion_rewrite.py` `brief_findings`, `core/graph/agent_nodes.py`, 테스트.

## 2. 방법 — 답 재생성 (맥미니)

목록 질문 21개: real40 목록 10(T01–T08 · R02 · R06) · real2 목록 8(T01–T08) · 새 3(`questions.tsv`: L01 job 120 · L02 job 126 질문 그대로, L03 = aspect_split_1022 M06). 대조 `lf0` · 처리 `lf1`, 운영 `.env` 그대로, `--answer --save-context`. 실행 `.cron/run_lf.sh`, 채점 `score.py`.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주(자동):** 본론 항목 중 **근거 수치 항목**(항목에 숫자가 있고, 그 숫자가 항목이 인용한 논문 초록에 그대로 있음 — 연도 · ID · 항목 번호 제외) — 문항마다 개수 | 처리 > 대조, 문항 짝 부호 검정 양측 p < 0.05 |
| **주(눈가림 직접 판정):** 두 조건 본론 항목에서 각 25개(시드 1023)를 섞어 조건을 모른 채 초록과 대조해 "결과 · 기여를 말함 / 배경 · 문제만" | 처리의 "결과 · 기여" 비율 > 대조 + 20%p |
| 보호: 본론 항목에 초록에 없는 숫자가 있는 항목 수 | 처리 ≤ 대조 |
| 보호: T 정답 인용 ≥ 3 (real40 · real2) · 검색 ok | 각각 처리가 대조보다 2 이상 낮지 않음 |
| 보호: 본론 항목 수 합 | 처리 ≥ 대조 × 0.9 |
| 보호: 응답 시간 중앙 | ≤ 대조 + 5s |

채택이면 사용자 승인 후 운영 `.env` `RAG_LIST_FINDINGS=1` + 봇 재시작.
