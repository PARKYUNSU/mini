# unit_check_1106: 답의 숫자 단위 불일치 진단 (dev, 오프라인)

> 측정 **전에** 쓴다. 저장된 답만 읽는다. LLM · Chroma 호출과 운영 변화는 없다. 사용자 요청(11-06): 숫자 · 단위 짝 검증이 필요한지 우리 답에서 먼저 잰다.

## 1. 왜

[`core/llm/body_numbers.py`](../../../core/llm/body_numbers.py)는 답의 숫자가 인용 블록에 그대로 있는지만 본다. 단위는 보지 않아서 `12 ms` 와 `12 s` 를 구분하지 못한다. 단위 검사를 붙일 가치가 있는지는 진짜 단위 오류가 얼마나 나오는지, 규칙이 그것을 얼마나 정확히 잡는지에 달렸다. 걸린 문장을 지우는 방식이므로 오탐은 맞는 문장을 지운다.

## 2. 입력

`RAG_BODY_NUM_CHECK` 운영 반영(10-26 10:55) 뒤의 결과 중 답과 컨텍스트가 함께 있는 대조 · 운영 조건 파일이다.

`weekly_20261101` · `pl0_dev` · `qt0_s2` · `ogb0_s2` · `ans_hu` · `sg0_new` · `sg0_old` · `nk1` · `us_1027`

- 문항 id 가 겹치면 위 순서에서 앞 파일의 답만 쓴다.
- **held-out 은 쓰지 않는다.** `cs0_heldout` · `cs0_h2` 를 빼고, `foundation_1031/heldout.tsv` · `heldout_followup.tsv` 에 있는 id 도 뺀다.

## 3. 규칙 (`run.py`, 측정 전 고정)

답의 각 줄에서 숫자와 바로 뒤 단위를 뽑는다. 단위는 표에 있는 것만 본다(퍼센트 · 배 · 시간 · 용량 · 토큰 · 규모 등, 한국어와 영어 표기를 같은 것으로 묶음). 그 줄의 인용 블록(인용이 없으면 컨텍스트 전체)에서 같은 숫자를 찾아 나눈다.

| 칸 | 뜻 |
|---|---|
| 일치 | 블록에 같은 숫자 · 같은 단위가 있다 |
| **후보** | 같은 숫자가 있지만 같은 단위는 없고, 다른 아는 단위로만 나온다 |
| 단위 없음 | 같은 숫자가 있지만 블록 쪽에 아는 단위가 없다 |
| 숫자 없음 | 블록에 그 숫자가 없다(지금 `body_numbers` 의 영역이고 이번 범위 밖, 수만 보고) |

## 4. 라벨

후보는 전부, 단위 없음은 무작위 30건(seed 1106)을 Claude 가 답 문장과 원문을 보고 나눈다.

- **T:** 답이 그 사실의 단위를 잘못 말했다.
- **F:** 틀리지 않았다. 다른 수치가 우연히 같은 숫자이거나 맞게 바꿔 쓴 경우다.
- **?:** 원문만으로 가릴 수 없다.

대조 조건이 없어 가릴 것은 없다.

## 5. 기준 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| 빈도: 후보 중 T | ≥ 5건 |
| 정밀도: T / (T + F) | ≥ 60% |

- **둘 다 통과:** `body_numbers` 에 단위 대조를 붙이는 라운드를 따로 사전 등록한다.
- **하나라도 미달:** 코드를 만들지 않고 진단으로 끝낸다.
- 단위 없음 표본은 보고만 한다. 이 칸의 T 가 많으면 '답이 단위를 지어 붙이는' 문제를 따로 적는다.

## 6. 한계

라벨은 Claude 한 명이 단다. 표에 없는 단위와 숫자가 바뀐 오류는 후보에 들어오지 않아 재현율은 모른다. 답은 대부분 AI 논문 질문이라, 탄소 배출량 같은 다른 분야의 단위 문제는 이 진단으로 말할 수 없다.
