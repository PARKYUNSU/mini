## 사전 등록 — D 바꿔 끼우기 (`RAG_CONCLUSION_SWAP`, 2026-11-02)

### 1. 바꾸는 것

플래그 `RAG_CONCLUSION_SWAP`(기본 0) · `core/llm/conclusion_swap.py`. DirectAnswer 에서 결론 다시 쓰기 · 인용 정리(`RAG_CITE_CLEANUP`) · 조건 고지(`RAG_COND_CHECK`) 뒤, 외부 검색 줄을 붙이기 전에 돈다. '없음' 결론 유지(`_keep_nodoc`)면 안 돈다.

1. 대상: 본론이 2편 이상 인용한 답(`cited_blocks` ≥ 2, 결론 다시 쓰기와 같은 조건)의 결론 단락. 단락은 `<b>결론</b>` 뒤부터 다음 `<b>` 머리나 `📎` 외부 검색 줄 앞까지.
2. 문장 나누기: conclusion_misattr_1025 `sentences` 규칙(문장 앞에 붙은 인용은 앞 문장 것).
3. 인용 없는 문장은 그대로 둔다(직답 · 대비).
4. 인용 붙은 문장은 인용한 논문마다 원문 문장 하나로 바꾼다.
   - 고르기(`snap`): 그 논문 블록(초록 + 본문 조각) 문장 중 9B 문장과 겹침 점수가 가장 높은 것. 점수 = 숫자 3점(모델 이름 속 숫자 GPT-4 · Llama-3 는 안 셈) + 영어 낱말(3자 이상, 대소문자 무시) 1점. 같으면 앞 문장(초록 쪽). 0점이면 초록 결과 문장(`extract_findings` 점수 — 첫 문장 빼고 수치 2 + 결과 동사 1, 같으면 뒤쪽).
   - 같은 (논문, 원문 문장)은 한 번만 넣는다.
   - 본론 밖 논문을 인용한 문장은 뺀다(다시 쓰기 검사가 막으므로 0 예상, 수만 보고).
5. 번역: `RAG_ANSWER_MODEL`(지금 yunsur_v13) · temperature 0 · seed 0 · 질문은 안 보여 준다. 프롬프트는 미리보기와 같고 "1인칭(we · our)은 '이 논문은' · '이 논문의'로" 한 줄을 더한다.
   - 번역문에 원문 밖 숫자 · 한자 · 여러 줄이 있으면 영어 원문을 쓴다.
   - 원문에 영어 부정어(not · no · never · without · cannot · neither · nor · unable · fail · lack)가 있는데 번역문에 않 · 없 · 못 · 아니 · 불가 · 실패 · 부족 · 결여 가 하나도 없으면 영어 원문을 쓴다.
6. 꼴: "{번역} [{ID}]" 문장들을 한 단락으로 잇는다.

### 2. 측정

- held-out 90(판정 전용, `foundation_1031/heldout.tsv` · `heldout_gold.jsonl`)을 운영 `.env` 그대로(플래그 끔) 답까지 한 번 만든다: `eval_e2e_ko.py --answer --save-context --label cs0_heldout`.
- D 는 저장된 답에 같은 `swap_conclusion` 함수를 오프라인으로 적용한다 → `cs1_heldout.jsonl`(전 · 후 · 바꾼 문장 쌍 · 번역 시간).
  - 같은 답에서 D 만 다르므로 생성 흔들림이 없다.
  - 온라인 D 는 저장된 답이 이미 거친 결론 단계(다시 쓰기 · 인용 정리 · 조건 고지) 뒤에 돌고, 외부 검색 줄은 단락 밖이다. 그래서 오프라인 적용과 결과가 같다.
- Chroma 쓰기(01:00 수집 · 임베딩 캐시) 중에는 돌리지 않는다. 다른 측정과 동시에 돌리지 않는다. 이어지는 질문 5쌍은 안 쓴다.
- dev 점검(관문 아님): dev 43답(recheck_1031 · weekly_20261101)에 먼저 적용해 미리보기 D 와 같은지(1인칭 표현만 다름), 영어로 둔 비율, 시간을 본다. 여기서 찾은 버그는 held-out 판정 전에 고친다.

### 3. 판정 (판정자 1명 Claude)

- 주 지표: 바뀐 답(D 가 문장을 1개 이상 바꾼 답)마다 바뀐 문장의 오류 수를 전 · 후로 비교한다.
  - 전 = D 가 바꾼 9B 인용 문장들, 후 = D 가 넣은 문장들. 인용 없는 문장은 양쪽이 같아 안 센다.
  - 문장마다 인용한 블록 전체와 대조해 라벨을 단다: O 맞음 · E 사실 오류(어긋남 · 뒤집힘 · 수치 틀림 · 남의 연구를 이 논문 결과로) · X 과장 · 일반화 · U 블록에 없음(질문 전제 포함) · F 맞지만 결과가 아닌 군더더기 · ? 판단 불가.
  - 오류 = E + X + U. 오류가 줄면 이김, 늘면 짐.
  - 가림: 답 안에서 전 · 후 문장을 섞어 무작위 번호로 보여 준다. 어느 쪽인지 적힌 열쇠 파일은 라벨을 다 쓴 뒤에만 연다(부분 가림 — 번역투로 짐작할 수는 있다).
  - 통과: 동점 뺀 부호 검정 양쪽 p < 0.05 (예 6:0 · 8:1 · 10:2).
- 보호 1 — 질문에 답하는 정도: 바뀐 답마다 질문과 전 · 후 결론 전체(무작위 A/B)를 보고, 어느 쪽이 문서와 맞는 내용으로 질문에 더 답하는지 고른다(A · B · 같음). 틀린 내용은 답한 것으로 치지 않는다. D 쪽이 나쁜 답 ≤ max(2, 바뀐 답의 10%).
- 보호 2 — 인용 논문 집합: 전 · 후 답의 인용 ID 집합이 다른 답 0(본론 밖 논문 인용 문장 뺌은 예외, 수 보고). 그러면 `answer_ok` · `answer_first_ok` 도 같다.
- 보호 3 — 시간: 바뀐 답의 번역 시간 중앙값 ≤ 15s.
- 보고만: 영어로 둔 문장 비율과 사유, F 수, 갈래별(A~H) 바뀐 답 수.

### 4. 문항 수 예상과 그만두기

- dev 기준 2편 이상 인용한 답은 30/43(70%)이다 → held-out 바뀐 답 ~60 예상. 오류 있는 답 비율은 모른다.
- D 의 후 문장은 원문 그대로라 질 수 있는 쪽은 번역 오류뿐이라고 본다. 효과가 4:1 이상이면 동점 뺀 12문항이면 된다(§2.5).
- 2:1 수준이면 37문항이 필요해 held-out 90 으로는 못 넘는다.
- 바뀐 답 < 20 이거나 동점 뺀 답 < 6 이면 통과할 수 없으니 판정을 멈추고 보고한다.
