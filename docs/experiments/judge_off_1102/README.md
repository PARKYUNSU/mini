# R7 판정 더 끄기 — dev 진단 · 설계안 (2026-11-02, 사전 등록 전 · held-out 안 씀 · 운영 변경 없음)

R6(`qtype_1102` §6.2)의 "판정 켜짐만 바뀐 문항 3 : 7"을 보고 정답 유무 판정(`RAG_PRESENCE_JUDGE`)을 더 끄는 라운드를 설계하려 했다. 설계 전에 R6 를 판정 결과로 다시 나눴다.

## 1. 판정이 실제로 바꾸는 것

- 판정은 `should_judge`(수치 · 비교 · 목록이 아닌 질문)이고 컨텍스트가 1편 이상일 때만 돈다(`core/graph/agent_nodes.py` 정답 유무 판정 부분).
- 판정이 문서 번호를 고르면 답 LLM 입력은 판정을 안 돌린 것과 같다. 바뀌는 것은 '없음'일 때뿐이다.
  - 시스템 프롬프트에 `NO_DOC_HINT`가 붙는다. 서론 · 결론이 '없음' 꼴이 되고, 관련 연구는 최대 2개로 줄어든다.
  - 목록 질문이 아니어도 외부 검색(OpenAlex)이 돈다.
  - 결론 다시 쓰기와 바꿔 끼우기를 건너뛴다(`RAG_NODOC_KEEP_CONCLUSION`).
- 끄려면 운영 `.env`의 `RAG_PRESENCE_JUDGE=0` 하나만 바꾸면 된다. 코드는 바꾸지 않는다.

## 2. R6 다시 나누기

판정 결과는 평가 행에 없어서 `.cron/run_qt.log` 의 `정답 유무 판정 =` 줄에서 문항별로 뽑았다. 대조(qt0)에서 판정이 돈 문항은 14(그중 '없음' 4)이고, 처리(qt1)에서는 26('없음' 15)이다.

| R6 바뀐 44문항 | 판정 '없음' 쪽 승 : 패 : 동점 |
|---|---|
| 판정 '없음'이 한쪽에서만 나옴, 목록 · 분리 결정은 같음 (5) | 3 : 2 : 0 |
| 판정 '없음'이 한쪽에서만 나옴, 목록 · 분리도 바뀜 (12) | 5 : 5 : 2 |
| **합 (17)** | **8 : 7 : 2** |

- 판정 '없음'이 어느 쪽에도 없고 목록 · 분리 결정도 같은 문항이 9개다(Q_A06 · A11 · E02 · E03 · E04 · E05 · E06 · G01 · G04).
  - 이 9문항은 두 쪽 답 LLM 입력이 같다. 컨텍스트와 프롬프트가 같다.
  - 그런데도 9 중 8 에서 승패가 갈렸다(처리 2 : 대조 6 : 동점 1).
  - 원인은 답 생성 표본 흔들림이다(`get_rag_answer_llm` temperature 0.2 · top_p 0.8 · 시드 없음).
- R6 §6.2 의 "판정 켜짐만 3 : 7" 11문항 중 7 이 이 9문항에 든다. 판정이 실제로 '없음'을 낸 4문항은 2 : 2 다. 그래서 §6.2 의 "판정 자체가 손해" 해석은 근거가 없다(`qtype_1102` README 에 고침을 기록했다).
- 판정 '없음'의 맞음: 위 17 중 거짓 '없음'(컨텍스트에 찾는 연구가 있는데 없다고 함, R6 판정 라벨)이 6 이다. 맞는 '없음'은 약 2/3 이다.

## 3. 판정 끄기 라운드를 돌린다면 (설계안)

- 조건: 처리 `RAG_PRESENCE_JUDGE=0` · 대조는 운영 `.env` 그대로.
- 판정할 문항: 대조에서 판정이 '없음'을 낸 문항만 판정한다. 나머지는 입력이 같아 흔들림만 잰다.
  - 그러려면 평가 행에 판정 결과를 저장해야 한다. 지금은 로그에만 있다.
- 문항 수: held-out 100 중 판정이 도는 문항은 63이다(A 24 · B 14 · I 7 · C 6 · F 6 · H 4 · D 1 · G 1).
  - '없음' 비율을 R6 처럼 30–60% 로 보면 판정할 문항은 19–38 이다.
- 주 지표: 처리 승 > 대조 승, 부호 검정 p < 0.05.
- 보호 지표:
  - 컨텍스트에 없는 연구를 있다고 쓴 답(거짓 있음): 처리 ≤ 대조 + 2.
  - 무관 인용 '0': 처리 ≤ 대조 × 1.5.
  - 응답 시간 중앙값.
- §2.5 와 맞춰 보면: 2:1 효과라도 동점을 뺀 37문항이 필요하다. dev 가 8 : 7 이라 효과가 거의 없을 것으로 보이고, 문항 수도 모자란다.

## 4. 설계자 의견 (사용자 결정 대기)

- 판정 끄기 A/B 는 지금 돌리지 않는 쪽을 권한다.
  - 판정 '없음'은 대략 3번 중 2번 맞고, 맞을 때는 지어내기를 막는다.
  - 끄면 거짓 '없음'을 지어내기와 맞바꾸는 셈이다. dev 에서 그 차이는 8 : 7 이다.
- 대신 할 것:
  1. 평가 행에 단계 결정(판정 결과 · 게이트 · 목록 모드 · 기간 거르기 등)을 저장한다. 그다음 "답 입력이 실제로 바뀐 문항"만 판정한다. R6 는 판정한 44 중 9(20%)가 입력이 같은 쌍이었다. 모든 라운드의 검정력이 오른다.
     - **했음(11-03, 사용자 결정):** `eval_e2e_ko.py` 행에 `answer_input`(답 LLM 입력 sha1 앞 12자) · `trace`(rag_trace 단계 결정, 긴 글 뺌)를 넣었다. protocol §2.5 에 규칙을 더했다. 확인 실행은 §5 에 적었다.
  2. 판정을 고친다면 표적은 거짓 '없음'(약 1/3)이다. 먼저 dev 에서 판정 '없음' 40개쯤을 맞음 · 틀림으로 라벨해 어떤 질문에서 틀리는지 본다.
- 스크립트: R6 로그 파싱과 다시 나누기는 이 README 의 수치를 낸 일회성 스크립트다(세션 scratchpad). 다시 하려면 `.cron/run_qt.log` 의 `정답 유무 판정 =` 줄과 `[k/N] ID ok=` 줄을 순서대로 짝짓는다.
