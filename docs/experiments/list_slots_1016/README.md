# 목록 답 — 문서별 번호 칸 템플릿 (사전 등록, 2026-10-16)

> 측정 **전에** 쓴다. 출발점: [`list_mode_1016/`](../list_mode_1016/) §5 — 컨텍스트 안 정답 80 인데 답이 인용한 정답 31. 답 인용 편수 중앙 2, 본론 항목 중앙 2.

## 0. 진단

목록 모드(`RAG_LIST_MODE=1`, 운영)는 10편을 넣고 사용자 메시지 끝 `[참고 문서 수]` 에 "최대 8개" 를 적는다. 그런데 같은 메시지 맨 끝 출력 템플릿(`RAG_OUTPUT_TEMPLATE_MULTI_STRICT`)은 **본론 예시 칸 3개**(1·2·3)와 규칙 "**2~4개**" 를 그대로 보여 준다. 9B 는 뒤에 오는 뼈대를 따른다 — template_collapse_1006 에서 본 것처럼 길이·개수 지시보다 템플릿 뼈대가 이긴다.

토큰 여유: 최근 프롬프트 2,445~3,300 토큰, 생성 350~460 토큰, `n_ctx` 4,096, 잘림 0. 목록 모드 프롬프트는 6.4k자로 일반(8k자)보다 짧다. 10항목 × 1~2문장(~+500 토큰)이면 들어간다.

## 1. 바꾸는 것 — `RAG_LIST_SLOTS` (기본 `0`)

`1` 이고 목록 모드가 걸린 질문이면 출력 템플릿을 **목록 전용**으로 바꾼다:
- 서론 1~2문장 → 본론에 **문서 수만큼 번호 칸**(최대 10), 칸마다 `**{이름}**: 1~2문장 [문서 k]` 를 미리 적어 둔다(k = 1..N) → 결론 2~3문장.
- 규칙: "k 번째 칸은 [문서 k] 에 대한 항목. 그 문서가 질문 주제와 관련 없으면 그 칸을 통째로 뺀다. 관련 있으면 빼지 않는다." 항목 상한 문장(`최대 8개`)은 이 템플릿에서는 "문서마다 한 칸" 으로 바꾼다.
- 목록 모드가 아닌 질문은 그대로(코드 경로 같음 — 단위 테스트).

## 2. 방법

운영 `.env` 그대로(목록 모드 켜짐) 같은 DB·같은 시간대에 대조 `ls0_*`(`RAG_LIST_SLOTS=0`, 지금 운영) · 처리 `ls1_*`(`=1`) 번갈아. 문항: list_mode_1016 과 같은 게이트 문항 — real40 T01–T08 · R02 · R06, real2 T01–T08, 162 A015 · C1_02.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** T 16 문항별 정답 인용 수 | 처리 > 대조, 부호 검정(동점 제외) 양측 p < 0.05 |
| 부: 정답 인용 ≥ 3 문항 수 | 보고 |
| 보호: 정답 정밀도(인용 ∩ 정답 / 인용, 16문항 합) | 처리가 대조보다 15%p 이상 낮지 않음 (정답 목록은 불완전하므로 느슨하게) |
| 보호: 지어낸 인용(컨텍스트에 없는 논문) | 처리가 대조보다 2 이상 많지 않음 |
| 보호: 비T 게이트 문항(R02 · R06 · 162 A015 · C1_02) | answer_ok 가 2 이상 나빠지지 않음 |
| 보호: T 응답 시간 중앙 | ≤ 대조 + 20s |
| 보호: 생성 잘림 (Ollama 로그 `truncated = 1` 또는 n_tokens ≥ 4,096, 측정 시간대) | 0 |
| 보고: 답 인용 편수 · 항목 수 · 답 길이 중앙, 컨텍스트 안 정답 합(같아야 함) | |

채택이면 **사용자 승인 후** 운영 `.env` `RAG_LIST_SLOTS=1` + 봇 재시작.

예상: 답 인용 편수 중앙 2 → 5~7, T 정답 인용 합 31 → 45~55, 정밀도 −5~10%p, 응답 +10~15s.

**읽은 것**
- 진단대로 뼈대가 개수를 정한다 — 같은 컨텍스트에서 항목이 2 → 7, 정답 인용이 31 → 59 로 거의 두 배. 컨텍스트 안 정답 80 중 59(74%)를 답에 올렸다(전 39%).
- 대가: 정답 목록 밖 논문 인용이 12 → 41 로 늘어 정밀도 −13%p. 정답 목록은 불완전하다(예: real40 T01 처리 답 10편은 모두 speculative decoding 논문인데 정답 목록에는 7편) — 정답 밖 인용이 곧 무관한 인용은 아니다. 다만 일부는 주제 가장자리 논문일 수 있다.
- 답이 두 배 길어져 응답이 +18s(중앙 74s). 4,096 토큰 벽까지 여유 ~470 토큰 — 칸을 10 보다 늘리면 안 된다.
