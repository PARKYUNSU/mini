**질문:** 에이전트가 작업 계획을 먼저 세운 뒤 단계별로 실행하는 방식을 다룬 연구 핵심 내용 알려줘

<b>서론</b>

<b>본론</b>
1. <b>DynaFlow</b>: 다중 에이전트 시스템에서 사전 정의된 협력 구조를 벗어나, 주어진 작업을 위해 특정 프로그램(플랜)을 실시간으로 합성하여 하위 에이전트를 순차·병렬로 조정하고 검증합니다[2610.34467v1].
2. <b>OmniNova의 Planner Agent</b>: 복잡한 작업에 대해 상세 분석과 실행 전략 수립 후 구조화된 JSON 형식의 플랜 (단계, 의존 관계 등) 을 생성하며, 필요 시 사전 연구를 통해 배경 정보를 수집할 수 있습니다[2503.20028v1].

<b>결론</b>
DynaFlow는 에이전트 간 오케스트레이션을 학습하는 방식에서 전체 정확도 88.08%를 달성하며, 기존 베이스라인보다 10.90%p 높은 성능을 보인 반면, OmniNova는 연구·데이터 분석·웹 상호작용 등 50개의 복잡한 과제에서 작업 완료율 87%와 인간 평가 점수 4.2/5로 기존 프레임워크를 능가한다[2610.34467v1][2503.20028v1]. 두 연구 모두 다중 에이전트 시스템의 성능 향상을 목표로 하지만, DynaFlow는 강제 모드에서의 오케스트레이션 학습에 집중하고, OmniNova는 계층적 구조와 동적 태스크 라우팅을 통해 다양한 도메인에서 종합적인 효율성과 품질을 개선한다는 점에서 접근 방식과 평가 범위에 차이가 있다.

<b>서론</b>
에이전트가 <b>작업 계획 수립 후 단계별 실행</b>하는 방식은 복잡한 다중 에이전트 시스템에서 작업 흐름 설계와 최적화의 핵심 과제이다. 이러한 접근법은 기존 템플릿 기반 워크플로우보다 유연성을 제공하지만, 구조 결정 시점과 평가 기준을 명확히 정의해야 한다[2603.22386v1].

<b>본론</b>
1. <b>Static Templates to Dynamic Runtime Graphs</b>: 이 조사는 LLM 에이전트의 실행 가능한 워크플로우는 정적 템플릿에서 동적 런타임 그래프로 전환되는 과정을 검토한다. 구조 결정 시점을 기준으로 고정된 스크래프트와 각 실행마다 선택·생성·수정하는 방법을 구분하고, 평가 신호(태스크 메트릭, 검증자 등) 를 활용한 최적화 프레임워크를 제시한다[2603.22386v1].
2. <b>DynaFlow</b>: 다중 에이전트는 사전 정의된 협력 구조에 의존해 왔으나 DynaFlow는 메인 에이전트의 행동 공간에 자유형 실행 워크플로우 합성을 통합하여, 필요 시 협업 여부를 결정하고 서열·병렬 실행을 통해 하위 에이전트를 조정한다. 학습은 주어진 트레이젝토리를 통한 지도 미세조정과 예외 사례 필터링으로 이루어지며, 모든 하위 에이전트는 고정되어 오케스트레이션만 배우게 된다[2610.34467v1].
3. <b>OmniNova</b>: 이 프레임워크는 계층적 다중‑에이전트 구조(조율자·계획가·감독관·전문가) 와 동적인 작업 라우팅 메커니즘을 도입한다. 복잡한 작업을 위해 계획가는 상세 분석과 전략 수립, 선택된 모델을 할당하는 멀티레이어 LLM 통합 시스템을 통해 에이전트를 효율적으로 배치하고 정보 흐름 일치를 최적화한다[2503.20028v1].

<b>결론</b>
제공된 문서들은 작업 계획을 먼저 세운 뒤 단계별로 실행하도록 설계한 연구들을 제시하며, 각각 정적·동적 워크플로우 전환(DynaFlow), 자유형 다중 에이전트 오케스트레이션(Static Templates to Dynamic Runtime Graphs) 및 계층 구조와 동적 라우팅을 활용한 통합 프레임워크(OmniNova)를 통해 계획‑실행 파이프라인의 유연성과 효율성을 향상시킨다.

## P4 · H_D11
**질문:** GraphRAG랑 일반 벡터 검색 RAG는 어떤 질문에서 성능이 갈려?

**X**

<b>서론</b>
GraphRAG와 일반 벡터 검색 기반 RAG는 질문 복잡도에 따라 성능 차이가 크게 발생합니다. 단순한 단일 홉 질문에서는 기존 텍스트 문서만으로도 충분하지만, 다중 홠프 구조나 계층적 추리가 필요한 복잡한 질문에 대해서는 그래프가 제공하는 관계성 정보가 결정적인 역할을 합니다[2601.08773v1][2602.03578v1].

<b>본론</b>
1. <b>Vector‑only No-Graph RAG</b>: 벡터 유사도만으로 검색을 수행하며, 다중 홠프 구조나 계층적 추리에는 한계가 있어 복잡한 질문에서 성능이 낮습니다.[2601.08773v1] 코드베이스의 구문을 파싱해 결정론적인 그래프를 구축하고 이를 활용해 검색하므로, 다중 홠프 구조와 계층적 추리에 대한 정확도가 벡터‑only보다 높습니다.[2601.08773v1]
2. <b>EA-GraphRAG</b>: 질문을 문법적으로 분석하여 복잡도를 점수화한 뒤, 낮은 복잡도에는 밀집된 RAG를 사용하고 높은 복잡도는 그래프 기반 검색으로 전환하는 적응형 방식을 도입해 단순·복합 질문에 모두 효과적입니다.[2602.03578v1]

<b>결론</b>
제공된 문서들에 따르면, GraphRAG와 일반 벡터 검색 RAG의 성능은 질문의 복잡도와 도메인에 따라 갈립니다. 단순한 단일 홉 질의에서는 일반 벡터 기반 RAG가 더 높은 정확도를 보이며, GraphRAG는 오히려 정확도 하락과 높은 지연 시간을 겪습니다[2602.03578v1]. 반면, 복잡한 다중 홉 질의나 코드베이스와 같은 구조화된 데이터에서는 결정론적 AST 파생 그래프를 활용한 DKB가 가장 높은 정확도를 달성하고, LLM 기반 지식 그래프도 그 뒤를 이으며, 순수 벡터만 사용하는 방법은 특히 상위 아키텍처 질의에서 성능이 떨어집니다[2601.08773v1]. 따라서 질문이 단순한 경우엔 일반 RAG가 유리하지만, 복잡한 관계 추적이 필요한 상황에서는 GraphRAG(특히 AST 기반) 가 더 나은 결과를 제공합니다.

**Y**

<b>서론</b>
제공된 문서에는 질문이 찾는 연구가 없습니다.

<b>본론</b>
1. <b>Deterministic AST‑derived GraphRAG (DKB)</b>: Java 코드베이스에서 377개의 파일을 건너뛰거나 놓치는 경우가 발생하여 그래프 크기와 임베딩 청크 커버리지가 감소하지만, 전체 비용은 벡터 기반 베이스라인에 비해 낮고 정답 정확도가 가장 높습니다. [2601.08773v1]
2. <b>HyperGraphRAG</b>: 하이퍼그래드를 이용해 n‑ary 관계를 표현하고 지식하이퍼그래드 구축·검색·생성 파이프라인을 제공합니다; 기존 그래프 RAG보다 답변 정확도, 검색 효율성이 향상되며 비용은 표준 RAG와 비슷하거나 약간 높습니다. [2503.21322v3]
3. <b>EA-GraphRAG</b>: 쿼리의 문법적 복잡도를 분석해 저복잡도는 밀집한 벡터 기반 RAG를 사용하고 고복잡도에 대해서는 그래프‑기반 검색을 적용하는 적응형 라우팅 정책을 도입했습니다; 이를 통해 정확도 향상과 지연 시간 감소가 동시에 달성됩니다. [2602.03578v1]

<b>결론</b>
따라서 질문이 찾는 연구는 제공된 문서에서 찾을 수 없습니다.
