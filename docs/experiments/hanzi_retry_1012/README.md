# RAG 답변 중국어 섞임 — 한 번 다시 생성하기 (사전 등록, 2026-10-12)

> 측정 **전에** 쓴다. §3 기준은 결과를 본 뒤 바꾸지 않는다.

## 1. 문제

운영 RAG 답변에 중국어 단어가 섞인다(사용자 보고 2026-10-12: "긴 컨텍스트와检索 능력"). 평가 159문항 중 중국어 글자(U+4E00–9FFF)가 든 답변: 운영 설정(v13 + 초록 + 판정) 3, v13 + 초록 8, v13 5, base 13. 기존 `lang_guard` 는 영어 섞임만 다룬다.

## 2. 방법 — 재생성으로 고쳐지는가

대상: `ans_v13abs_pj`·`ans_v13abs` 에서 중국어가 섞였던 9문항(A034 A037 A041 A093 A094 C1_16 C1_21 C2_19 C2_20). 운영 설정 그대로(`RAG_ANSWER_MODEL=yunsur_v13 RAG_CONTEXT_ABSTRACT=1 RAG_PRESENCE_JUDGE=1`, 재생성 끔) **5회씩** 다시 생성(`eval_e2e_ko.py --answer --ids …` 5번, 라벨 `hz_r1`…`hz_r5`) → 45개 답변.

- 지표: 생성 1회당 중국어 섞임 비율 p (45개 중 섞인 수). 이 문항들에서 "섞이면 한 번 더 생성"하면 남는 비율은 대략 p.
- 서술: 문항별 섞임 횟수(0~5) — 특정 문항에서만 반복되는지.

## 3. 기준

- **채택**: p ≤ 25% → 재생성 1회를 구현한다(운영 기본 꺼짐 → 사용자 승인 후 켬). 운영 전체로는 섞임 ≈ 2% × p 로 줄어든다.
- p > 25% 이면 재생성만으로는 부족 → 보류하고 다른 방법(예: 섞인 단어만 한국어로 바꾸는 짧은 수정 호출)을 따로 잰다.

구현(채택 시): 답변에 중국어 글자가 있으면 같은 메시지로 1회 재생성, 재생성본에도 있으면 중국어 글자가 더 적은 쪽을 쓴다. 지연은 섞인 답변(≈ 2%)에서만 +1회 생성.

## 3.5 결과 (2026-10-12)

9문항 × 5회 = 45개 답변(운영 설정, 재생성 끔).

- **생성당 섞임 p = 10/45 = 22.2%** → 기준(≤ 25%) 통과 → **채택**.
- 문항별: A034 **5/5**, A037 3/5, A041 2/5, 나머지 6문항 0/5. 대부분은 우연한 섞임이라 재생성으로 고쳐지지만, A034(독일 법학 교육)는 같은 단어(`了指令`·`从头`)가 매번 나와 재생성으로 고쳐지지 않는다.
- 운영 전체 추정: 섞임 ≈ 2% → 재생성 후 ≈ 0.5% 안팎(A034 같은 고정형만 남음).

구현: `RAG_HANZI_RETRY=1` 이면 답변에 한자가 있을 때 같은 메시지로 1회 재생성, 한자가 더 적은 쪽을 쓴다(`core/llm/lang_guard.hanzi_count`, `agent_nodes` RAG 경로). 기본 꺼짐.
