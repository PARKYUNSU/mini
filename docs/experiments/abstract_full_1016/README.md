## 1. 바꾸는 것

- `RAG_ABSTRACT_CHARS` (기본 `800`): 블록에 붙이는 초록 길이. 처리 `2000`(코퍼스 초록은 대부분 이보다 짧다 → 사실상 전체).
- 같이 묶음(한 설정으로): 답변 프롬프트의 컨텍스트 상한 `rag_max_chars` 를 `5 × (초록 길이 − 800)` 만큼 늘린다(논문 5편 기준). 늘리지 않으면 지금 컨텍스트(최대 7,309자)가 8,000자 상한에 걸려 **다른 논문 내용이 잘린다** — 그 효과와 섞이지 않게.
- 검색은 바뀌지 않는다(초록은 포맷 단계에서만 붙는다).

**읽은 것**
- 진단대로다 — 기대 수치가 컨텍스트에 들어간 문항이 19 → 25 로 늘고 수치 정답이 같은 만큼 늘었다.
- 수치만이 아니라 **일반 답변의 correct 도 크게 올랐다**(3 : 25). 초록 뒤쪽(결과·기여 요약)이 컨텍스트에 들어가 "핵심 기여를 정확히 설명"하는 답이 늘었다. status_1015 의 날조 5건(약어 풀이·수치 오기)은 처리 쪽에서 0 — 초록 원문이 들어가 지어낼 여지가 줄었다.
- 응답 시간 대가는 작다(중앙 +3~6s).

**판정의 한계 (밝혀 둠)**
- 판정자(Claude)는 이 라운드의 가설을 알고 있었고, 대조 `now_162` 답은 status_1015 판정에서 이미 본 답이다(재판정 일치 1.000 은 그 영향일 수 있다). 처리 쪽 답은 초록 세부가 많아 문체로 구분될 여지가 있다. correct 기준이 "핵심 기여를 정확히 설명"이라 세부가 많은 답이 실제로 유리한 것은 맞지만, 판정자 편향을 배제하려면 **독립 판정자(gpt-oss 등)로 일부 재확인**이 좋다 — 주 지표(수치 정답)는 자동 채점이라 이 한계와 무관하다.
