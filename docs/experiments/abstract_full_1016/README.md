# 초록 전체 넣기 — 수치 질문 (사전 등록, 2026-10-16)

> 측정 **전에** 쓴다. 출발점: [`status_1015/`](../status_1015/) §5 — 수치 질문 real40 7/15 (D), 10-13 이후 변화 없음.

## 0. 진단 (2026-10-16, `now_real40` 컨텍스트 저장분)

real40 수치 오답 중 정답 논문은 찾았는데 **기대 수치가 컨텍스트에 없던** 문항: N02 · N06 · N15 (+ N03 · N13 은 두 수치 중 하나만, 또는 짧은 수치라 문자열 일치가 애매). 모두 그 수치가 **초록의 894~1,232번째 글자**에 있다. 블록에 붙이는 초록은 앞 **800자**(`_ABSTRACT_CHARS`, abstract_context_1011 에서 정한 값)라 잘렸다. 초록은 결과 수치를 끝에 쓰는 일이 많다.

| 문항 | 수치 | 초록 안 위치 / 길이 | 정답 논문 검색 |
|---|---|---|---|
| N02 | 25.5 | 1,069 / 1,118 | ✅ |
| N06 | 79.6 | 1,232 / 1,332 | ✅ |
| N15 | 48.3 | 1,075 / 1,552 | ✅ |
| N03 | 30 | 894 / 1,592 | ✅ |
| N13 | 30 | 1,039 / 1,291 | ✅ |

주의: 수치 문항은 **초록에 수치가 있는 논문으로 만든** 문항이라 이 처리에 유리하다(효과가 실제 사용보다 크게 보일 수 있다). 그래서 다른 유형·162 를 지키는지(§3 보호 기준)를 함께 본다.

## 1. 바꾸는 것

- `RAG_ABSTRACT_CHARS` (기본 `800`): 블록에 붙이는 초록 길이. 처리 `2000`(코퍼스 초록은 대부분 이보다 짧다 → 사실상 전체).
- 같이 묶음(한 설정으로): 답변 프롬프트의 컨텍스트 상한 `rag_max_chars` 를 `5 × (초록 길이 − 800)` 만큼 늘린다(논문 5편 기준). 늘리지 않으면 지금 컨텍스트(최대 7,309자)가 8,000자 상한에 걸려 **다른 논문 내용이 잘린다** — 그 효과와 섞이지 않게.
- 검색은 바뀌지 않는다(초록은 포맷 단계에서만 붙는다).

## 2. 방법

운영 `.env` 그대로(`eval_e2e_ko.py --answer --save-context`), 같은 DB·같은 날:

| 라벨 | 설정 | 질문 |
|---|---|---|
| `ab0_real40` · `ab0_real2` | `RAG_ABSTRACT_CHARS=800` (대조, 운영과 같음) | real40 40 · real2 34 |
| `ab1_real40` · `ab1_real2` | `RAG_ABSTRACT_CHARS=2000` (처리) | 같음 |
| `ab1_162` | 처리 | 162 — 대조는 `now_162`(status_1015, 10-16 01:00 수집 전후). 컨텍스트 논문이 같은 문항만 짝으로 쓰므로 DB 증가(1,244,068 → 1,251,297행)는 짝에서 빠진다 |

순서: ab0_real40 → ab1_real40 → ab0_real2 → ab1_real2 → ab1_162 (같은 시간대에 대조·처리를 번갈아).

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** 수치 정답 (real40 N 15 + real2 N 12 = 27, `score_real_eval.py` 자동: 기대 수치 전부 답에 등장 **그리고** 정답 논문 인용) | 처리 > 대조, McNemar 양측 p < 0.05 |
| 보호: 비교 C 25 두 편 모두 인용 · 목록 T 16 정답 인용 ≥ 3 | 각각 처리가 대조보다 2 이상 낮지 않음 |
| 보호: 162 답변 (ab1_162 vs now_162, Claude 눈가림 짝 판정, status_1015 와 같은 기준·관대 날조 기준) | correct 유의하게 낮지 않음 · 날조 유의하게 많지 않음 (McNemar p ≥ 0.05) |
| 보호: 거짓 부정 (`nogold_metrics.py`) | ≤ 5% |
| 보호: 162 응답 시간 중앙 | ≤ 대조 + 10s |
| 보고: 기대 수치가 컨텍스트에 있는 N 문항 수(대조·처리), 검색 ok(같아야 함), 답 길이, 한자 섞임 | |

채택이면 **사용자 승인 후** 운영 `.env` `RAG_ABSTRACT_CHARS=2000` + 봇 재시작.

예상: 수치 정답 16/27 → 21~23/27 (짝 0 : 5~7). 컨텍스트 +1,500~2,500자로 응답 +3~8s. 다른 유형은 그대로.
