# 논문 cross-encoder 재순위 — 운영 경로 dev 측정 · held-out 판정 (사전 등록, 2026-11-01)

> 측정 **전에** 쓴다. 출발점은 [ce_multi_1101](../ce_multi_1101/README.md) §6 이다. 가벼운 재순위 상위 30편을 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` 이 9B 영어 검색어로 다시 매기고 운영 순위와 RRF(k = 60)로 합쳤다. 그러자 거르기 전 상위 5 정답이 dev 227문항에서 얻음 14 : 잃음 2 였다. 이번에는 이것을 플래그로 넣는다. 관련 문서 거르기까지 도는 운영 경로로 재고, 판정은 held-out 에서 한다(protocol §2.5).

## 1. 바꾸는 것 — `RAG_PAPER_CE_RERANK=1` (기본 끔)

- 자리: `_paper_max_one_chunk_per_paper` 의 가벼운 재순위 바로 뒤다. 가벼운 재순위가 돌 때만 돈다.
- 가벼운 재순위 순서의 상위 30편을 (가벼운 재순위 검색어, `제목. 초록 앞 1,500자`)로 점수 매긴다. 31위 아래는 그대로 뒤에 둔다.
- 초록은 Chroma 메타데이터 초록(공백 정리)이다. 오프라인은 JSONL 초록을 먼저 썼다. 289편을 대 보니 287편이 같았다.
- 합치기: 가벼운 재순위 순위와 CE 순위의 RRF(k = 60). 점수가 같으면 가벼운 재순위 순서를 따른다.
- 그 뒤 단계(이름 찾기 보호 · 15편 자르기 · 이름 논문 맨 앞)는 그대로다.
- 모델은 CPU 에서 돈다. 운영 MiniLM 임베더처럼 9B 가 쓰는 GPU 와 겹치지 않게 했다. 30편 중앙 1.21s 다(MPS 0.69s, 11문항 시험). 처음 쓸 때 한 번 읽는다(약 470MB). 점수 계산이 실패하면 가벼운 재순위 순서 그대로 둔다.
- 경로: 가벼운 재순위가 도는 검색 모두 — 라우터 · 직답 · 목록 모드 · 계획 · 토론 컨텍스트 · 평가용 디버그 순위. 비교 분리 검색의 대상 검색은 가벼운 재순위를 끄고 돌아서(`light_rerank=False`) 바뀌지 않는다.
- 확인: 단위 테스트 `tests/unit/test_paper_ce_rerank.py` 3개(전체 705 통과). 켬 상태 운영 검색이 오프라인의 고른 갈래(`mm_en rrf`) 15편 순서를 10문항 중 10문항 그대로 냈다.

## 2. 측정 (검색만 — `--save-context`, 답 생성 없음)

- `run.sh`: 세트마다 끔(`pc0_<세트>`) → 켬(`pc1_<세트>`) 순서로 `scripts/eval_e2e_ko.py` 를 돌린다. 세트 순서는 162 → real40 → real2 → heldout 이다.
- dev: ce_multi_1101 주 227문항(162 의 159 · real40 34 · real2 34 — `ids.json`).
- held-out: `foundation_1031/heldout.tsv` 90문항. 이어지는 질문 5쌍은 안 잰다.
- dev 세 세트가 끝나면 `score.py gate` 로 §4 관문을 본다. 미달이면 held-out 을 돌리지 않는다.
- 코퍼스가 바뀌면 안 된다. 실행마다 앞에서 Chroma 쓰기 잠금을 보고(잠겼으면 멈춤) 청크 수를 적는다(`chroma_count.py`). 끝에서 청크 수가 처음과 같은지 본다. 운영 Chroma 쓰기(chroma_gap_1101 의 66편 채우기)는 이 측정 앞이나 뒤에만 한다.
- 예상 시간: 문항당 약 45초 × 634행 ≈ 8시간(dev 454행 ≈ 5.7시간).

## 3. 지표

### 3.1 dev (정답 ID)

- 주: 최종 컨텍스트(`context_papers` — 관련 문서 거르기 · 자르기 뒤 LLM 에 건네는 [문서 N])에 정답이 든 문항(`ok`). 켬 대 끔 얻음 : 잃음.
- 보고: 세트별 · 라우팅이 두 실행에서 다른 문항 수 · 컨텍스트 편수. 라우터는 temperature 0.2 라 흔들린다. 라우터 검색도 CE 를 타므로 경로가 갈린 문항도 빼지 않고 그대로 센다.

### 3.2 held-out (판정)

- 두 실행의 컨텍스트 논문 중 **한쪽에만 든 논문**을 문항별로 모아 섞는다(`pool.py`). 조건 표시 없이 (질문, 제목 + 초록 앞 600자) 쌍마다 0 · 1 · 2 로 판정한다(corpus_er_1029 방식, 판정자 Claude). 두 쪽에 함께 든 논문은 양쪽에 똑같이 더해지므로 판정하지 않는다.
- 주: 문항마다 '2' 개수 켬 대 끔 — 늘어남 : 줄어듦, 부호 검정 양측.
- B 층 14문항(정답 ID 있음): 컨텍스트 정답 포함, 켬 대 끔.
- 보호: 한쪽에만 든 논문 중 '2' 비율이 켬에서 끔보다 5%p 이상 낮지 않다. '0' 개수 합은 보고한다.
- 문항 수: 오프라인에서 상위 5 가 바뀐 문항이 215/227(평균 1.66편)이었다. held-out 도 대부분 바뀐다고 보고, '2' 개수가 다른 문항을 절반(약 45)으로 본다. 2 : 1 효과면 동점 뺀 37 이 필요하므로 대략 맞는다. 동점이 더 많아 검정력이 모자라도 규칙대로 판정한다.

### 3.3 시간 · 오류

- 문항 시간(`elapsed`) 중앙과 단계별 시간(`stages`) 중앙, 켬 대 끔. dev 와 held-out 을 합쳐 본다.
- 오류 행 수(`error`).

## 4. 판정 (측정 전 고정)

1. **dev 관문** (held-out 을 돌리기 전에 본다): 얻음 − 잃음 ≥ +3 이고 얻음 ≥ 2 × 잃음. 못 맞추면 R1 을 접는다(held-out 을 돌리지 않는다).
2. **held-out 주:** 늘어남 > 줄어듦 이고 부호 검정 양측 p < 0.05.
3. **보호:**
   - 한쪽에만 든 논문 중 '2' 비율이 켬에서 5%p 이상 낮지 않다.
   - B 층 정답을 잃은 문항 ≤ 1.
   - 오류 행이 켬 ≤ 끔.
   - 문항 시간 중앙 증가 ≤ 3s.
- 모두 맞으면 채택을 제안한다(운영 `.env` 에 `RAG_PAPER_CE_RERANK=1` · 봇 재시작 — 사용자 승인 뒤). 하나라도 어기면 기각한다(운영 변경 없음).
- 판정자 점검(§2.5)용 사용자 판정 20쌍은 아직 없다. 그 점검 전까지 이 판정은 Claude 한 판정자의 결과다.

## 6. 결과 — dev 관문 미달, R1 접음

| 세트 | 정답 든 문항 끔 → 켬 | 얻음 : 잃음 | 경로 다름 | 컨텍스트 바뀐 문항 | 컨텍스트 편수 평균 | 문항 시간 중앙 | 검색 단계 중앙 |
|---|---|---|---|---|---|---|---|
| 162 | 148 → 150 / 159 | 2 : 0 (A003 · A106) | 0 | 87 / 159 | 2.69 → 2.77 | 36.9 → 39.2s | 4.13 → 5.63s |
| real40 | 31 → 31 / 34 | 0 : 0 | 0 | 17 / 34 | 3.68 → 3.85 | 29.5 → 30.9s | 3.91 → 4.43s |
| real2 | 33 → 33 / 34 | 0 : 0 | 0 | 16 / 34 | 3.59 → 3.29 | 39.3 → 41.3s | 3.12 → 4.29s |
| 합 | 212 → 214 / 227 | **2 : 0** (순 +2, p 0.50) | 0 | 120 / 227 | | | |

- §4.1 관문은 순 ≥ +3 이고 얻음 ≥ 2 × 잃음 이다. 결과는 순 +2 로 미달이다. 그래서 **R1 을 접는다.**
- held-out 은 돌리지 않았다. `run.sh` 가 관문에서 멈췄다.
- 운영은 바꾸지 않는다. `RAG_PAPER_CE_RERANK` 는 기본 끔 그대로다.
- 오류 행은 0 → 0 이다.
- 오프라인 얻음이 운영 경로에 남지 않았다.
  - 끔 쪽에서 이미 227문항 중 212문항의 최종 컨텍스트에 정답이 들어 있었다. 남은 여지는 15문항뿐이었다.
  - 오프라인 14 : 2 는 거르기 전 상위 5 의 순서였다.
  - 15편 안에 정답이 드는지(오프라인 @15)는 2 : 0 이었다. 운영 경로 결과도 같은 2 : 0 이다.
  - 상위 5 안의 순서가 바뀌어도, 15편을 거르는 운영 경로에서 정답 포함은 거의 바뀌지 않았다.
- 컨텍스트 논문은 120 / 227 문항에서 바뀌었다. 바뀐 논문이 더 나은지는 정답 ID 로 알 수 없다. 그 판정은 held-out 이 할 일이었지만, 사전 등록대로 관문에서 멈췄다.
- 비용(CPU 30편):
  - 검색 단계 중앙 +0.5 ~ +1.5s
  - 문항 시간 중앙 +1.4 ~ +2.3s
