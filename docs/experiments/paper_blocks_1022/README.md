# 컨텍스트를 논문 단위로 — 같은 논문이 칸을 여러 개 차지하지 않게 (사전 등록, 2026-10-22)

> 측정 **전에** 쓴다. 출발점: 실제 사용(10-22 18:26 "RAG 에서 검색된 문서의 순서나 개수가 답변 품질에 주는 영향 …") 외부 리뷰 65점 — 1편만 찾았는데 밝히지 않고 과장, Lost in the Middle · Long-Context LLMs Meet RAG 누락(둘 다 DB 에 있음).

## 0. 진단

- 그 답: 관련 문서 거르기 `5→2` 였는데 **남은 2편이 같은 논문(2510.21440)의 두 블록**. 모델은 "문서 2편"을 받고 같은 논문 항목 합치기가 1항목으로 줄였다. 결론 다시 쓰기는 논문 2편 이상이 아니라 `대상 아님`.
- 원인 구조: 라우터 검색이 `top_k=RAG_TOP_K=3`(논문 3편) × 논문당 청크 `HYBRID_CHUNKS_PER_PAPER=2` → 블록 6개(`_format_chroma_hits` 는 논문별 첫 청크를 앞에, 같은 논문 추가 청크를 뒤에 둔다). 답변 노드는 라우터 컨텍스트를 그대로 쓰고 앞 5블록을 자르므로 **같은 논문이 2칸**을 먹는다. 두 번째 블록에도 같은 초록이 다시 붙는다.
- 빈도(rf0 = 운영과 같은 설정, 74문항): 답 72 중 **28(39%)** 에서 같은 논문이 두 칸 이상, 낭비된 칸 **54**. 이것이 본론 항목 갈라짐(merge_same_paper_1021) · `[A][A]`(cite_cleanup_1022) · 결론 "두 문서 모두"(conclusion_rewrite_1021 §8) · 이번 "2편인데 실제 1편"의 공통 뿌리다.

## 1. 바꾸는 것 — `RAG_PAPER_BLOCKS` (기본 `0`)

`1` 이면:
- `_format_chroma_hits`: 같은 논문의 추가 청크 블록을 **내보내지 않는다**(논문당 한 블록: 머리 · 초록 · 최고 점수 청크). 단 `wants_depth`("자세히" 등) 검색은 같은 논문 청크를 모으는 경로라 그대로 둔다.
- 라우터 검색 `top_k` 를 3 → **5**(답변 노드가 쓰는 칸 수와 맞춤).
- 코드 `core/rag/agent_chroma_rag.py` · `core/graph/agent_nodes.py`, 테스트 `tests/unit/test_paper_blocks.py`.

**읽은 것** — 중복 칸 제거는 해가 없고(보호 통과, 응답 −3s, 검색 ok · N 소폭 +) 이후 후처리(같은 논문 항목 합치기 · 인용 정리 · 결론 "두 문서 모두")의 원인을 줄이지만, 사전 등록한 효과(정답 인용)는 없다.
