# 열린 요청용 판정 프롬프트 — 오프라인 dev 측정 (2026-11-03, 사전 등록)

## 0. 왜

- R8(`open_gate_1103` · `open_gate2_1103`)은 열린 요청("추천해줘" · "N편" · "아무거나" · "최신 논문")에서 판정을 건너뛰었다.
  - 거짓 '없음'은 8 → 1 로 줄었지만 거짓 '있음'이 0 → 3 으로 늘어 접었다. 맞는 '없음'까지 잃었기 때문이다.
- 판정 프롬프트는 "사용자는 **특정한 연구 하나**를 찾고 있다"를 전제한다. 열린 요청에는 이 전제가 맞지 않는다.
- 그래서 열린 요청에만 "이 주제를 다룬 문서가 있나"를 묻는 판정 꼬리를 쓴다. 이것은 `judge_none_1103` §3 후보 2(판정 프롬프트 손보기)를 열린 요청에만 적용한 꼴이다.
- 이번 라운드는 dev 만, 판정만 오프라인으로 잰다. 답은 만들지 않고 운영 · 코드는 바꾸지 않는다.

## 1. 바꾸는 것 — 판정 꼬리 v1

- 운영 판정은 답변 앞부분을 같이 쓴다(`RAG_JUDGE_SHARED_PREFIX=1`, `judge_presence_shared`). 그 꼬리 `SHARED_TAIL` 을 열린 요청(`_GATE_OPEN` 이 걸리는 질문)에서만 아래로 바꾼다.
- 나머지(앞부분 · 모델 `yunsur_v13` · temperature 0 · seed 0 · 64토큰 · 답 꼴 파싱)는 운영과 같다.

```
[판정 요청 — 답변을 쓰지 말고 판정 한 줄만]
위 [참고 문서]는 사용자의 질문으로 검색한 논문 발췌다. 사용자는 특정한 연구 하나가 아니라 **질문의 주제를 다룬 논문**을 추천받으려 한다.

질문의 주제를 주된 내용으로 다루는 문서가 있으면 그 문서 번호를, 하나도 없으면 `없음`을 답하라.
- 방법·대상·결과가 질문의 표현과 똑같지 않아도 주제가 같으면 고른다.
- 낱말이나 분야만 겹치고 주된 내용이 다른 주제이면 `없음`이다.
- 여러 문서가 맞으면 가장 앞 번호 하나만 적는다.

출력은 정확히 한 줄: `답: 문서 N` 또는 `답: 없음`

[질문]
{question}
```

## 2. 문항 (dev 만)

- 판정이 돈 열린 요청 중 컨텍스트가 저장된 167 문항이다.
  - OB 115(`ogb_s1`, R8 확인 라운드 뒤 dev).
  - O 42(`og_s1`, R8 1회차 뒤 dev). 규칙에 안 걸리게 쓴 4 와 held-out `H_*` 는 뺀다.
  - judge_none dev 10(`jn_dev`).
- 저장 판정은 '없음' 33 · 문서 134 다.
- 판정 입력은 저장 행에서 운영과 같은 글자로 다시 만든다. 다시 만든 답 입력의 sha1 이 저장 행의 `answer_input` 과 167 모두 같은 것을 확인했다.

## 3. 라벨 — 측정 전 고정

- 주제는 질문이 추천을 요청한 연구 주제다(예: "밀집 검색기를 학습시키는 방법"). 편수 · '최신' · '좋은' 같은 말은 주제가 아니다.
- **F** (판정 틀림): 어떤 문서가 제목 · 초록에서 그 주제를 주된 내용으로 다룬다. 방법 · 대상이 질문 표현과 달라도 같은 주제면 F 다.
- **T** (판정 맞음): 어느 문서도 그 주제를 주된 내용으로 다루지 않는다. 낱말 · 분야만 겹치거나 다른 과제다.
- **?** (애매): 주제를 일부만 다룬다. 더 넓은 상위 주제의 서베이, 주제가 부수 요소인 응용, 입장 논문 등이다.
- 저장 판정 '없음' 33 은 새 꼬리를 돌리기 **전에** 질문과 컨텍스트만 보고 라벨한다(`labels.tsv`).
- 측정 뒤 새로 '없음'이 된 문항은 같은 규칙으로 라벨한다. 이때 어느 꼬리가 '없음'을 냈는지는 보지 않는다(`labels_extra.tsv`).

## 4. 측정

- `oj.py run`: 문항마다 옛 꼬리, 새 꼬리 순서로 판정 2번을 부른다. 결과는 `oj_dev.jsonl` 이다.
  - 앞부분이 같아 두 번째 호출은 캐시를 쓴다. 예상 시간은 ~50분이다.
- Chroma · DB · 운영 `.env` 는 건드리지 않는다.

## 5. 관문 — 측정 전 고정

| 관문 | 기준 |
|---|---|
| G0 재현 | 옛 꼬리 오프라인 판정의 '없음' 여부가 저장 판정과 ≥ 95% 같다 (167) |
| G1 회복 | 라벨 F 중 새 꼬리가 '없음'을 안 낸 비율 ≥ 70% |
| G2 보존 | 라벨 T · ? 중 새 꼬리가 '없음'을 안 낸 비율 ≤ 20% |
| G3 새 '없음' | 저장 판정이 문서인 134 중 새 꼬리가 '없음'을 낸 문항 ≤ 3 |

- 왜 T 와 ? 를 함께 보나: R8 확인 라운드에서 판정을 건너뛰어 '없음'이 사라진 문항은 F 가 처리 8 : 대조 1 이었다. T · ? 는 0 : 6 이었다.
  - 따라서 F 만 바꾸고 T · ? 는 남겨야 held-out 에서 이길 수 있다.
- 미달이면 꼬리를 **한 번만** 고쳐(v2) 같은 dev 로 다시 잴 수 있다. 그래도 미달이면 접는다. 고친 횟수는 held-out 라운드 등록에 적는다.

## 6. 관문 뒤

- 모두 넘으면 held-out A/B 라운드를 설계한다. 플래그는 `RAG_OPEN_JUDGE`(기본 0)이고, 문항 수는 이번 dev 비율로 §2.5 에 따라 정한다. 진행은 사용자 결정이다.
- 운영 반영은 그 라운드를 넘고 **사용자 승인 뒤**에만 한다.

### 8.2 v2 — 측정 전 고정

- v1 에서 세 가지를 바꿨다. 기준 · 라벨 · 문항은 그대로다.
  - 기법을 다른 목적의 한 단계로만 쓰는 문서와, 질문 주제보다 넓은 분야를 두루 다루는 개관 · 입장 논문은 고르지 않는다.
  - 이런 문서에 "`없음`이다" 대신 "고르지 않는다"를 썼다. 다른 문서가 맞으면 그 문서를 고를 수 있게 하려는 것이다.
  - 주제가 없는 요청은 첫 문서를 고른다.
- 위험: 같은 dev 의 실패를 보고 고쳤으니 dev 결과가 좋게 나오기 쉽다. held-out 라운드를 등록하면 "v2, 1회 고침"을 적는다.
- 측정은 `oj.py run v2` → `oj_dev_v2.jsonl` 이다. 새로 '없음'이 된 문항은 `labels_extra_v2.tsv` 로 라벨한다.

```
[판정 요청 — 답변을 쓰지 말고 판정 한 줄만]
위 [참고 문서]는 사용자의 질문으로 검색한 논문 발췌다. 사용자는 특정한 연구 하나가 아니라 **질문의 주제를 다룬 논문**을 추천받으려 한다.

질문의 주제를 주된 내용으로 다루는 문서가 있으면 그 문서 번호를, 하나도 없으면 `없음`을 답하라.
- 방법·대상·결과가 질문의 표현과 똑같지 않아도 주제가 같으면 고른다.
- 질문이 말한 기법·과제가 문서의 중심이어야 한다. 그 기법을 다른 목적의 한 단계로만 쓰는 문서, 질문 주제보다 넓은 분야를 두루 다루는 개관·입장 논문은 고르지 않는다.
- 낱말이나 분야만 겹치고 주된 내용이 다른 주제인 문서도 고르지 않는다.
- 질문에 주제가 없으면(아무 논문 · 재밌는 논문) 첫 문서를 고른다.
- 여러 문서가 맞으면 가장 앞 번호 하나만 적는다.

출력은 정확히 한 줄: `답: 문서 N` 또는 `답: 없음`
```
