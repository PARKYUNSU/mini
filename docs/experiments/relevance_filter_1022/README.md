# 관련 없는 문서를 답변 전에 빼기 — 2단계 평가 (사전 등록, 2026-10-22)

> 측정 **전에** 쓴다. 출발점: 실제 사용(10-22 09:14 "긴 컨텍스트 중간에 있는 정보를 LLM 이 놓치는 문제 …") 외부 리뷰 — 답 3편 중 2편(2503.09579 GQA 비용 최적화 · 2607.02980 HiLS 희소 어텐션)이 질문과 무관한데 본론에 인용되고 "(참고: … 질문과 직접 관련이 없습니다)"라고 스스로 적은 뒤 결론에서 비중 있게 다뤘다. 정답 유무 판정은 "문서 3" 하나를 골랐지만 답변 단계는 판정과 무관하게 5편을 다 받는다.

## 0. 진단 (저장된 at1 답, 읽기 전용)

| 세트 | 컨텍스트 논문 | 그중 정답(gold) | 답이 인용한 논문 | 그중 gold 아님 |
|---|---|---|---|---|
| at1_real40 | 203 | 64 | 113 | 54 |
| at1_real2 | 174 | 75 | 97 | 38 |

(gold 는 목록 질문에서 완전하지 않다 — "gold 아님"은 "무관"의 상한이다.)

## 1. 바꾸는 것 — `RAG_RELEVANCE_FILTER` (기본 `0`)

`1` 이면 RAG 답변 경로에서 컨텍스트를 거른 뒤(top-5 · 목록 압축 등) **번호를 매기기 전**에:
- 한 번의 호출(답변 모델, temperature 0, seed 0, 비-thinking, 32토큰): 질문 + 문서마다 `[문서 N] 제목` + 초록 앞 600자 → "질문이 묻는 주제를 **직접** 다루는 문서 번호를 모두" `관련: 1, 3` 또는 `관련: 없음`.
- 관련으로 나온 문서만 남긴다. **안전장치:** 문서가 1편이면 호출하지 않음 · 응답을 못 읽으면 그대로 · `없음`이면 그대로(정답 유무 판정이 '없음' 처리를 맡는다).
- 남은 문서가 1편이면 기존 문서 수 지시("본론 항목은 1개만")가 그대로 걸린다.
- 코드: `core/llm/relevance_filter.py`, 테스트 `tests/unit/test_relevance_filter.py`.

## 2. 방법 — 2단계

**1단계(오프라인, 판정만):** at1_real40 · at1_real2 의 저장 컨텍스트(문서 2편 이상)에 관련성 호출만 돌려, gold 논문을 남겼는지 · 무엇을 뺐는지 본다. 스크립트 `stage1.py`.

**2단계(답 재생성, 1단계 통과 시):** real40 + real2 74문항을 `rf0`(꺼짐) · `rf1`(켬)으로, 운영 `.env` 그대로. 실행 `.cron/run_rf.sh`, 채점 `stage2.py`.

## 3. 판정 (측정 전 고정)

**1단계 (통과해야 2단계):**

| 지표 | 기준 |
|---|---|
| gold 유지율 — 컨텍스트에 있던 gold 논문 중 남긴 비율 | ≥ 95% |
| gold 아닌 논문 중 뺀 비율 | ≥ 30% (못 빼면 할 의미가 없다) |
| 뺀 논문 15개 직접 읽기(질문 · 초록 대조) | 실제로 관련 있는데 뺀 것 ≤ 2 |
| 보고: 호출 시간 중앙, 파싱 실패 수, `없음` 수 | |

**2단계:**

| 지표 | 기준 |
|---|---|
| **주:** 답이 인용한 논문 중 gold 아닌 논문 수(문항 합) | 처리 < 대조, 문항 짝 부호 검정 양측 p < 0.05 |
| 보호: 검색 ok · N 정답 · C 두 편 인용 · T 정답 인용 ≥ 3 (real40 · real2) | 각각 처리가 대조보다 2 이상 낮지 않음 |
| 보호: 응답 시간 중앙 | ≤ 대조 + 8s |
| 보고: 남은 문서 1편인 답 수, 결론 다시 쓰기 대상 수 변화 | |

채택이면 사용자 승인 후 운영 `.env` `RAG_RELEVANCE_FILTER=1` + 봇 재시작.
