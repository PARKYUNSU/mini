# 답변 지시 보강 — 핵심 구성요소·결과 명시 + 서베이 질문 (사전 등록, 2026-10-13)

> 측정 **전에** 쓴다. 출발점: [`upper_bound_1013/`](../upper_bound_1013/) §6.4. v13 은 120B 대비 correct 78% (짝 3:15) 인데, 격차 대부분이 핵심 구성요소·결과를 빠뜨린 partial 이었고 서베이 질문 3건(C1_07·C1_10·C1_11)에서 정답 서베이를 놓쳤다.

## 1. 바꾸는 것

`RAG_ANSWER_DETAIL=1` 이면 RAG 시스템 프롬프트에 `core/llm/agent_prompts.RAG_DETAIL_HINT` 두 줄을 붙인다(기본 꺼짐).

1. 본론 각 항목에 문서가 **명시한** 핵심 구성요소(모듈·기법 이름)와 주요 결과 중 하나 이상을 구체적으로 쓴다. 문서에 없는 것은 쓰지 않는다.
2. 질문이 서베이·리뷰를 찾으면 서베이 논문 자체를 본론 첫 항목으로 둔다.

재학습 없음. 답변 모델 `yunsur_v13`, 나머지 운영 설정 그대로(`RAG_CONTEXT_ABSTRACT=1 RAG_PRESENCE_JUDGE=1 RAG_HANZI_RETRY=1`).

**우려:** 이전 측정([`template_collapse_1006/08_depth_paired/`](../template_collapse_1006/08_depth_paired/))에서 9B 는 **길이 지시를 듣지 않았다**. 이번 지시도 무시될 수 있다(그러면 무변화). 반대로 "수치·결과를 쓰라"는 지시가 날조를 늘릴 수 있다.

## 2. 방법

- 대조 `ans_v13_db2` / 처리 `ans_v13_detail`: 둘 다 `eval_e2e_ko.py --answer --save-context`, 162문항, **현재(재구축) Chroma**. 기존 `ans_v13abs_pj` 는 재구축 전 DB 라 쓰지 않는다.
- **같은 DB 보장:** 두 실행 동안 HF 공백 백필을 일시정지(`kill -STOP`)한다. 일일 수집(01:00) 전에 끝낸다. 짝은 `context_papers` 가 같은 문항만 쓴다(수를 보고).
- **주 판정: Claude 눈가림 짝 판정**(answer_quality_1010 §6 기준, X/Y 순서 문항 ID 시드). 날조 규칙은 upper_bound_1013 §6.4 와 같다 — 초록과 모순되거나, 다른 논문 기법을 정답 ID 로 붙이거나, 근거 없는 비교 우위·수치를 쓰면 날조. 검색 발췌에서 온 정확한 세부는 날조 아님.
- 자동 지표: `nogold_metrics.py ans_v13_db2 ans_v13_detail`(거짓 부정·일관 고지), 한자 섞임, 답변 길이.

## 3. 채택 규칙 (모두 만족)

| 지표 | 기준 |
|---|---|
| **correct** 짝 (주) | 처리 > 대조, McNemar 양측 p < 0.05 |
| ok 짝 | 처리가 유의하게 낮지 않음 (p ≥ 0.05 또는 처리 쪽 우위) |
| 날조 짝 | 처리가 유의하게 많지 않음 (같은 규칙) |
| 거짓 부정 (정답 있음) | ≤ 5% |
| 일관 고지 (정답 없음) | 처리가 유의하게 낮지 않음 |

채택이면 운영 `.env` 에 `RAG_ANSWER_DETAIL=1` 을 **사용자 승인 후** 켠다.

예상: correct 는 소폭 오르지만 유의하지 않을 수 있다(지시 무시). 서베이 3건은 1~2건 개선. 날조는 비슷하거나 조금 는다.

## 6. 결과 (2026-10-14) — **채택하지 않음**

같은 컨텍스트 RAG 157문항(컨텍스트 다름 2) · 정답 있음 **135쌍**. Claude 눈가림 짝 판정 [`judged_claude_blind_ans_v13_db2_vs_ans_v13_detail.jsonl`](../answer_quality_1010/judged_claude_blind_ans_v13_db2_vs_ans_v13_detail.jsonl).

|---|---|---|---|---|---|

자동 지표: 답 길이 중앙값 653 → 651자, 한자 섞임 2 → 1, 경과 중앙값 69.6 → 71.1s.

**읽은 것**
- 방향은 예상대로(correct +8, 짝 12:4)지만 주 지표가 기준에 못 미쳐 **사전 규칙상 채택하지 않는다.** 운영 `.env` 무변경.
- **답 길이가 그대로다**(653 vs 651). 두 답이 문장 단위로 거의 같은 짝이 대부분이었다 — template_collapse_1006 과 같은 결론: 9B 는 시스템 프롬프트 끝의 추가 지시를 거의 반영하지 않는다. correct 가 갈린 16짝은 주로 한쪽이 본론에 모듈 이름·결과를 한 항목 더 쓴 경우였다(판정 중 관찰, 따로 세지 않음).
- 서베이 지시 효과도 없었다(C1_07 은 둘 다 정답 서베이를 놓침; 이번 DB 에서 C1_10·C1_11 은 둘 다 짚음).
- 날조가 늘지 않은 것(3 → 5, 유의 아님)은 안심 요소.
- 다음 후보: 지시가 아니라 **학습 데이터**로 — v13 교사 데이터의 본론 항목에 "핵심 구성요소·결과"를 넣어 재학습하거나, 초록 컨텍스트가 붙은 운영 프롬프트로 교사 데이터를 다시 만드는 안(README §지금 상태의 v12~v14 교훈과 같은 방향).
