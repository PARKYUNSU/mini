# 비교 질문 두 대상 각각 검색 (사전 등록, 2026-10-15)

> 측정 **전에** 쓴다. 출발점: 비교 질문에서 **두 편 모두** 컨텍스트에 들어오는 비율이 real40 3/11 · real2 2/14 ([`real_eval2_1015/`](../real_eval2_1015/) §6). 한 편은 찾는데 두 편을 함께 못 찾는다. 운영은 질문을 영어 키워드 한 줄로 바꿔 한 번 검색한다 — 두 대상이 한 줄에 섞인다. 문헌: 질문 분해는 1차 검색에서 의미를 희석한다(2606.08577) → 질문 전체를 쪼개지 않고 **대상 이름만** 따로 검색해 앞에 붙인다.

## 1. 바꾸는 것

`RAG_COMPARE_SPLIT=1` (기본 `0`) 이고 질문이 게이트 `cmp` 유형이면(`presence_judge.gate_types`):
1. `agent_nodes._extract_comparison_targets` — 검색어 추출과 같은 LLM 으로 두 대상을 영어 검색어 두 줄(`A:` `B:`)로 뽑는다. 실패하면 기존 그대로.
2. 대상마다 `rag.search(대상, …)` → 각 상위 2블록을 앞에, 원래 검색 블록을 뒤에 붙이고 같은 논문은 한 번만(`_merge_rag_blocks`), 이후 기존 상위 5블록 자르기.
그 밖의 질문은 코드 경로가 같다. 대가: LLM 1회 + 검색 2회 추가.

## 2. 방법

같은 DB(10-15 수집 뒤, Chroma 서버, 쓰기 없음)에서 대조(`RAG_COMPARE_SPLIT=0`)·처리(`=1`) 연달아, 검색만:
- real40 비교 11문항(C01–C11) · real2 비교 14문항(C01–C14, 그중 게이트 `cmp` 12) · 162 중 `cmp` 2문항(A054 · A090).
- 운영 설정 그대로(`RAG_CONTEXT_ABSTRACT=1 RAG_PRESENCE_GATE=1`).

## 3. 판정

| 지표 | 기준 |
|---|---|
| **주:** 게이트 `cmp` 비교 문항의 **두 편 모두 검색** 짝 (real40 11 + real2 12, real2 C01 은 정답 한 편이 Chroma 에 없어 제외 → 22문항) | 처리 > 대조, McNemar 양측 p < 0.05 |
| 같은 문항의 한 편 이상 검색 (`ok`) | 처리가 유의하게 낮지 않음 |
| 162 `cmp` 2문항 `ok` | 잃지 않음 |
| 검색 단계 지연 중앙값 (비교 문항) | 보고 (+20s 안팎 예상) |

채택이면 **사용자 승인 후** 운영 `.env` `RAG_COMPARE_SPLIT=1`.

예상: 두 편 모두 4~5/22 → 12~16/22 (대상 이름이 정확하면 제목 매칭이 각자 잡는다). 이름 없이 묘사된 대상(C03 · C11 등)은 덜 오른다.
