# yunsur_v13 — 정답 없는 RAG 예시의 형식만 고친다 (사전 등록, 2026-10-11)

> 이 문서는 데이터를 만들기 **전에** 쓴다. §3 판정 규칙은 결과를 본 뒤 바꾸지 않는다.

## 1. 문제 — v12 의 거짓 부정 31%

[yunsur_v12 §4.5](../yunsur_v12/README.md): v12 는 정답 논문을 컨텍스트에서 받고도 43/138 (31%) 에서 서론 첫 문장을 "제공된 문서에는 질문에서 찾는 … 없습니다"로 쓴 뒤, 본론·결론에서는 그 논문을 찾았다고 설명한다 (base 0%). 운영은 후처리(`core/llm/answer_fix.py`)로 3% 까지 막고 있다.

원인 (2026-10-11 학습 데이터에서 확인): v12 RAG 400건 중 정답 없는 컨텍스트 30건은

- 서론만 "제공된 문서에는 질문이 찾는 연구가 없습니다."로 시작하고,
- 본론은 정답 있는 예시와 똑같이 관련 논문을 답처럼 나열하며,
- 결론에서 "없다"를 다시 말하는 것은 **9/30** 뿐이다. 나머지 21건은 "제공된 문서들은 …을 제시합니다" 같은 중립 요약.

즉 정답 유무에 따라 달라지는 것이 **서론 한 문장뿐**이라, 모델은 그 문장을 정답 유무와 묶지 못하고 7.5% 쯤의 상투어로 배웠다. 결론이 중립이라 "없다고 해 놓고 찾았다고 끝내는" 모순도 함께 배웠다.

## 2. 바꾸는 것 — 하나뿐

**정답 없는 RAG 예시 30건의 답 형식.** 같은 30개 프롬프트(v12 에 들어간 src_pid 그대로)에 교사를 다시 돌린다. 나머지는 v12 와 바이트 동일:

- RAG 정답 있는 370건, 잡담 300, 계획 400 — 그대로 (검증한다).
- 하이퍼파라미터·`MAX_SEQ_LENGTH=3072`·시드 — v12 와 같다.
- 정답 없는 예시의 비율(30/400)도 그대로 — 비율과 형식을 동시에 바꾸면 무엇이 효과인지 모른다.

새 형식 (교사 규칙 4b, 정답 없음일 때만):

1. 서론 첫 문장: `제공된 문서에는 질문이 찾는 연구가 없습니다.` (v12 와 같음)
2. 본론: 주제가 가장 가까운 문서 최대 2개, 항목 이름 뒤에 **`(관련 연구)`** 표시. 내용은 문서 근거 규칙(1~3) 그대로.
3. 결론 첫 문장: **`따라서 질문이 찾는 연구는 제공된 문서에서 찾을 수 없습니다.`** 그 뒤 관련 문서가 다루는 범위를 한 문장 이내로.

→ 정답이 없으면 서론·본론·결론 **세 곳 모두** 다르게 생기고, 정답이 있으면 셋 다 v12 와 같다. 모델이 "없다" 모드로 들어가면 끝까지 일관되게 쓰도록 하는 것이 목적이다.

검증: v12 자동 검증(`verify_v12.check`) + 새 규칙 3개 자동 확인(서론 첫 문장 · 항목마다 `(관련 연구)` · 결론 첫 문장) + 문서 근거 LLM 검증(`verify_v12_llm`) 통과분만. 30건 중 통과 못 한 것은 같은 프롬프트로 다시 생성(최대 3회), 그래도 안 되면 다른 정답 없는 프롬프트(적격 109개 중, 평가 누수 없음)로 대체하고 수를 기록한다.

교사: Groq `openai/gpt-oss-120b` (v12 와 같은 모델, RunPod 대신 무료 한도 사용).

## 3. 평가 (사전 선언)

생성: `RAG_ANSWER_MODEL=yunsur_v13` 으로 `eval_e2e_ko.py --answer --label ans_v13` 162문항 (평가 프로세스에만). **후처리 적용 전 원문**으로 센다(`answer_format_stats.py`, 후처리 없이). 컨텍스트가 `ans_v12` 와 같은지 확인.

- **주 지표 — 거짓 부정**: 정답이 컨텍스트에 있는 138문항에서 서론이 "없다"고 하는 비율. v12 와 짝 McNemar (양측 α=0.05).
- 부 지표 (서술만): 자기모순(서론 "없다" + 결론이 "없다" 아님) 비율, 정답 없는 21문항에서 일관 고지(서론·결론 모두 "없다") 수, 첫 항목이 정답 논문 비율.
- **안전 지표 — 내용**: v13 vs v12 짝 비교, `ok`(correct+partial)·날조. 판정은 [`judge_answers.py`](../../../scripts/judge_answers.py) 의 검증된 단일 답변 프롬프트로 답변 하나씩, 모델 이름 없이(그 자체로 눈가림) — RunPod H100 vLLM (`--base-url`), 비교는 [`compare_judged_pairs.py`](../../../scripts/compare_judged_pairs.py). 판정자는 **gpt-oss-120b** (Claude 와 일치도 검증 통과, [answer_quality_1010 §6.1](../answer_quality_1010/README.md)). Claude 는 v12 답변을 이미 다 읽어 눈가림이 안 되므로 쓰지 않는다.

판정:
- **채택**: 거짓 부정이 v12 보다 유의하게 낮다 **그리고** ok 가 유의하게 낮지 않다 **그리고** 날조가 유의하게 높지 않다.
- **보류**: 거짓 부정 차이가 유의하지 않다 → v12 + 후처리 유지.
- **실패**: ok 가 유의하게 낮거나 날조가 유의하게 높다.

예상: 거짓 부정 31% → 10% 이하. 정답 없는 21문항의 일관 고지는 v12(서론만 14/21) 보다 결론까지 일관된 수가 늘어난다. 내용 지표는 같다(정답 있는 370건이 그대로이므로).

운영: 채택돼도 후처리는 안전망으로 남긴다.

## 3.5 결과 — 자동 지표 (2026-10-11)

학습: L40S, 138스텝, loss 1.004 → 0.699, 잘림 0. `ans_v13` 162문항 생성(RAG 159). **컨텍스트가 `ans_v12` 와 같은 RAG 154문항**만 비교(5문항 다름 — 사전 등록대로 제외). 후처리 전 원문.

| 154문항 | v13 | v12 |
|---|---|---|
| **거짓 부정** (정답 있는 133문항, 서론 "없다") | **0** | 41 |
| 자기모순 (서론 "없다" + 결론 "없다" 아님) | **0** | 49 |
| 정답 없는 21문항: 서론·결론 일관 "없다" | **0** | 2 |
| 정답 없는 21문항: 답변 어디든 "없다" 류 | 6 | 14 |
| 첫 항목이 정답 논문 (159 기준) | 0.92 | 0.90 |

- **주 지표: 거짓 부정 짝 v13만 0 · v12만 41 → McNemar p = 9×10⁻¹³.** 사전 규칙의 첫 조건 충족.
- **예상과 반대인 부작용:** 정답 없는 21문항에서 v13 은 "없다" 모드에 **한 번도** 들어가지 않는다(일관 고지 0/21, v12 원문 서론만 14/21·일관 2/21, base 서론 1/21). §3 예상("일관 고지가 늘어난다")은 틀렸다. 정답 없음 형식을 서론·본론·결론 전체로 뚜렷하게 만들자, 7.5% 뿐인 그 모드를 모델이 거의 고르지 않게 된 것으로 보인다 — 자기모순은 사라졌지만 "없다"고 말하는 능력도 함께 사라졌다.
- 해석: v12 의 서론 "없다"는 정답 유무와 거의 무관한 상투어였다(정답 있음 31% vs 없음 67%). v13 은 그 상투어를 버리고 항상 "찾았다" 모드로 쓴다 — base 와 같은 행동.

## 3.6 결과 — 안전 지표(내용) 와 판정 (2026-10-11)

판정: gpt-oss-120b (RunPod H100 Secure $3.99/h, 약 15분), 답변 하나씩 모델 이름 없이. 짝 133문항(컨텍스트 동일·정답 있음·양쪽 판정됨).

| 133쌍 | v13 | v12 |
|---|---|---|
| ok (correct+partial) | 108 | 111 |
| correct | 16 | 25 |
| wrong | 21 | 15 |
| absent | 4 | 7 |
| 날조 | 39 | 36 |

- **ok 짝: v13만 10 · v12만 13 → p = 0.68 (유의하게 낮지 않음).**
- **날조 짝: v13만 20 · v12만 17 → p = 0.74 (유의하게 높지 않음).**
- 참고(사전 등록 지표 아님): correct 짝 v13만 7 · v12만 16, p = 0.093 — 유의하지 않지만 v13 쪽으로 기운다. 다음 라운드에서 지켜볼 것.
- gpt-oss 는 Claude 보다 엄격하다(v12 ok: Claude 124/138, gpt-oss 111/133) — 판정자가 달라 v12 절대 수치는 §4.5 와 비교하지 않는다.

**사전 규칙(§3)에 따른 판정: 채택** — 거짓 부정이 유의하게 낮고(0 vs 41, p = 9×10⁻¹³), ok 가 유의하게 낮지 않으며, 날조가 유의하게 높지 않다.

단서: 정답 없는 문항에서 "없다" 고지가 0/21 이 됐다(§3.5). 운영의 후처리는 v13 에서 할 일이 없지만 안전망으로 남긴다. "정답이 없을 때 없다고 말하기"를 다시 살리려면 별도 라운드가 필요하다 — 비율(7.5%)을 늘리거나, 정답 유무를 판단하는 단계를 생성과 분리하는 것이 후보.

## 4. 비용

교사 Groq 무료(하루 한도 내, 30~90 호출). 학습 RunPod L40S ≈ $0.5. 판정 gpt-oss-120b — Groq 하루 한도로 276 답변이면 이틀 걸릴 수 있다. 그보다 빠르게 하려면 RunPod H100 vLLM (시간당 가격을 미리 알리고 사용자 확인 후).
