# 실제 사용형 평가셋 2 + 유형별 light rerank 끄기 확인 (사전 등록, 2026-10-14 밤)

> 측정 **전에** 쓴다. 출발점: [`light_rerank_1014/`](../light_rerank_1014/) §5 — light rerank 를 끄면 수치·비교·목록형(real40) 0 : 9 로 좋아지고 찾기형(162) 18 : 7 로 나빠졌다. "게이트에 걸리는 질문에서만 끈다" 는 그 결과를 **보고 나서** 세운 가설이라, real40 이 아닌 **새 질문 세트**로 확인한다.

## 1. 새 세트 (34문항, `questions.tsv` · `gold.jsonl` · `spec.jsonl`)

- 162 · real40(real_eval_1013) 의 정답 논문과 real40 후보 논문은 모두 제외, 시드 1015.
- **N 수치 12** (초록에 수치가 있는 논문) · **C 비교 14** (같은 제목 키워드의 두 논문 — real40 과 다른 주제: 양자화·증류·연합학습·시계열·GNN·에이전트 메모리·코드 생성·토크나이저·월드모델·DiT·ICL·CoT·VLA·워터마크) · **T 목록 8** (제목 키워드 논문 전부가 정답).
- 측정 전 셈: 게이트(`presence_judge.gate_types`)에 걸림 **32/34** (C05 · C08 은 "각각 뭘 하는 거야/어떻게 다뤄" 라 안 걸림 — 그대로 둔다). C01 정답 중 2605.19972 는 Chroma 에 없어 한 편만 찾을 수 있다.
- 질문 문장은 Claude 가 사용자 말투로 썼다.

## 2. 바꾸는 것

`RAG_LIGHT_RERANK_GATED_OFF=1` (기본 `0`) 이면 게이트에 걸리는 질문만 `ChromaRAGTool.search(light_rerank=False)` — 논문 단위 light rerank 를 건너뛴다(`core/graph/agent_nodes.py`). 나머지는 운영 그대로(`RAG_PRESENCE_GATE=1` 포함).

## 3. 방법

- 일일 수집(10-15 01:00)이 끝난 뒤 같은 DB 로 대조·처리를 연달아 (Chroma 서버, 쓰기 없음), **검색만**:
  - `r2_ctl` / `r2_lrg`: 새 세트 34문항
  - `g4_ctl` / `g4_lrg`: 162 중 게이트에 걸리는 4문항(A015 · A054 · A090 · C1_02) — 나머지 158 은 코드 경로가 같다.
- 지표 `ok`: 정답 논문이 최종 컨텍스트에 있음(C 는 한 편 이상, T 는 정답 집합 중 ≥ 1). 부: C 두 편 모두 검색, T 컨텍스트 안 정답 수.

- 운영 설정은 새 실제 사용형 세트에서 N 12/12 · T 7/8 로 real40(22/34)보다 훨씬 좋다. real40 의 비교 질문들이 유독 어려웠던 것으로 보인다(같은 키워드 군집이 크고 제목이 일반적).
