# 목록 블록 결과 문장 v2 — 숫자 대조 + 짧은 예산 (사전 등록, 2026-10-26)

> 측정 **전에** 쓴다. 출발점: 실사용 job 129(10-26) — "관련 없는 문서가 섞였을 때 RAG가 흔들리지 않게 하는 연구" 답의 본론이 RbFT · GGatrieval 등의 **방법 대신 문제 배경**만 옮겼다. 원인은 목록 모드가 블록마다 초록 **앞 500자**만 남기는 것(`_compact_list_blocks`). 최근 저장 답 5 세트 블록 984 개 중 압축 블록 806 개는 결과 수치가 든 경우가 **3%**(전체 초록 34%), 제안 문장이 든 경우 44%(80%). list_findings_1023 의 `RAG_LIST_FINDINGS=1`(제안 · 결과 · 대상 문장 고르기)은 근거 수치 항목 7 → 41 · 배경만 항목 4 → 0 이었지만 **응답 +16s · 숫자 오기 2건**으로 보류됐다(10-23 사용자 결정).

## 1. 바꾸는 것 (처리 조건 `lf2` = 셋 다 켬, 각 기본은 끔)

- `RAG_LIST_FINDINGS=1` — list_findings_1023 그대로.
- `RAG_LIST_ABS_CHARS=400` — 목록 블록 초록 예산 500 → 400 자(답 길이 · 시간 억제). 새 환경 변수, 기본 500.
- `RAG_BODY_NUM_CHECK=1` — **본론 항목 숫자 대조**: 항목이 인용한 블록에 그대로 없는 숫자(두 자리 이상, 연도 제외, LaTeX `46{,}080` · `\\%` 정규화)가 든 문장을 그 항목에서 뺀다. 문장을 다 빼야 하면 항목은 그대로. 목록 모드 밖 답에도 적용된다. `core/llm/body_numbers.py`, 테스트 `tests/unit/test_body_numbers.py`(전체 699 통과).

## 2. 방법

- **새 목록 질문 40** (`questions.tsv`, 측정 전 고정) — 이전 세트와 다른 주제 · 문장, 모두 "~연구들 정리해줘" 형.
- 맥미니에서 같은 질문을 두 조건으로: 대조 `lf0v`(운영 `.env` 그대로) · 처리 `lf2`(위 셋을 환경 변수로 켬). `--answer --save-context`.
- **자동 채점:** list_findings_1023 `score.py` 방식 — 항목별 숫자를 그 항목이 인용한 논문의 **전체 초록**(`raw_data_queue`)과 대조, LaTeX 숫자 정규화를 더함.
- **눈가림 판정:** 두 조건 본론 항목에서 각 60 개(시드 1026)를 섞어, 조건을 모른 채 그 논문의 전체 초록과 대조해 `R` 방법 · 결과 · 기여를 말함 / `B` 배경 · 문제만 / `W` 내용이 초록과 다름.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주(눈가림):** `B` 항목 수 — lf2 대 lf0v (각 60) | lf2 < lf0v, Fisher 정확 검정 양측 p < 0.05 |
| 보조(자동): 문항마다 근거 수치 항목 수 | lf2 > lf0v, 부호 검정 (보고) |
| 보호: 초록에 없는 숫자가 든 항목 수(자동) | lf2 ≤ lf0v + 1 |
| 보호: 눈가림 `W` 수 | lf2 ≤ lf0v + 2 |
| 보호: 본론 항목 수 합 | lf2 ≥ 0.9 × lf0v |
| 보호: 응답 시간 중앙 | lf2 ≤ lf0v + 8s (지난번 +5s 기준 · +16s 결과 — 예산 축소로 줄일 목표치) |
| 보고: 답 길이 중앙 · 숫자 대조로 뺀 문장 수 | |

채택이면 사용자 승인 후 운영 `.env` 에 세 변수 + 봇 재시작.
