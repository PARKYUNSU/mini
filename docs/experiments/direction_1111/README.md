# direction_1111: 업무를 돕는 봇 — 설계 초안 (2026-11-11)

> 사용자 요청: "발전 가능성을 조사해 업그레이드하고, 나에게 도움이 되는 봇을 설계해 달라." 사용자가 자기 일을 소개했다. 저장소가 공개이므로 회사 · 제품 · 사람 이름은 적지 않고 일의 꼴만 적는다. 이 문서는 초안이고, 항목마다 측정은 따로 사전 등록한다.

## 1. 누구를 돕나

| 사용자의 일 | 봇에 실제로 온 질문(10-28~11-09) |
|---|---|
| **A. 근거 기반 초안 생성 RAG 서비스** — 기준 문서와 회사 문서를 근거로 보고서 초안을 쓴다 | 판정 모델의 자기편향 · 거르기와 판정 분리 · 사람 표본 몇 건 · 두 판정 모델이 갈릴 때 범위로 보고 · 다른 주체 문서가 섞였을 때 사실로 쓰는 비율 |
| **B. 기준 ↔ 목차 · 지표 매핑 데이터 관리** — 매핑 오류 · 중복 정리 | 두 DB 에서 같거나 비슷한 내용 찾기 |

- 이 기간의 실제 질문 6개 중 5개가 여러 요소 질문이다(`usage_types_1110`: 10-30 이후 5/5).
- 질문의 목적은 대개 **결정을 뒷받침할 근거 찾기**다("이 주장을 뒷받침할 논문", "절차는 무엇인가", "몇 건이면 되는가").
- 지금 봇은 바로 이 꼴에서 가장 약하다(`eval30_1110`: 여러 요소 질문 요소 8/15 · 결론 문제 4/5).

## 2. 경계

- 회사 코드 · 고객 문서 · 고객사 이름 · 자격증명은 이 봇 · 저장소 · 메모리에 넣지 않는다. 공개 논문 · 공개 문서 · 합성 데이터만 쓴다.
- 업무 질문은 로컬 모델 경로(RAG)로 답한다. 밖으로 나가는 것은 영어 검색어뿐이어야 한다(외부 검색 · 클라우드 LLM 경로는 점검 대상).
- 비용이 드는 외부 호출은 예상 비용을 먼저 말한다.
