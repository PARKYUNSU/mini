# 실험 노트 — yunsur_v12: 문서에 근거한 RAG 학습 데이터 (단일 변수)

- 시작일: 2026-10-10
- 선행: [`../answer_quality_1010/`](../answer_quality_1010/) §6 — 같은 컨텍스트에서 **base 가 v9 보다 내용이 압도적으로 정확** (ok 짝 49:2, p<0.0001; 교차 귀속 26→7, 날조 65→36)
- **범위: 단일 변수.** v9 학습 데이터 1,100건 중 **RAG 400건만** 새 데이터로 바꾼다. 잡담 300·계획 400 은 바이트 동일, 하이퍼파라미터는 v9 와 동일(lr 2e-4 포함 — v10/v11 의 lr 축과 섞지 않는다).

## 1. 원인 — v9 RAG 데이터에는 문서가 없다

`finetune_datasets/v9/train_data_v9.jsonl` 의 RAG 400건을 세어 보면:

| | 400건 중 |
|---|---|
| `instruction` 에 `[참고 문서]` | **0** |
| `instruction` 에 `[문서 N]` | **0** (질문만, 중앙값 134자) |
| `output` 에 `[문서 N]` 인용 | **0** |

즉 v9 는 **문서 없이 질문에 기억으로 에세이를 쓰는 법**을 400번 배웠다. 운영에서는 문서 5편을 주지만 모델은 그걸 무시하고 아는 대로 쓰며 ID 만 붙인다 → 교차 귀속·날조. 문헌과 맞다: 모델이 모르는 사실로 파인튜닝하면 환각 경향이 그 비율만큼 늘어난다(Gekhman+ EMNLP'24). 근거 문서를 섞어 넣고 무관 문서를 무시하게 학습하면 RAG 가 좋아진다(RAFT 2024, RetRobust ICLR'24 — 약 1,000건이면 충분).

## 2. 새 RAG 데이터 (400건)

1. **질문**: 코퍼스 논문의 제목·초록으로 한국어 질문을 만든다(로컬 base, `scripts/gen_v12_questions.py`). 유형 비율은 평가 세트와 비슷하게 특정 논문 ≈ 85% · 서베이 ≈ 15%.
2. **입력 = 운영 프롬프트 그대로**: 질문을 운영 `router_node → direct_answer_node` 에 넣고 답변 LLM 호출 직전의 메시지(시스템 + 사용자[참고 문서 5편 + 템플릿])를 그대로 저장한다. RAG 경로(`direct_answer/B`)로 간 질문만 쓴다.
3. **정답 = 강한 교사**: Groq `openai/gpt-oss-120b` 에 **같은 메시지**와 교사 전용 지시를 준다 — 본론 각 문장은 인용한 `[문서 N]` 블록에서 확인되는 것만, **질문의 묘사를 문서 내용처럼 옮기지 않기**, 결론은 본론만 종합. 그리고 RAFT 처럼 **정답 힌트**("질문이 찾는 논문은 [문서 N]" 또는 "없다")를 교사에게만 준다. 학습 입력에는 교사 전용 지시·힌트를 넣지 않는다.
   - 파일럿(2건)에서 확인한 실패와 교정: 힌트 없이는 ① 질문 문장의 묘사("두 모듈", "도구 호출")를 문서 내용처럼 옮겼고 ② 규칙만 강화하자 정답 논문이 컨텍스트에 있는데도 발췌에 세부가 없다며 "그런 연구는 없다"고 했다. 힌트를 준 뒤 둘 다 고쳐졌다.
4. **검증 — 통과한 것만 쓴다**:
   - 자동: 템플릿 섹션(서론·본론·결론), 본론 2~4개, 인용 번호가 1~5 범위, arXiv ID 를 직접 쓰지 않음, 빈 칸·플레이스홀더 없음.
   - 내용(Claude): 본론 각 항목의 주장이 **인용한 `[문서 N]` 블록에 실제로 있는가**. 하나라도 다른 문서 내용이거나 문서에 없으면 탈락.
5. **분포**: 검색이 정답 논문을 놓친 질문(운영에서 ≈15%)도 그대로 둔다 — "문서에 없으면 없다고 말하기" 를 배우는 몫. 비율을 보고한다.

### 2.1 평가 오염 격리 (필수)
- 질문의 출처 논문이 평가 세트(`retrieval_eval_1007/eval_set.jsonl`)의 정답 논문이면 제외.
- 학습 질문과 평가 162문항의 임베딩 코사인 유사도 ≥ 0.85 면 제외. **임베더는 `paraphrase-multilingual-MiniLM-L12-v2`** (데이터를 쓰기 전 파일럿 6문항에서 교정, 2026-10-10): 처음 정한 영어 전용 MiniLM 은 한국어 문장을 구분하지 못해 파일럿 6개가 전부 0.79~0.96 이었다. 다국어 모델에서 **서로 다른 논문의 평가 질문끼리** 최근접 유사도가 p50 0.704 · p90 0.845 라, 0.72 는 '같은 주제(RAG 등)' 만으로 절반을 버린다. 막으려는 것은 주제 겹침이 아니라 **사실상 같은 질문**이므로 p90 위인 0.85 로 둔다. 주제 수준의 누출은 아래 두 규칙(출처 논문·컨텍스트 격리)이 막는다.
- **학습 컨텍스트 5편 중 평가 정답 논문이 하나라도 있으면 제외** — 평가 답변 내용을 미리 보여주지 않는다.

## 3. 평가 (사전 선언 — 결과를 본 뒤 바꾸지 않는다)

- `eval_e2e_ko.py --answer` 162문항, `RAG_ANSWER_MODEL=yunsur_v12` (평가 프로세스에만). 컨텍스트가 `ans_base`·`ans_full` 과 같은지 확인.
- Claude 눈가림 짝 판정([`../answer_quality_1010/`](../answer_quality_1010/) §6 과 같은 기준, 판정자 일치도 검증됨).
- **주 비교: v12 vs base**, 둘 다 RAG·컨텍스트에 정답이 있는 문항, `ok`(correct+partial) 짝 McNemar(양측 α=0.05). 부: correct, 날조, ID 맞고 내용 틀림, 템플릿 준수.
- 판정:
  - **채택**: v12 의 ok 가 base 보다 유의하게 높다, **또는** ok 차이가 유의하지 않고 날조가 유의하게 낮다.
  - **보류**: 둘 다 아님 → RAG 답변 모델을 base 로 둔다(파인튜닝 이득 없음).
  - **실패**: v12 의 ok 가 base 보다 유의하게 낮다.
- 참고 비교: v12 vs v9 (같은 방식). 판정에는 쓰지 않는다.
- 예상: v12 는 v9 보다 확실히 낫고(교차 귀속 감소), base 대비는 ok 동률·날조 감소. base 가 이미 ok 91% 라 ok 로 유의차를 내기는 어렵다.

## 4. 비용·일정

- 교사 Groq `gpt-oss-120b` 무료 한도 하루 200K 토큰, 1건 ≈ 3K 토큰 → **하루 ≈ 60건**. 400건 통과에 질문 ≈ 550개 필요 → **약 9~10일**. 봇 사용이 적어 운영 코딩 영향은 감수(사용자 결정 2026-10-10).
