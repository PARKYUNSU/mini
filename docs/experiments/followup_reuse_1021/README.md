# 이어지는 질문이면 직전 답의 논문을 다시 쓰기 — 다회차 평가 (사전 등록, 2026-10-21)

> 측정 **전에** 쓴다. 출발점: history_gate_1019 §5 — 이어지는 질문 10개가 대조·처리 모두 **0/10**. "그 중 첫 번째 논문 자세히" 가 새로 검색해 다른 논문을 가져오고, 10개 중 3개(F04 · F05 · F07)는 잡담(A)으로, F09 는 도구로 빠졌다.

## 1. 바꾸는 것 — `RAG_FOLLOWUP_REUSE` (기본 `0`)

`1` 이면:
- RAG 답을 낸 뒤 세션에 (질문, 번호 붙이기 전 컨텍스트, 본론 항목별 처음 인용 논문 ID)를 메모리에 둔다.
- 다음 질문이 ① 직전 턴이 바로 그 RAG 답이고 ② `is_followup`(history_gate 판정기)이고 ③ 새 논문을 원하는 표현("다른 논문/연구", "비슷한", "최신", "동향", "추천", "더 찾아/있어")이 **없으면**:
  - 라우터: 하드룰·LLM 분류 전에 B(RAG)로 보낸다.
  - 답변: 새로 검색하지 않고 직전 컨텍스트를 그대로 쓴다. 서수("첫 번째", "두 번째", "3번")가 있으면 직전 답 **본론 N번 항목이 인용한 논문 블록 하나**만(못 찾으면 컨텍스트 N번째 블록).
- 새 논문을 원하는 이어지는 질문(F02 · F06 · F09)은 지금과 같다(대화 기록 반영 새 검색).
- 코드: `core/graph/agent_nodes.py` `followup_reuse_context` · `body_item_ids`, 테스트 `tests/unit/test_history_gate.py`.

## 2. 방법 — history_gate_1019 와 같은 다회차 순서 (맥미니)

- `seq_questions.tsv` · `seq_gold.jsonl`(history_gate_1019) 84문항을 한 대화로, `--answer --save-context --keep-session`. 운영 `.env` 그대로(`RAG_HISTORY_GATE=1` 포함).
- 대조 `fr0`(`RAG_FOLLOWUP_REUSE=0`) · 처리 `fr1`(`=1`). 실행 `.cron/run_fr.sh`, 채점 `.cron/fr/score.py`.

## 3. 판정 (측정 전 고정)

직전 답을 가리키는 이어지는 질문 7개 = F01 · F03 · F04 · F05 · F07 · F08 · F10 ("가리킴 7").

| 지표 | 기준 |
|---|---|
| **주:** 가리킴 7 중 **직전 답 논문 인용** — 답이 직전 답 본론에 인용된 논문을 1편 이상 인용(서수 F01 · F05 는 그 번째 항목 논문을 인용) | 처리 > 대조, McNemar 단측 방향 + 처리 ≥ 5/7 |
| 보호: 가리킴 7 의 경로가 B | 처리 7/7 |
| 보호: 독립 74 검색 ok · 수치 N 정답 · 비교 C 두 편 인용 · 목록 T 정답 인용 ≥ 3 | 각각 처리가 대조보다 2 이상 낮지 않음 |
| 보호: 새 논문 이어지는 질문 3개(F02 · F06 · F09) 경로 · 검색 | 대조와 같은 처리(코드상 바뀌지 않음 — 확인만) |
| 보호: 응답 시간 중앙(독립 74) | ≤ 대조 + 5s |
| 보고: 가리킴 7 응답 시간(검색을 건너뛰므로 줄어야 함), 7개 답을 직접 읽은 메모(직전 논문을 제대로 설명하는지), 독립 74 중 재사용이 걸린 수(0 이어야 함) | |

7개로는 7 : 0 이어야 p 0.016 이다. 유의하지 않으면 그대로 적고 채택은 방향 + 보호 + 직접 읽기로 사용자와 정한다.

채택이면 **사용자 승인 후** 운영 `.env` `RAG_FOLLOWUP_REUSE=1` + 봇 재시작.

예상: 대조 0~1/7 → 처리 5~7/7. 독립 74 는 같은 수준(재사용이 걸리지 않음).

알려진 한계: 컨텍스트는 메모리에만 둔다(봇 재시작 뒤 첫 이어 묻기는 지금처럼). 목록 답의 블록은 초록 500자로 줄어 있어 "두 번째 항목 실험" 같은 질문엔 재료가 얇다.
