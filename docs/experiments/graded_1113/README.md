# graded_1113 — 거르기 · 판정을 3단계로 (judge_filter_diag_1113 §3 의 2단계)

## 0. 진단 바로잡기

judge_filter_diag_1113 §1 의 "거르기 입력은 검색어 한 줄" 은 **topic_filter_1104 재생**(여러 주제 나눠 검색 실험, 접음)의 입력이다. 운영 거르기(`agent_nodes` → `filter_relevant(user_request, …)`)에는 원 질문이 들어간다. 그래서 이 라운드의 대조는 같은 풀에 **원 질문**을 넣은 운영 프롬프트(Q0)로 다시 잰다. 판정 쪽 운영 꼬리(`SHARED_TAIL`)는 "사용자는 특정한 연구 하나를 찾는다" 고 못박아, 추천형 질문에서 지시를 그대로 따르는 큰 모델이 '없음' 을 낸 것이다(진단 §2 의 27b 104) — v13 맞춤이라기보다 꼬리가 추천형 질문에 틀린 지시다.

## 1. 바꾸는 것 (코드 기본 꺼짐, 운영 영향 없음)

- **거르기 v2** `relevance_filter.PROMPT_V2` · `filter_graded()`: 원 질문 + 문서마다 `핵심 / 관련 / 무관` 한 줄. 남기는 집합은 두 변형 K(핵심만) · KR(핵심+관련). 아무것도 안 남으면 운영처럼 그대로 둔다.
- **판정 v2** `presence_judge.SHARED_TAIL_V2` · `parse_pick_v2()`: 질문이 (가) 특정 연구 묘사인지 (나) 주제 추천인지 먼저 가리고 `있음 문서 N / 부분 문서 N / 없음`. 운영 연결(부분일 때 안내 문구)은 이 라운드를 통과한 뒤 따로.
