# 잘린 초록 청크에도 초록 전체 붙이기 — 답 재생성 평가 (사전 등록, 2026-10-21)

> 측정 **전에** 쓴다. 출발점: conclusion_rewrite_1021 §8 — 청킹 질문 답에서 2601.14123 블록이 559자뿐이라 초록 끝의 결과("overlap provides no measurable benefit … sentence chunking is the most cost-effective")가 답변 모델에 가지 않았다.

## 0. 진단

`core/rag/agent_chroma_rag.py` `_with_abstract`: 발췌에 **초록 앞 80자**가 들어 있으면 "초록이 이미 있다"고 보고 `[초록]` 을 붙이지 않는다. 그 발췌가 PDF 의 Abstract 청크인데 **초록 중간에서 잘린** 경우 결과 문장(초록 끝)이 빠진다. 저장된 s18 컨텍스트에서 블록 436 중 `[초록]` 없는 블록 29개 — **29개 전부** 초록 끝 80자가 블록에 없다(6.7%).

## 1. 바꾸는 것 — `RAG_ABSTRACT_TAIL_CHECK` (기본 `0`)

`1` 이면 "이미 있다" 판정을 **붙일 초록(`abstract[:RAG_ABSTRACT_CHARS]`)의 끝 80자**로 한다. 끝이 발췌에 없으면 `[초록] …` 을 앞에 붙인다(초록 앞부분이 발췌와 겹쳐도 붙인다). 테스트 `tests/unit/test_abstract_chars.py`.

## 2. 방법 — 답 재생성 (맥미니)

real40 + real2 74문항(문항마다 기록 지움, `s18` 과 같은 방식) `--answer --save-context`, 운영 `.env` 그대로(결론 다시 쓰기 v2 포함). 대조 `at0`(`=0`) · 처리 `at1`(`=1`), 같은 날 연속. 실행 `.cron/run_at.sh`, 채점 `docs/experiments/abstract_tail_1021/score.py`.

**왜 효과 지표가 안 움직였나(문항별로 본 것)**
- **지표가 못 잡는 경우가 많다:** 누락 논문 중 초록 뒤 절반에 숫자가 없는 것이 16문항 중 7문항(T04 · R03 · R04 · C02 · C11 · T03 · T06) — 결과가 질적 문장("no measurable benefit" 류)이라 숫자 지표로는 0 이다.
- **목록(T) 질문은 고쳐도 끝이 다시 잘린다:** 목록 모드가 블록을 초록 앞 500자로 줄인다(`_compact_list_blocks`, list_mode_1016). real40 T01 은 처리 쪽에서도 끝 숫자가 컨텍스트에 없다.
- **끝 숫자가 들어온 비중심 논문:** N15 · C08 · R05 는 처리 쪽 컨텍스트에 끝 숫자가 들어왔지만 그 논문을 답이 인용하지 않았다(질문의 중심 논문이 아님).
- 반면 누락됐던 논문을 **인용한 수는 14 → 23** 으로 늘었다 — 초록이 붙으니 모델이 그 논문을 쓴다(사전 등록 밖이라 판정에는 넣지 않음).

**읽은 것** — 버그는 기계적으로 고쳐지고(31 → 0) 해는 없다(보호 통과, 시간 같음). 하지만 사전 등록한 효과 지표로는 이득이 보이지 않는다. 목록 질문은 500자 압축이 같은 문제를 다시 만든다 — 다음 후보: 목록 모드 압축을 "초록 앞 500자" 대신 결론 v2 의 결과 문장 추출(`extract_findings`)로.
