# 복제 검증 — 계획 제약 문항에서 v10 이 정말 나은가 (사전 등록)

- 개설일: 2026-09-29
- **학습 없음.** 모델을 새로 만들지 않는다. 문항을 늘려 기존 관측을 다시 시험하는 라운드다.
- 선행: [`../baseline_0929/`](../baseline_0929/) — 3모델 같은 세션 측정

**이 문서는 문항을 만들기 전에 쓴다.** 가설·판정 기준을 먼저 고정하지 않으면, 신호가 잘 나오도록 문항을 고르고 그 문항으로 신호를 확인하는 순환에 빠진다. 커밋 시각이 문항 파일의 커밋 시각보다 앞선다는 것이 그 증거다.

## 1. 무엇을 봤나

[`../baseline_0929/`](../baseline_0929/) 에서 v10 이 계획 제약 문항 3~4개를 통과하고 base·v9 은 실패했다. **세 비교에서 방향이 한 번도 뒤집히지 않았다.**

| 비교 | v10 쪽 불일치 : 반대 | 계획 실패율 |
|---|---|---|
| base : v10 (09-29 새벽) | **4 : 0** | 47.9% → 27.1% |
| base : v10 (09-29 오전) | **3 : 0** | 50.0% → 31.2% |
| v9 : v10 (09-29 오전) | **3 : 0** | 47.9% → 31.2% |

그런데 **유의하지 않다** (각 p=0.125~0.250). [`../protocol.md`](../protocol.md) §2.3 은 불일치 쌍 6개가 한쪽으로 완전히 쏠려야 p<0.05 라고 적어두었는데, 계획 제약 문항이 8개뿐이라 불일치가 3~4쌍에서 멈춘다. **신호가 없어서가 아니라 문항이 모자라서** 유의하지 않다.

두 밤의 결과를 합치면 될 것 같지만 안 된다 — **같은 문항을 두 번 잰 것**이라 독립 표본이 아니다. 불일치를 만든 문항이 양쪽 밤에 거의 같다 (`planner_10`·`12`·`16`).

## 2. 이 라운드의 위험 — 그리고 막는 장치

관측을 보고 나서 그 관측이 잘 나오도록 문항을 추가하면, **같은 데이터로 가설을 만들고 검증하는 것**이 된다. 세 가지로 막는다.

1. **판정 기준을 문항보다 먼저 고정한다** (이 문서, §4).
2. **문항을 고르지 않는다 (무선택).** 쓴 16개를 **전부** 채택한다. 파일럿으로 추리는 단계가 없다.

   > **[2026-09-30 수정]** 원래 이 항목은 "base 파일럿으로 base 가 실패하는 16개를 고른다" 였고, "base 실패 여부는 가설과 무관하므로 편향이 아니다" 라고 적었다. **H2 에 대해서는 틀린 말이다.** base 가 실패하는 문항만 남기면 `base : v10` 의 불일치는 구조적으로 "base 만 실패" 쪽으로만 생길 수 있다 — v10 이 base 보다 나아 보이도록 문항을 깔아두는 셈이다. 파일럿 1회로 고른 실패에는 평균 회귀도 섞인다. H1(v9:v10)은 둘 다 선택에 쓰이지 않아 영향이 없지만, 한 문서 안에서 기준이 갈리는 것보다 선택 단계를 없애는 편이 낫다. **결과를 보기 전에 고친다.**
3. **판정은 새 문항에서만 한다.** 기존 계획 제약 8문항(`planner_09`~`16`)은 가설을 만든 데이터이므로 검증에 쓸 수 없다. 결과 표에 참고로 병기만 한다.

**2026-09-28 의 실수를 되풀이하지 않기 위한 조건**([`../protocol.md`](../protocol.md) §6): 문항이 무력한지 판단할 때는 **최소 두 모델**의 결과를 본다. 다만 위 2번 때문에 문항 확정 전에는 base 만 본다 — 그래서 이 라운드에서는 "양쪽 다 실패라 문항이 무력했다" 가 **사후에 드러날 수 있고**, 그 경우는 §4 의 '판정 불가' 로 처리한다.

## 3. 가설

- **H1 (주): lr 을 낮춘 v10 은 길이 제약을 v9 보다 잘 지킨다.** 데이터·스텝이 같고 lr 만 다르므로(2e-4 → 5e-5), 차이가 나면 그 축에 귀속된다.
- **H2: v10 은 base 보다도 잘 지킨다.** H1 이 맞아도 H2 는 별개다 — 학습이 base 를 **넘는지**는 일곱 라운드 동안 한 번도 확인되지 않았다.
- **H3 (반대 가능성): 관측은 세 문항의 우연이었다.** 새 문항에서 방향이 갈리면 이쪽이다.

## 4. 판정 (사전 선언 — 결과를 본 뒤 바꾸지 않는다)

**새 계획 제약 문항 16개**에서만 판정한다. base·v9·v10 을 [`../../../scripts/eval_trio_round.sh`](../../../scripts/eval_trio_round.sh) 로 **같은 세션에서** 재고 짝지어 비교한다.

- **통과 (H1 확인)**: 새 문항에서 **v9 : v10 McNemar p < 0.05** 이고 쏠림이 **v10 쪽**이다.
  - 이때 base : v10 도 같은 방향이면 H2 도 확인된 것으로 본다. 반대면 H1 만 취한다.
- **실패 (H3)**: v9 : v10 의 p ≥ 0.05. **v10 우위 주장을 철회**하고, [`../baseline_0929/`](../baseline_0929/) 의 관측을 "세 문항의 우연" 으로 기록한다.
- **판정 불가**: 새 문항에서 **불일치 쌍이 6개 미만**. 문항이 양쪽 다 실패(또는 양쪽 다 통과) 쪽으로 쏠려 검정력이 없다는 뜻이다. 이 경우 **결과를 해석하지 않고** 문항 난도를 다시 잡을지 별도로 정한다 — 이 라운드의 숫자를 근거로 쓰지 않는다.

문항 수 16개의 근거: 기존 8문항에서 불일치가 3~4쌍 나왔으므로(약 40%), 6쌍을 기대하려면 두 배가 필요하다.

## 5. 문항 제작 규칙

- **16개를 쓰고 전부 채택한다.** 난도에 따라 고르거나 버리지 않는다 (§2-2).
- 줄 길이 상한은 **30~42자에 고르게 펼친다.** 기존 8문항이 28~36자에 몰려 절반이 양쪽 다 실패였으므로, 조금 넓혀 양끝(너무 쉬움·너무 어려움)이 섞이게 둔다. 이 범위는 **기존 문항의 결과**에서 왔고 새 문항의 성적과는 무관하다.
- 슬롯은 **계획만**. 잡담·RAG·코딩은 건드리지 않는다.
- 제약은 **`max_chars_per_line`** 을 축으로 한다 — 기존 8문항에서 변별력이 나온 것이 이것이다. 줄 수 제약은 쓰지 않는다 (시스템 프롬프트가 3단계를 요구해 충돌한다).
- 판정기가 쓰는 `_parse_planner_llm_lines` 는 `1 단계: ` 접두어(약 7자)를 **남긴다.** 상한을 정할 때 이 여유를 감안한다.
- 참조답안으로 **풀림 가능성을 증명**한다 ([`../../../tests/fixtures/constraint_reference_answers.json`](../../../tests/fixtures/constraint_reference_answers.json), 테스트가 지킨다).
- 기존 문항·학습 데이터와 유사도 **< 0.72** ([`../protocol.md`](../protocol.md) §2.1).
- 문항 집합이 바뀌므로 §2.1 의 sha256 과 두 스크립트의 `EXPECT_SHA` 를 같이 갱신한다.
