# 2차 — 통과

커밋 `601bca5`, 102문항 sha256 `4573072530b6`, 반복 3회, 세 모델 918시행. [`scripts/eval_trio_round.sh`](../../../scripts/eval_trio_round.sh) 로 **같은 세션에서** 쟀다.

## 판정 ([§4](README.md#4-판정-사전-선언--결과를-본-뒤-바꾸지-않는다) 그대로 대입)

```
판정 대상 — 새 계획 문항 16개 (planner_33~48), v9 vs v10
  둘 다 실패 0 · v9만 10 · v10만 2 · 둘 다 통과 4
  → 불일치 12쌍, McNemar 양측 p = 0.039
```

**통과 (H1 확인).** 불일치 12쌍(기준 6 이상)이고 p=0.039 < 0.05, 쏠림이 v10 쪽이다.

| 비교 (새 16문항) | 앞만 실패 : 뒤만 실패 | 불일치 | p |
|---|---|---|---|
| **v9 : v10** | **10 : 2** | 12 | **0.039** |
| base : v10 | 9 : 2 | 11 | 0.065 |
| base : v9 | 3 : 4 | 7 | 1.000 |

**H2 는 방향으로만 확인된다.** §4 는 "base : v10 도 **같은 방향**이면 H2 도 확인된 것으로 본다" 고 적었고 9:2 로 같은 방향이다. 다만 p=0.065 로 유의 문턱은 넘지 못했다 — 사전 선언이 방향 기준이었으므로 그대로 취하되, **"base 보다 낫다" 는 유의하게 보이지 않았다**는 사실을 같이 적는다.

**`base : v9` 가 3:4, p=1.000 이라는 점이 중요하다.** 이 효과는 "파인튜닝이 base 를 이긴다" 가 아니다. v9 은 base 와 구분되지 않는다. **lr 2e-4 → 5e-5 라는 그 축에서만** 차이가 난다.

## 슬롯별 (102문항, 같은 세션)

| 슬롯 | base | v9 | v10 |
|---|---|---|---|
| 잡담 (n=48) | 27.1% | 27.1% | **18.8%** |
| 계획 (n=144) | 62.5% | 68.1% | **44.4%** |
| RAG (n=24) | 12.5% | **0%** | **0%** |
| 코딩 (n=90) | 23.3% | **18.9%** | 30.0% |
| **전체 (n=306)** | 41.5% | 41.8% | **32.7%** |

계획 슬롯이 **68.1% → 44.4%** 로 23.7%p 벌어졌다. 반대로 **코딩은 v10 이 가장 나쁘다** (30.0% vs v9 18.9%) — 짝지은 비교에서도 v10 만 실패한 코딩 문항이 5개다. lr 인하가 모든 것을 좋게 만들지는 않는다.

## 1차가 없었으면 이 결과도 없었다

1차에서 건진 것은 **상한 44~50자라는 실측 눈금** 하나였다. 그것이 2차를 만들었다.

| | 1차 (30~42자) | 2차 (44~50자) |
|---|---|---|
| 둘 다 실패 | 14 | **0** |
| 둘 다 통과 | 0 | 4 |
| 불일치 | 2 | **12** |

**1차는 신호가 없어서가 아니라 잴 수 없어서 실패했다.** §4 에 "불일치 6쌍 미만이면 해석하지 않는다" 를 미리 적어두지 않았다면 p=1.000 을 보고 "H3 확인 — v10 우위는 우연이었다" 로 닫았을 것이고, 그것이 **정반대의 결론**이었다.

그리고 2차 문항은 **은퇴 모델(v5·v6)로 파일럿**해 난도를 맞췄다 (둘 다 통과 3 · 둘 다 실패 8 · 갈림 5). 비교 대상을 건드리지 않으면서 난도만 보정하는 방법이고, 1차에서 "선택 편향을 피한다" 며 파일럿 자체를 생략한 것이 실패의 원인이었다.

## 믿을 수 있는 이유와, 아직 못 믿을 이유

**설계상 지킨 것**

- 판정 기준을 **문항보다 먼저** 고정했다 (`0bde0bc` 11:49 → 선택 편향 수정 `1008345` → 문항 `601bca5`). 커밋 순서가 기록이다.
- 판정은 **새 16문항에서만** 했다. 가설을 만든 `planner_09`~`16` 은 참고로만 병기한다.
- 세 모델을 **같은 세션에서** 쟀다. 밤 사이 기준선 이동이 끼어들 수 없다.
- 문항을 결과로 고르지 않았다. 쓴 16개를 전부 채택했고, 난도 파일럿은 비교 대상이 아닌 은퇴 모델로 했다.

**그래도 남는 한계**

1. **단일 세션이다.** [`../baseline_0929/`](../baseline_0929/) 에서 7:2(p=0.180)가 다음 날 6:4(p=0.754)로 주저앉은 적이 있다. **다른 밤에 한 번 더 재기 전에는 확정으로 쓰지 않는다.**
2. **상한 구간(44~50자)은 1차의 base·v9·v10 분포에서 골랐다.** 검정력을 맞추려는 것이었고 문항을 결과로 고른 것은 아니지만, 그 눈금이 v10 에 유리한 쪽으로 잡혔을 가능성을 배제할 수 없다. 타당성은 **새 문항이 독립 표본**이라는 데서 오지 눈금의 중립성에서 오지 않는다.
3. **한 가지 능력을 16번 물었다.** 전부 `max_chars_per_line` 이다. 문장은 서로 다르지만(유사도 최대 0.698) 재는 것은 "분량을 미리 계획해 줄 길이를 지키는 능력" 하나다. **"v10 이 지시를 더 잘 따른다" 로 일반화할 수 없다.**
4. **p=0.039 는 문턱 바로 아래다.** 불일치 12쌍에서 한 문항만 반대로 뒤집혀도(9:3) p=0.146 이 된다.

# 1차 — 판정 불가 (2026-09-30)

측정 2026-09-30 19:44 → 22:39 (174분). [`scripts/eval_trio_round.sh`](../../../scripts/eval_trio_round.sh) `yunsur_v9 yunsur_v10 v9v10_86`, 커밋 `922d29d`, 86문항 sha256 `7c74b3549057`, 반복 3회, 세 모델 774시행. 원본 [`04_eval/`](04_eval/).

## 판정

사전 선언한 [§4](README.md#4-판정-사전-선언--결과를-본-뒤-바꾸지-않는다) 의 세 갈래 중 **판정 불가**다.

```
판정 대상 — 새 계획 문항 16개 (planner_17~32), v9 vs v10
  둘 다 실패 14 · v9만 1 · v10만 1 · 둘 다 통과 0
  → 불일치 2쌍 (기준: 6쌍 미만이면 판정 불가)
```

**16문항 중 14개를 세 모델이 전부 실패했고, 셋 다 통과한 문항은 0개다.** 모델을 가를 자리가 없었다.

p=1.000 이 나왔지만 이것은 **"신호가 없다" 가 아니라 "못 쟀다"** 다. §4 에 이 구분을 미리 적어두지 않았다면 "p=1.000 이므로 H3 확인, v10 우위는 우연이었다" 로 결론 낼 뻔했고, 그것은 틀린 결론이었을 것이다.

| 비교 (새 16문항) | 앞만 실패 : 뒤만 실패 | 불일치 | p |
|---|---|---|---|
| v9 : v10 | 1 : 1 | 2 | 1.000 |
| base : v10 | 1 : 2 | 3 | 1.000 |
| base : v9 | 0 : 1 | 1 | 1.000 |

## 왜 — 상한이 통째로 빗나갔다

이번 라운드 774시행에서 **각 응답의 가장 긴 단계 줄** 길이를 실측했다. 그것이 곧 "그 응답이 통과할 수 있는 최소 상한" 이다.

| 모델 | 10% | 25% | 중앙 | 75% | 90% |
|---|---|---|---|---|---|
| base | 35 | 40 | **47** | 59 | 70 |
| v9 | 37 | 43 | **49** | 56 | 67 |
| v10 | 33 | 37 | **41** | 46 | 57 |

**중앙값이 41~49자인데 상한을 30~42자에 걸었다.** 거의 모든 응답이 자동으로 실패하는 구간이다. 상한별 통과율로 보면 더 분명하다:

| 상한 L | base | v9 | v10 |
|---|---|---|---|
| 34 | 9% | 7% | 19% |
| 38 | 19% | 12% | 31% |
| 42 | 32% | 22% | 57% |
| **44** | **43%** | 32% | **65%** |
| **46** | **49%** | 43% | **76%** |
| **48** | **57%** | 49% | **79%** |
| **50** | **62%** | 53% | **83%** |
| 56 | 74% | 76% | 90% |

**변별 구간은 44~50자다.** base 통과율이 43~62% 로 중간에 걸치고, base 대비 v10 의 격차도 거기서 +21~27%p 로 가장 크다. 내가 쓴 30~42자는 그 아래 끝이었다.

**선택 편향을 피하면서 난도 보정은 유지할 수 있었다.** 둘은 분리 가능한 문제였다 — 비교 대상이 아닌 **은퇴 모델(v5·v6)로 파일럿**하면 v9·v10 을 건드리지 않고 구간만 잡을 수 있었고, 그것은 사전 등록 당시 대안으로 올렸다가 버린 선택지였다. "무선택" 을 고르면서 난도 보정까지 같이 버린 것이 이번 실패의 원인이다.

## 참고 — 기존 8문항에서는 신호가 또 재현됐다

```
기존 planner_09~16 (가설을 만든 문항), v9 vs v10
  v9만 실패 3 (planner_10·12·16) · v10만 실패 0 → p=0.250
```

**네 번째 측정에서도 방향이 뒤집히지 않았고 같은 세 문항이다.** 다만 이것은 가설을 만든 데이터라 검증에 쓸 수 없고, 그 문항들은 서로 0.68~0.71 로 닮아 독립 증거도 아니다 ([`../protocol.md`](../protocol.md) §2.1).

전체 86문항에서는 v9 : v10 이 **9 : 3, p=0.146** 으로 v10 쪽이지만 유의하지 않다. base : v10 은 10 : 5, p=0.302.

## 다음 — 상한만 바꿔 다시 한다

가설과 판정 기준은 [`README.md`](README.md) §3·§4 **그대로 둔다.** 바꾸는 것은 문항의 상한 하나뿐이다.

1. 계획 제약 문항 16개를 **상한 44~50자**로 다시 쓴다 (`planner_33`~`48`). 기존 32개는 그대로 둔다.
2. 상한 구간은 **base 의 통과율**(43~62%)로 골랐다 — 이번 라운드의 실측 분포에서다. 개별 문항을 결과로 고르는 선택 편향(§2-2)과는 다르다: 어떤 문항을 넣고 뺄지가 아니라 **난도 눈금만** 정한 것이고, 쓴 16개는 결과와 무관하게 전부 채택한다.
   - 다만 이 눈금이 v9·v10 의 분포도 본 데이터에서 나왔다는 점은 기록해 둔다. 검증의 타당성은 **새 문항이 독립 표본**이라는 데서 오지 눈금의 중립성에서 오지 않는다.
3. 문항 집합이 또 바뀌므로 sha256 · `EXPECT_SHA` × 2 · §2.1 · §4 를 갱신하고 세 모델을 다시 잰다 (약 3시간 40분).
