# 05. 결론 — 판정 불가. 문항이 너무 어려워 못 쟀다

측정 2026-09-30 19:44 → 22:39 (174분). [`scripts/eval_trio_round.sh`](../../../scripts/eval_trio_round.sh) `yunsur_v9 yunsur_v10 v9v10_86`, 커밋 `922d29d`, 86문항 sha256 `7c74b3549057`, 반복 3회, 세 모델 774시행. 원본 [`04_eval/`](04_eval/).

## 판정

사전 선언한 [§4](README.md#4-판정-사전-선언--결과를-본-뒤-바꾸지-않는다) 의 세 갈래 중 **판정 불가**다.

```
판정 대상 — 새 계획 문항 16개 (planner_17~32), v9 vs v10
  둘 다 실패 14 · v9만 1 · v10만 1 · 둘 다 통과 0
  → 불일치 2쌍 (기준: 6쌍 미만이면 판정 불가)
```

**16문항 중 14개를 세 모델이 전부 실패했고, 셋 다 통과한 문항은 0개다.** 모델을 가를 자리가 없었다.

p=1.000 이 나왔지만 이것은 **"신호가 없다" 가 아니라 "못 쟀다"** 다. §4 에 이 구분을 미리 적어두지 않았다면 "p=1.000 이므로 H3 확인, v10 우위는 우연이었다" 로 결론 낼 뻔했고, 그것은 틀린 결론이었을 것이다.

| 비교 (새 16문항) | 앞만 실패 : 뒤만 실패 | 불일치 | p |
|---|---|---|---|
| v9 : v10 | 1 : 1 | 2 | 1.000 |
| base : v10 | 1 : 2 | 3 | 1.000 |
| base : v9 | 0 : 1 | 1 | 1.000 |

## 왜 — 상한이 통째로 빗나갔다

이번 라운드 774시행에서 **각 응답의 가장 긴 단계 줄** 길이를 실측했다. 그것이 곧 "그 응답이 통과할 수 있는 최소 상한" 이다.

| 모델 | 10% | 25% | 중앙 | 75% | 90% |
|---|---|---|---|---|---|
| base | 35 | 40 | **47** | 59 | 70 |
| v9 | 37 | 43 | **49** | 56 | 67 |
| v10 | 33 | 37 | **41** | 46 | 57 |

**중앙값이 41~49자인데 상한을 30~42자에 걸었다.** 거의 모든 응답이 자동으로 실패하는 구간이다. 상한별 통과율로 보면 더 분명하다:

| 상한 L | base | v9 | v10 |
|---|---|---|---|
| 34 | 9% | 7% | 19% |
| 38 | 19% | 12% | 31% |
| 42 | 32% | 22% | 57% |
| **44** | **43%** | 32% | **65%** |
| **46** | **49%** | 43% | **76%** |
| **48** | **57%** | 49% | **79%** |
| **50** | **62%** | 53% | **83%** |
| 56 | 74% | 76% | 90% |

**변별 구간은 44~50자다.** base 통과율이 43~62% 로 중간에 걸치고, base 대비 v10 의 격차도 거기서 +21~27%p 로 가장 크다. 내가 쓴 30~42자는 그 아래 끝이었다.

## 참고 — 기존 8문항에서는 신호가 또 재현됐다

```
기존 planner_09~16 (가설을 만든 문항), v9 vs v10
  v9만 실패 3 (planner_10·12·16) · v10만 실패 0 → p=0.250
```

**네 번째 측정에서도 방향이 뒤집히지 않았고 같은 세 문항이다.** 다만 이것은 가설을 만든 데이터라 검증에 쓸 수 없고, 그 문항들은 서로 0.68~0.71 로 닮아 독립 증거도 아니다 ([`../protocol.md`](../protocol.md) §2.1).

전체 86문항에서는 v9 : v10 이 **9 : 3, p=0.146** 으로 v10 쪽이지만 유의하지 않다. base : v10 은 10 : 5, p=0.302.

## 다음 — 상한만 바꿔 다시 한다

가설과 판정 기준은 [`README.md`](README.md) §3·§4 **그대로 둔다.** 바꾸는 것은 문항의 상한 하나뿐이다.

1. 계획 제약 문항 16개를 **상한 44~50자**로 다시 쓴다 (`planner_33`~`48`). 기존 32개는 그대로 둔다.
2. 상한 구간은 **base 의 통과율**(43~62%)로 골랐다 — 이번 라운드의 실측 분포에서다. 개별 문항을 결과로 고르는 선택 편향(§2-2)과는 다르다: 어떤 문항을 넣고 뺄지가 아니라 **난도 눈금만** 정한 것이고, 쓴 16개는 결과와 무관하게 전부 채택한다.
   - 다만 이 눈금이 v9·v10 의 분포도 본 데이터에서 나왔다는 점은 기록해 둔다. 검증의 타당성은 **새 문항이 독립 표본**이라는 데서 오지 눈금의 중립성에서 오지 않는다.
3. 문항 집합이 또 바뀌므로 sha256 · `EXPECT_SHA` × 2 · §2.1 · §4 를 갱신하고 세 모델을 다시 잰다 (약 3시간 40분).
