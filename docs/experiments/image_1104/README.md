# image_1104: 논문 그림 설명 1단계 (속도 · 설명 품질 dev)

> 측정 **전에** 쓴다. dev 전용이고 답 효과를 판정하지 않는다. 사용자 결정(11-04): 지금 맥미니로 1단계를 시작한다. 답이 나아지는지는 2단계(새 맥미니, 별도 사전 등록)에서 본다.

## 1. 왜

수집은 `pymupdf4llm` 으로 글만 뽑고, 그림은 `picture [W x H] intentionally omitted` 자리표시로 바뀌며, PDF 는 남기지 않는다. 큐 2,943편 기준 자리표시 54,705 중 높이 40 미만(수식 · 줄 조각)이 61%, 가로세로 100 이상(그림 크기)이 28% 이고 논문당 평균 5.2장이다. 그림을 글 설명으로 바꿔 청크에 더하려면 먼저 두 가지를 알아야 한다.

1. 9B 비전이 장당 얼마나 걸리는가.
2. 설명이 맞는가, 그리고 캡션 · 본문에 없는 정보를 더하는가.

## 2. 대상

[`labels_hu.tsv`](../topic_split2_1104/labels_hu.tsv) 에서 주제 라벨이 달린 논문(HU40, 이미 dev) 중 수집 본문에 그림 크기 자리표시가 1개 이상인 논문을 고른다. seed 1104 로 섞어 앞 20편을 쓴다. 목록은 [`papers.jsonl`](papers.jsonl) 이고, 측정 전에 커밋한다.

PDF 는 `ArxivFetcher.download_pdf` 로 3–5초 간격으로 받아 `tmp/image_1104/` 에 둔다. PDF 와 그림 파일은 커밋하지 않는다.

## 3. 처리 ([`run.py`](run.py))

- **그림 추출:** `parse_document(write_images=True, image_dpi=150)`. `boxclass == "picture"` 이고 가로세로가 모두 100pt 이상인 것만 쓴다. `formula` 는 뺀다.
- **문맥:** 같은 쪽에서 가장 가까운 캡션과 앞뒤 글을 각 500자까지 넣는다.
- **설명:** `qwen3.5:9b`, `/api/chat`, `think=false`, `temperature=0.2`, `top_p=0.8`, `repeat_penalty=1.18`, `num_predict=400`, `num_ctx` 는 기본값(4096). 지시문은 `run.py` 의 `PROMPT` 다.
- 운영 Chroma · `.env` 는 쓰지 않는다. 도는 동안 봇 질문이 오면 Ollama 가 모델을 바꿔 답이 느려질 수 있다.

## 4. 재는 것

**전체:** PDF 크기 · 쪽수 · 그림 수 · 파싱 시간, 장당 시간(모델 올리는 시간 제외 중앙값 · 포함 중앙값), 입력 · 출력 토큰.

**무작위 30장(seed 1104)을 실제 그림과 대조해 Claude 가 분류한다:**

| 칸 | 값 |
|---|---|
| 정확 | O 전부 맞음 · △ 사소한 오류(읽기 · 라벨 하나) · X 사실 오류(구조 · 경향 · 수치를 틀리게 말함) |

새 정보를 가릴 때는 설명 단어 중 그 논문 본문에 없는 단어 목록을 함께 본다.

## 5. 기준 (30장, 측정 전 고정)

- **G1 설명 정확:** X ≤ 6.
- **G2 새 정보:** Y ≥ 9.
- 시간은 보고만 한다. 이 맥미니 속도는 새 맥미니와 다르다.

**결정 규칙**
- 둘 다 통과: 2단계를 설계한다.
- G1 미달: 9B 설명은 코퍼스에 넣지 않는다. 새 맥미니에서 큰 비전 모델로 같은 30장을 다시 본다.
- G2 미달: 큰 비전 모델로 같은 30장을 다시 보고, 그래도 미달이면 접는다.

**한계:** 30장은 작아 경향만 본다. 분류는 한 명(Claude)이 한다. 대조 조건이 없어 가릴 것은 없다. 표본은 그림이 있는 논문만이다.
