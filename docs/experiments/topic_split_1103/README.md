## 1. 바꾸는 것

`RAG_TOPIC_SPLIT=1` (기본 `0`) — `agent_nodes.direct_answer_node` B 경로:
1. **1단계 후보(결정적, `topic_split_candidate`)**: 번호 항목이 1 · 2 순서로 있거나(`1.` · `(1)` · `1)` · `①`, 소수점 `1.0` 은 아님) 한 줄에 쉼표가 둘 이상. dev 967문항 중 **16 (1.7%)**. 아니면 LLM 호출도 없다.
2. **2단계(LLM, `_extract_subtopics`)**: 검색어 추출과 같은 보조 모델(`get_rag_query_rewrite_llm`, temperature 0 · seed 0, 출력 상한 320)이 하위 주제마다 영어 키워드 한 줄(최대 4줄)을 쓴다. 한글이 든 줄은 기존 영어 검색어 추출(`_extract_english_rag_query_base`)로 바꾸고, 줄마다 앞 10단어, 영어 낱말 2개 이상인 줄만. 질문에 RAG(검색 증강)가 있으면 RAG 없는 줄에 ` RAG` 를 붙인다. **2줄 이상이면 나눈다**, 아니면 기존 그대로.
3. 나뉘면 **목록 모드**(`RAG_LIST_MODE` 경로 — 원래 검색 10편, 상위 10 자르기, 압축 블록, 번호 칸 템플릿, 외부 검색)로 답하고, 주제마다 `rag.search(주제, top_k=15)` → 주제별 상위 3블록을 **번갈아**(1주제 1위, 2주제 1위, …, 1주제 2위 …) 앞에, 원래 검색 블록을 뒤에, 같은 논문은 한 번만(`_interleave_topic_blocks`). 상위 10 자르기가 주제를 고루 남긴다.
4. 나뉘면 비교 분리 검색(`RAG_COMPARE_SPLIT`)과 정답 유무 판정은 하지 않는다(목록 질문과 같이). 한 편 집중(`prefer_single_hit`) · 이어지는 질문 재사용이면 나누지 않는다.
5. 평가 행 `trace` 의 `search` 단계에 `topics` 를 남긴다(나뉠 때만).

대가: 나뉘는 질문에서만 LLM 1회(+한글 줄마다 1회) + 검색 2~4회. 그 밖의 질문은 코드 경로가 같다.

평가기 변경: `scripts/eval_e2e_ko.py` 가 질문 TSV 의 `\n` 을 줄바꿈으로 읽는다(여러 줄 실사용 질문 그대로). 기존 TSV 에는 `\n` 글자가 없다(확인). `get_rag_query_rewrite_llm(num_predict=160)` 에 출력 상한 인자를 더했다(기본값 그대로).

## 3. 방법

- **held-out 30문항** [`heldout_topics.tsv`](heldout_topics.tsv) (sha256 `69b695079e61`) — 측정 전에 새로 썼다. 꼴: 번호 `1.` 10 · `(1)`/`①` 4 · 쉼표 목록 8 · 따옴표 키워드 3 · 키워드 줄 + 번호 지시문 3 · "각각" 2(HT30 은 쉼표 · 번호가 없어 1단계 후보가 아닐 것 — 실사용에 있는 꼴이라 넣었다). 하위 주제 2~4개, 모두 93개([`heldout_topics_gold.jsonl`](heldout_topics_gold.jsonl) `topics`). 기존 질문 1,874개와 SequenceMatcher 최대 0.482, 서로 최대 0.435 (< 0.72).
- 검색만(`--save-context`, 답 생성 없음): `run.sh heldout_topics.tsv heldout_topics_gold.jsonl ht` → 대조 `ts0_ht`(`RAG_TOPIC_SPLIT=0`, 운영과 같음) · 처리 `ts1_ht`. 컨텍스트 뒤 단계(외부 검색 · 결론 다시 쓰기)는 두 조건 모두 끈다. 같은 DB, Chroma 쓰기 없는 시간(01:00 수집 피함).
- **라벨**(`score.py packet`): 문항마다 두 조건 최종 컨텍스트(답 LLM 이 받는 문서) 합집합을 섞어(seed 1103) 조건을 가리고, 문서마다 **주로 다루는 하위 주제 번호**(여럿 가능) 또는 `-` 를 단다(`labels_ht.tsv`). 기준: 그 주제의 방법 · 문제가 제목 · 초록에서 논문의 중심 주제이거나 주된 기여다. 언급만 하거나 한 단계로만 쓰면 아니다. 라벨을 다 단 뒤에 조건을 연다(`score.py score`).

## 4. 판정

| 지표 | 기준 |
|---|---|
| **주:** 문항별 **덮은 하위 주제 수** (최종 컨텍스트에 그 주제를 주로 다루는 문서가 1편 이상) | 처리가 더 많은 문항 > 더 적은 문항, **부호 검정 양측 p < 0.05** |
| 보호 1: 주제 밖 문서 비율(라벨 `-` 편수 / 전체 편수, 문항 합) | 처리 − 대조 **≤ +10%p** (처리는 목록 모드라 편수가 늘어 개수 대신 비율 — protocol §2.5) |
| 보호 1b: 대조는 3편 이상인데 처리만 3편 미만으로 준 문항 | **≤ 3** (dev D_140 이 거르기에서 10→1) |
| 보호 2: 단일 주제 held-out([`foundation_1031/heldout.tsv`](../foundation_1031/heldout.tsv) 90)에서 나뉜 문항 | **≤ 4**. 나뉜 문항은 두 조건 검색만 → 정답 `ok` 잃은 문항 ≤ 1 |
| 보호 3: 나뉜 문항의 검색 ~ 거르기 단계(`search` + `select` + `filter`) 중앙값 증가 | **≤ +60s** |
| 보고 | 하위 주제를 다 덮은 문항 수 · 덮은 주제 합계 · 나뉜 문항 수(꼴별) · 2단계 출력 · 최종 편수 |

**필요 문항 수(§2.5):** 동점 예상 — 2단계가 못 나누는 문항(dev 2/7 ≈ 30%) + 대조도 다 덮는 문항(주제 둘 · 목록 질문). 동점 아닌 문항 15~18 예상, 효과 비율 4:1 이상 예상(dev §6: 나뉜 4 중 이김 2 · 비김 1 · 불분명 1) → 12 필요. **동점 아닌 문항이 12 미만이면 "검정력 부족"으로 적고 채택하지 않는다**(다음은 문항 추가).

채택이면 **사용자 승인 후** 운영 `.env` `RAG_TOPIC_SPLIT=1` · 봇 재시작.

여기서 재지 않는 것: 답 단계 — 나뉜 질문은 목록 모드 번호 칸 템플릿으로 답하고 판정을 건너뛴다(답 꼴이 바뀜). 근거 없는 주장 · 인용 번호 오류가 줄었는지는 채택 뒤 별도 라운드. 목록 모드 몫(편수 5→10)과 나눠 검색 몫을 따로 재지 않는다 — dev D_75 는 대조도 목록 모드(10편)였는데 4주제 중 2 → 4 라 나눠 검색 몫이 있다.
