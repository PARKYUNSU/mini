# 정답 유무 판정 호출 — 오프라인 측정 (사전 등록, 2026-10-11)

> 측정 **전에** 쓴다. §3 기준은 결과를 본 뒤 바꾸지 않는다.

## 1. 왜

[yunsur_v14 §3.5](../yunsur_v14/README.md): 답변 모델(9B) 하나에 "정답이 컨텍스트에 있는가" 판단과 답변 생성을 함께 맡기면, 정답 없음 예시 비율을 올려도 고지율과 거짓 부정을 맞바꿀 뿐이다(v14: 고지 7/21, 거짓 부정 8%). 교사 데이터는 "정답은 문서 N / 없음" 힌트를 받고 만들어졌다 — 운영에서도 판단을 **따로** 하고 결과를 힌트로 넣는 구조가 자연스럽다.

이 측정은 그 판단 호출만 떼어서, 운영 컨텍스트 그대로 얼마나 맞는지 잰다. 답변 모델·운영 코드는 바꾸지 않는다.

## 2. 방법

1. **컨텍스트 캡처** — [`capture_eval_prompts.py`](../../../scripts/capture_eval_prompts.py): 평가 162문항을 운영 그래프(라우터 → RAG 검색 → 번호 매기기)에 넣고 답변 LLM 호출 직전의 번호 붙은 컨텍스트를 저장한다(답변 LLM 은 스텁). `context_papers` 가 `ans_v13` 과 같은 문항만 쓴다.
2. **판정 호출** — [`presence_judge.py`](../../../scripts/presence_judge.py): 질문 + 번호 붙은 문서만 주고 "질문이 찾는 그 연구가 몇 번 문서인가, 없으면 `없음`" 을 묻는다. Ollama, `reasoning=False`, temperature 0, seed 0 (운영 로컬 호출과 같은 설정).
   - 모델 후보: `qwen3.5:9b`(base, 운영 LOCAL_LLM) · `yunsur_v13`(운영 RAG 답변 모델). 둘 다 이미 맥미니에 있다.
   - 프롬프트는 측정 전에 고정한다(스크립트 안 `PROMPT`). 결과를 보고 고치지 않는다 — 고치면 새 측정으로 기록한다.
3. 운영에서 쓰는 방식(측정 대상): 판정이 `없음` 일 때만 답변 프롬프트에 "정답 없음" 힌트를 넣는다. 번호를 고른 경우엔 힌트를 넣지 않는다(v13 그대로) — 그래서 **틀린 번호를 고르는 오류는 운영에 해가 없고, `없음` 판정의 정확도만 중요하다.**

## 3. 기준 (사전 선언)

정답 있음 = 정답 논문이 컨텍스트에 있는 문항, 정답 없음 = 없는 문항 (평가셋 정답 목록 기준).

- **거짓 '없음'** (정답 있음에서 `없음`) **≤ 5%** — v14 상한과 같다.
- **'없음' 재현** (정답 없음에서 `없음`) **≥ 7/21 (33%)** — v14 가 학습으로 얻은 수준 이상.
- 두 조건을 모두 만족한 모델이 있으면 **다음 단계(통합 측정)로 간다**: 판정 → 힌트 → v13 답변을 162문항 생성해 거짓 부정·고지·내용 지표를 v13 과 비교(별도 사전 등록). 둘 다 만족하면 base 를 쓴다(답변 모델과 독립된 판단, 운영에 이미 상주).
- 하나도 만족하지 못하면 판정 호출 방식은 보류하고, 검색 점수 임계값(후보 2)을 같은 기준으로 잰다.
- 서술 지표: 정답 번호 지목률, 판정 출력 형식 오류율, 호출당 지연(초).

한계: 정답 없음이 21문항뿐이라 재현율 추정의 신뢰구간이 넓다. 평가셋 정답 목록 밖에 질문에 맞는 논문이 컨텍스트에 있을 수 있다(그 경우 `없음` 이 아니라 번호를 고른 것이 오히려 맞을 수 있다 — 표본으로 확인해 서술).

## 3.5 결과 (2026-10-11)

컨텍스트 캡처 `ctx_1011` (162문항, 답변 스텁) — RAG 159문항 모두 `ans_v13` 과 컨텍스트 동일. 정답 있음 138 · 없음 21.

| | `qwen3.5:9b` | `yunsur_v13` | 기준 |
|---|---|---|---|
| 거짓 '없음' (정답 있음 138) | 23 (16.7%) | **13 (9.4%)** | ≤ 5% ✗ ✗ |
| '없음' 재현 (정답 없음 21) | **20/21** | 16/21 | ≥ 7/21 ✓ ✓ |
| 정답 번호 지목 | 113 (81.9%) | 122 (88.4%) | 서술 |
| 형식 오류 · 지연 | 0 · 6.8s | 0 · 6.7s | 서술 |

**사전 기준(§3)에 따른 판정: 두 모델 모두 미달 → 판정 호출 방식 보류.**

- v13 의 거짓 '없음' 13건은 모두 base 도 틀렸다(base 만 틀린 것 10건).
- 표본 확인: 13건 모두 평가셋 정답이 질문에 맞는 논문이다(CoPE, HuggingGPT, GPT-3 등) — 라벨 문제가 아니다. 대부분 검색된 발췌가 논문의 핵심 기여가 아닌 부분이라 판정기가 "다른 연구"로 본 것으로 보인다. v12/v13 답변이 약했던 문항(A003·A031·A069·C2_03 등)과 겹친다 — **판정의 한계가 아니라 발췌의 한계**일 가능성이 크다.
- 비교: v14(학습으로 고지) 는 재현 7/21 · 거짓 부정 8%, 판정 호출은 재현 16~20/21 · 거짓 '없음' 9~17%. 판정 호출 쪽이 '없음'을 훨씬 잘 잡지만 거짓 '없음'이 더 많다.

다음(§3 의 계획): 검색 점수 임계값(후보 2)을 같은 기준으로 잰다. 발췌 문제라면 임계값도 같은 문항에서 막힐 수 있다 — 그 경우 근본 원인은 검색이 핵심 발췌(초록·제목)를 컨텍스트에 넣지 못하는 것이다.

## 5. 후보 2 — 검색 점수 임계값 (사전 등록, 2026-10-11, 결과 전)

- 신호: 컨텍스트 문서들의 `[Distance]` 중 **최솟값**(가장 가까운 문서). 최솟값 > t 이면 `없음`.
- 같은 159문항(`ctx_1011`)에서 t 를 고르면 과적합이므로: **표본 안 최적 t 조차 §3 기준(거짓 '없음' ≤ 5% 그리고 재현 ≥ 7/21)을 못 맞추면 이 방식은 기각**한다. 맞추는 t 가 있으면 그것은 상한일 뿐이며, 운영에 쓰기 전 새 문항으로 검증한다.
- 서술: AUC(정답 없음 vs 있음 구분력), 거짓 '없음' ≤ 5% 를 지키는 가장 큰 재현.

## 6. 원인 확인 — 정답 발췌가 초록인가 (사전 등록, 결과 전)

가설(§3.5): 거짓 '없음'은 검색이 정답 논문의 **핵심 발췌(초록)** 대신 본문 조각을 넣었을 때 생긴다.

- 정답 있음 138문항에서 정답 논문 블록에 초록이 들어 있는지 센다(블록 본문에 `Abstract` 머리 또는 코퍼스 초록 첫 120자가 포함).
- 판정 호출(`yunsur_v13`)의 거짓 '없음' 비율을 초록 있음 / 없음으로 나눠 비교(Fisher 정확 검정, 양측). 초록 없음 쪽이 유의하게 높으면 가설을 지지 → 다음 단계는 검색이 정답 후보 논문마다 초록 청크를 함께 넣도록 고치는 것(별도 사전 등록).
- 같은 분할로 v13 답변의 첫 항목 정답률·gpt-oss ok 도 서술한다(답변 품질에도 같은 원인이 있는지).
