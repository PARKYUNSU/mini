# 검색어 후처리만 — 목록 번호 · 일반어 빼기 (사전 등록, 2026-10-21)

> 측정 **전에** 쓴다. 선행: [`query_extract_1021/`](../query_extract_1021/) — 프롬프트를 바꾼 v2 는 예시 용어가 무관한 질문에 새어 들어가 정답 검색 236 중 197 → 181 로 **기각**. 다만 일반어만 빠진 검색어는 깔끔했다. 외부 검색 v3 에서 효과가 확인된 부분(일반어 빼기)만 DB 검색어에 옮기는 최소 변경. 사용자 요청(10-21).

## 1. 바꾸는 것 — `RAG_QUERY_CLEAN` (기본 `0`)

`_extract_english_rag_query` 의 **프롬프트는 그대로**(지금 운영). 두 가지만:
1. LLM 에 넘기기 전 질문 앞 목록 번호(`1.` · `1)` · `①` · `-` 등)를 지운다.
2. 나온 검색어에서 외부 검색 v3 와 **같은 일반어 목록**(`core/rag/external_search.clean_query`: research · academic · paper(s) · study · survey · keywords · summary · trends · methods …)을 뺀다. 빼고 3단어 미만이면 원래 검색어. 쉼표 구분은 유지한다.

대화 맥락 재작성 · 비교 대상 추출 · 외부 검색은 그대로.

## 2. 방법 (맥미니, 검색만 — 판정 끔, 운영 설정 그대로)

대조 `qc0_*`(`RAG_QUERY_CLEAN=0`) · 처리 `qc1_*`(`=1`), 세트마다 번갈아: 162 · real40 · real2(정답 있는 세트) + corpus_seed 의 held-out 30(H) · 직무 질문 34(D). 대조를 다시 잰다(10-21 01:00 수집으로 DB 가 바뀌어 지난밤 `qx0` 는 쓰지 않는다).
- 관련성(보호 기준을 통과할 때만): H · D 의 두 조건 컨텍스트 논문을 합쳐, 이미 판정한 쌍(corpus_seed `judged_*`)은 그 판정을 쓰고 새 쌍만 섞어 조건을 모른 채 0 · 1 · 2 판정.

예상: 검색어가 바뀌는 문항 40~60%, 정답 있는 세트 ±3, held-out '2' 논문 늘어난 질문 6 : 줄어든 3 안팎(효과는 작을 수 있다 — v1 검색어는 쉼표 구 단위라 일반어가 빠져도 핵심 구가 남는다).

**읽은 것**
- 해롭지 않다(정답 검색 그대로, 시간 그대로). 검색어의 절반 이상이 바뀌었지만 결과는 **조금 나아지는 방향**(held-out +3편, 직무 질문 +10편)이고 유의하지 않다 — 사전 등록 예상대로 v1 검색어는 쉼표 구 단위라 일반어가 빠져도 핵심 구가 남는다.
- 외부 검색 v3 에서 일반어 빼기가 크게 들었던 이유는 OpenAlex 가 단어 하나하나로 넓게 찾는 검색이기 때문으로 보인다. DB 검색(임베딩 + BM25 + 재순위)은 일반어에 덜 흔들린다.
- 이로써 "검색어" 쪽 개선은 일단 여기까지 — 큰 차이를 내려면 검색어가 아니라 다른 단계(재순위 · 코퍼스 범위)를 봐야 한다.
