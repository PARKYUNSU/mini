# 정답 유무 판정 → 힌트 → 답변 통합 측정 (사전 등록, 2026-10-12)

> 측정 **전에** 쓴다. §3 판정 규칙은 결과를 본 뒤 바꾸지 않는다.

## 1. 왜

- 운영(v13 + 초록 컨텍스트)은 정답이 컨텍스트에 없을 때도 "없다"고 말하지 않는다(정답 없음 일관 고지 0/21 — [abstract_context_1011 §3.5](../abstract_context_1011/README.md)).
- 학습으로 고치려던 v14 는 고지 7/21 을 얻었지만 거짓 부정 8% 로 실패([yunsur_v14 §3.5](../yunsur_v14/README.md)).
- 초록 컨텍스트에서는 따로 묻는 판정 호출(`yunsur_v13`)이 거짓 '없음' 3.6%·재현 13/21 로 기준을 통과했다([abstract_context_1011 §3.5](../abstract_context_1011/README.md), [presence_judge_1011](../presence_judge_1011/README.md)).

## 2. 바꾸는 것 — 하나

`RAG_PRESENCE_JUDGE=1` 이면 답변 생성 직전(번호 매긴 뒤) [`core/llm/presence_judge.judge_presence`](../../../core/llm/presence_judge.py) 를 부르고, 판정이 `없음` 이면 시스템 프롬프트 끝에 `NO_DOC_HINT`(v13 의 정답 없음 형식 지시)를 붙인다. 번호를 고르거나 실패하면 아무것도 바꾸지 않는다. 판정 모델은 `RAG_ANSWER_MODEL`(= `yunsur_v13`), 프롬프트는 오프라인 측정과 같은 글자(스크립트가 같은 상수를 import).

기본 꺼짐. 답변 모델·초록 컨텍스트·후처리는 그대로.

## 3. 평가 (사전 선언)

생성: `RAG_ANSWER_MODEL=yunsur_v13 RAG_CONTEXT_ABSTRACT=1 RAG_PRESENCE_JUDGE=1 eval_e2e_ko.py --answer --save-context --label ans_v13abs_pj`. 비교: `ans_v13abs` (판정 없음). 컨텍스트 논문이 같은 문항만.

- **주 지표 — 정답 없음 일관 고지** (`nogold_metrics.py ans_v13abs_pj ans_v13abs`): 정답 없음 문항에서 서론·결론 모두 "없다". McNemar 양측 α=0.05 로 **유의하게 높을 것**.
- **가드 — 거짓 부정**: 정답 있음에서 서론 "없다" ≤ **5%**, 그리고 유의하게 늘지 않을 것.
- **안전 — 내용** (gpt-oss 단일 답변 판정, H100; `ans_v13abs` 판정은 기존 것): 정답 있음 짝에서 ok 가 유의하게 낮지 않고 날조가 유의하게 높지 않을 것.
- **채택**: 세 조건 모두. **실패**: 가드 또는 안전 위반. 그 밖은 보류.
- 부 지표(서술): 판정 분포(번호/없음/형식 오류), 힌트가 붙었는데 형식을 안 따른 수, 문항당 지연 증가, correct 짝.

예상: 일관 고지 0 → 10~13/21, 거짓 부정 0 → ≤ 5/138 (판정 거짓 '없음' 3.6% 만큼). ok 는 정답 있음 중 거짓 '없음' 문항만큼(≤ 5건) 내려갈 수 있다 — 유의하지 않을 것으로 본다.

## 4. 비용

생성 로컬(약 2.5시간 — 판정 호출만큼 늘어남). 판정 H100 Secure 약 10분(≈ $0.7).
