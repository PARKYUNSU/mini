# 기전 메모 — lr 인하는 왜 길이 제약에만 작용하나 (탐색, 미해결)

작성 2026-10-03. **사전 등록 없는 탐색 분석**이다. 새로 측정하지 않고 [`finetune_damage_1002/04_eval/`](finetune_damage_1002/04_eval/) (150문항 × 3회 × 3모델)과 v9 학습 데이터를 다시 셌다. **판정이 아니므로 결론으로 인용하지 않는다.**

## 묻는 것

[`protocol.md`](protocol.md) §3 에 올린 결론 — lr 2e-4 → 5e-5 가 **계획 슬롯의 길이 제약 준수를 개선한다** (네 세션 재현). 알려진 것은 **v10 이 단계 줄을 짧게 쓴다**는 사실뿐이고, **왜 그런지는 모른다.**

## 1. 짧아지는 것은 전역 효과가 아니다

출력 길이 중앙값 (글자, `status=ok` 시행):

| 슬롯 | base | v9 | v10 | v10 vs base |
|---|---|---|---|---|
| 잡담 (n≈144) | 154 | 152 | 139 | −10% |
| 계획 (n=192) | 140 | 142 | 122 | −12% |
| 코딩 (n≈80) | 165 | 175 | 132 | −20% |
| **RAG (n=24)** | 784 | 774 | **1140** | **+45%** |

**RAG 만 반대 방향이다.** "v10 은 간결하다" 는 설명은 성립하지 않는다.

## 2. 학습 목표와 견주면 더 꼬인다

v9 학습 데이터(1,100건)의 슬롯별 `output` 길이 중앙값과 비교:

| 슬롯 | 학습 목표 | base | v9 | v10 | 목표에 가까운 쪽 |
|---|---|---|---|---|---|
| 잡담 | 74 | 154 | 152 | **139** | v10 |
| RAG | 1398 | 784 | 774 | **1140** | v10 |
| 계획(응답 전체) | 156 | 140 | 142 | 122 | v9 |

**잡담과 RAG 에서는 v10 이 학습 목표 쪽으로 더 갔다.** lr 을 낮춰 델타를 작게 줬는데 학습 분포를 **더** 따라간 셈이다 — 직관과 어긋난다.

## 3. 그런데 계획의 **줄 길이**는 학습 목표에서 멀어진다

제약이 실제로 재는 것은 응답 전체가 아니라 **단계 한 줄의 길이**다. 학습 데이터의 계획 단계 줄(표본 1,102개)과 비교하면:

| | 모든 단계줄 중앙 | 한 응답의 최장 단계줄 중앙 |
|---|---|---|
| **학습 데이터** | **50자** | — |
| base | 42 | 49 |
| v9 | 43 | 51 |
| **v10** | **37** | **44** |

**v9 은 학습 데이터(50자)를 그대로 따라갔고 v10 만 13자 짧다.** 여기서는 v10 이 학습 목표에서 **멀어진다.** §2 와 방향이 반대다.

응답당 단계 수는 셋 다 2.8~3.0 으로 같다 — 단계를 덜 쓰는 것이 아니라 **한 줄을 짧게 쓴다.**

## 4. 남는 설명 후보

**(A) v10 이 슬롯별 길이 규범을 더 선명하게 구분한다.** 잡담은 짧게·RAG 는 길게 — 학습 데이터의 슬롯 간 차이를 더 잘 배웠다는 그림. 계획의 줄 단축은 그 과정의 부작용.

**(B) RAG 의 길이는 학습이 아니라 템플릿에서 온다.** RAG 슬롯은 시스템 프롬프트가 3단 구조를 강제한다 (`RAG_OUTPUT_TEMPLATE_MULTI_STRICT`). v10 이 그 템플릿을 더 성실히 채우면 길이는 자동으로 늘어난다 — 그렇다면 "학습 목표에 가까워졌다" 는 해석은 착시이고, **v10 은 전반적으로 지시를 더 잘 따르는 것**이 된다.

**(B) 가 맞다면 §3 의 결론("길이 제약 준수")은 더 넓은 성질의 한 단면일 수 있다.** 다만 [`finetune_damage_1002/`](finetune_damage_1002/) 에서 비길이 제약(줄 수·어휘)은 세 비교 모두 갈렸으므로, "지시를 더 잘 따른다" 는 **이미 한 번 반증된 방향**이다.

**가르는 방법**: RAG 응답에서 템플릿 섹션이 실제로 채워졌는지 세어 본다. v10 이 섹션을 더 많이/성실히 채웠다면 (B), 섹션 수는 같은데 각 섹션이 길어졌다면 (A) 쪽이다. → **셌다. §6 에서 (A) 로 기울었다.**

## 5. 학습 방식 (참고)

LoRA SFT 다 — 베이스 가중치는 건드리지 않고 저랭크 델타만 더한다.

```
peft_type  LORA ·  r 16 ·  lora_alpha 32
target     q·k·v·o_proj + gate·up·down_proj
학습 비율  29,097,984 / 9,438,911,728 = 0.31%
어댑터     111MB (베이스 17GB)
```

v9 과 v10 은 **데이터·스텝·시드가 같고 lr 만 다르다**(2e-4 ↔ 5e-5). 그러므로 둘의 차이는 **더해지는 델타의 크기** 하나로 귀속된다. 운영 배포는 머지 후 q4_k_m 양자화다 (Ollama 가 `ADAPTER` 를 거부해 v5 부터 머지 방식, [`scripts/merge_lora_gguf.sh`](../../scripts/merge_lora_gguf.sh)).

**역설은 여기 있다**: 델타가 **작은** v10 이 잡담·RAG 에서 학습 분포 쪽으로 **더** 갔다. 작은 갱신이 더 큰 행동 변화를 낸 셈이고, 아직 설명이 없다.

## 6. 가른 결과 — (A) 쪽이다

**측정을 다시 해야 했다.** §4 에 "측정 없이 기존 원본으로 셀 수 있다" 고 썼는데 틀렸다. 라운드 원본(`04_eval/*.jsonl`)은 응답을 240자 `preview` 로만 저장한다. 그 상태로 센 섹션 수는 잘림의 부산물이었다(base 1개·v9 2개·v10 1개). 그래서 RAG 8문항 × 3회 × 3모델을 **전문으로 다시 받았다** — [`length_mechanism_1003/data/ragdump.jsonl`](length_mechanism_1003/data/ragdump.jsonl) (sha256 `4c3a404fbf3f…`, 72행 전부 `ok`), 집계 스크립트는 [`count_sections.py`](length_mechanism_1003/count_sections.py).

재측정에서 길이 차이가 **독립 세션으로 재현됐다** (중앙값): base 839 · v9 794 · v10 **1108**. §1 의 784/774/1140 과 같은 그림이다.

템플릿(`RAG_OUTPUT_TEMPLATE_MULTI_STRICT`)은 섹션 3개 · 논문 2편 · 논문마다 `무엇을/어떻게/차별점` **고정 3슬롯** · Gap 불릿 2개를 지정한다. 고정 칸이 있으므로 "칸이 늘었나" 와 "칸 안이 길어졌나" 를 따로 셀 수 있다. 마크업(`##`·`###`·굵게)에 의존하지 않도록 **섹션 이름**으로 셌다.

| | base | v9 | v10 | base→v10 |
|---|---|---|---|---|
| 전체 길이 | 752 | 776 | 1103 | **+47%** |
| 섹션 수 (지정 3) | 2.12 | 0.04 | 2.12 | **±0%** |
| 논문 수 (지정 2) | 1.75 | 0.00 | 1.58 | −10% |
| 고정 슬롯 채움 (지정 6) | 5.04 | 0.00 | 4.25 | −16% |
| **고정 슬롯당 값 길이** | **27.9** | — | **47.6** | **+71%** |
| Gap 불릿 수 (지정 2) | 1.42 | 0.00 | 1.17 | −18% |
| Gap 불릿 길이 | 38.7 | — | 58.1 | +50% |

**칸을 세는 지표는 전부 제자리이거나 오히려 줄었고, 칸 안의 길이만 올랐다.** +47% 는 전부 후자에서 온다. 문항별로 짝지어 봐도 한 문항이 끌고 가는 것이 아니다: 양쪽이 템플릿을 따른 6문항에서 **6/6 길어졌다**(부호검정 양측 p = 0.031). 슬롯 **수**가 늘어난 문항은 3/8 뿐이다.

→ **(B) 가 아니다.** v10 은 템플릿을 더 성실히 채우는 것이 아니라, **같은 칸에 더 길게 쓴다.** (A)("슬롯별 길이 규범") 와 맞는 그림이고, §3 의 계획 단계줄 13자 단축도 같은 축의 반대 끝으로 읽힌다 — 잡담·계획은 짧게, RAG 는 길게.

### 곁가지로 나온 것 — v9 는 템플릿을 버린다

섹션 이름이 하나도 없는 시행(= 템플릿 이탈):

| base | v9 | v10 |
|---|---|---|
| 4/24 | **23/24** | 7/24 |

v9 는 24시행 중 23번 템플릿을 무시하고 `서론`/`본론`/`결론` 에세이로 답했다. 시스템 프롬프트가 "아래 뼈대를 그대로 따라 값만 채우세요" 라고 지시한 자리다. 같은 데이터·스텝·시드에서 **lr 만 2e-4 → 5e-5 로 내리면 템플릿 준수가 23/24 이탈 → 7/24 로 돌아온다.** v10 은 base(4/24) 보다는 여전히 나쁘다.

이것은 사전 등록 없이 나온 **탐색 관측**이고 셋 다 같은 세션 1회분이다. 다만 효과 크기가 크고 방향이 분명해서, 다음 라운드의 사전 등록 후보로 남긴다: *"lr 인하가 RAG 템플릿 준수를 회복시키는가"* — 문항 8개로는 부족하니 문항을 늘려야 한다.

### 그래도 남는 역설

(A) 로 기울었다고 §5 의 역설이 풀리지는 않는다. **델타가 작은 v10 이 슬롯별 길이 규범을 더 선명하게 배웠다** 는 말은 여전히 설명이 아니라 서술이다. lr 2e-4 가 무엇을 망가뜨려 길이 규범과 템플릿 준수를 동시에 잃게 했는지는 모른다. 중간 체크포인트나 중간 lr(1e-4) 없이는 더 갈 수 없다.
