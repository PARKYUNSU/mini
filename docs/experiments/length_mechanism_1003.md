# 기전 메모 — lr 인하는 왜 길이 제약에만 작용하나 (탐색, 미해결)

작성 2026-10-03. **사전 등록 없는 탐색 분석**이다. 새로 측정하지 않고 [`finetune_damage_1002/04_eval/`](finetune_damage_1002/04_eval/) (150문항 × 3회 × 3모델)과 v9 학습 데이터를 다시 셌다. **판정이 아니므로 결론으로 인용하지 않는다.**

## 묻는 것

[`protocol.md`](protocol.md) §3 에 올린 결론 — lr 2e-4 → 5e-5 가 **계획 슬롯의 길이 제약 준수를 개선한다** (네 세션 재현). 알려진 것은 **v10 이 단계 줄을 짧게 쓴다**는 사실뿐이고, **왜 그런지는 모른다.**

## 1. 짧아지는 것은 전역 효과가 아니다

출력 길이 중앙값 (글자, `status=ok` 시행):

| 슬롯 | base | v9 | v10 | v10 vs base |
|---|---|---|---|---|
| 잡담 (n≈144) | 154 | 152 | 139 | −10% |
| 계획 (n=192) | 140 | 142 | 122 | −12% |
| 코딩 (n≈80) | 165 | 175 | 132 | −20% |
| **RAG (n=24)** | 784 | 774 | **1140** | **+45%** |

**RAG 만 반대 방향이다.** "v10 은 간결하다" 는 설명은 성립하지 않는다.

## 2. 학습 목표와 견주면 더 꼬인다

v9 학습 데이터(1,100건)의 슬롯별 `output` 길이 중앙값과 비교:

| 슬롯 | 학습 목표 | base | v9 | v10 | 목표에 가까운 쪽 |
|---|---|---|---|---|---|
| 잡담 | 74 | 154 | 152 | **139** | v10 |
| RAG | 1398 | 784 | 774 | **1140** | v10 |
| 계획(응답 전체) | 156 | 140 | 142 | 122 | v9 |

**잡담과 RAG 에서는 v10 이 학습 목표 쪽으로 더 갔다.** lr 을 낮춰 델타를 작게 줬는데 학습 분포를 **더** 따라간 셈이다 — 직관과 어긋난다.

## 3. 그런데 계획의 **줄 길이**는 학습 목표에서 멀어진다

제약이 실제로 재는 것은 응답 전체가 아니라 **단계 한 줄의 길이**다. 학습 데이터의 계획 단계 줄(표본 1,102개)과 비교하면:

| | 모든 단계줄 중앙 | 한 응답의 최장 단계줄 중앙 |
|---|---|---|
| **학습 데이터** | **50자** | — |
| base | 42 | 49 |
| v9 | 43 | 51 |
| **v10** | **37** | **44** |

**v9 은 학습 데이터(50자)를 그대로 따라갔고 v10 만 13자 짧다.** 여기서는 v10 이 학습 목표에서 **멀어진다.** §2 와 방향이 반대다.

응답당 단계 수는 셋 다 2.8~3.0 으로 같다 — 단계를 덜 쓰는 것이 아니라 **한 줄을 짧게 쓴다.**

## 4. 남는 설명 후보

**(A) v10 이 슬롯별 길이 규범을 더 선명하게 구분한다.** 잡담은 짧게·RAG 는 길게 — 학습 데이터의 슬롯 간 차이를 더 잘 배웠다는 그림. 계획의 줄 단축은 그 과정의 부작용.

**(B) RAG 의 길이는 학습이 아니라 템플릿에서 온다.** RAG 슬롯은 시스템 프롬프트가 3단 구조를 강제한다 (`RAG_OUTPUT_TEMPLATE_MULTI_STRICT`). v10 이 그 템플릿을 더 성실히 채우면 길이는 자동으로 늘어난다 — 그렇다면 "학습 목표에 가까워졌다" 는 해석은 착시이고, **v10 은 전반적으로 지시를 더 잘 따르는 것**이 된다.

**(B) 가 맞다면 §3 의 결론("길이 제약 준수")은 더 넓은 성질의 한 단면일 수 있다.** 다만 [`finetune_damage_1002/`](finetune_damage_1002/) 에서 비길이 제약(줄 수·어휘)은 세 비교 모두 갈렸으므로, "지시를 더 잘 따른다" 는 **이미 한 번 반증된 방향**이다.

**가르는 방법**: RAG 응답에서 템플릿 섹션이 실제로 채워졌는지 세어 본다. v10 이 섹션을 더 많이/성실히 채웠다면 (B), 섹션 수는 같은데 각 섹션이 길어졌다면 (A) 쪽이다. 측정 없이 기존 원본으로 셀 수 있다.

## 5. 학습 방식 (참고)

LoRA SFT 다 — 베이스 가중치는 건드리지 않고 저랭크 델타만 더한다.

```
peft_type  LORA ·  r 16 ·  lora_alpha 32
target     q·k·v·o_proj + gate·up·down_proj
학습 비율  29,097,984 / 9,438,911,728 = 0.31%
어댑터     111MB (베이스 17GB)
```

v9 과 v10 은 **데이터·스텝·시드가 같고 lr 만 다르다**(2e-4 ↔ 5e-5). 그러므로 둘의 차이는 **더해지는 델타의 크기** 하나로 귀속된다. 운영 배포는 머지 후 q4_k_m 양자화다 (Ollama 가 `ADAPTER` 를 거부해 v5 부터 머지 방식, [`scripts/merge_lora_gguf.sh`](../../scripts/merge_lora_gguf.sh)).

**역설은 여기 있다**: 델타가 **작은** v10 이 잡담·RAG 에서 학습 분포 쪽으로 **더** 갔다. 작은 갱신이 더 큰 행동 변화를 낸 셈이고, 아직 설명이 없다.
