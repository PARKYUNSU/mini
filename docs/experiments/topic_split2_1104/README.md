## 1. 1103 과 달라지는 것 (`RAG_TOPIC_SPLIT=1`, 기본 `0`)

나눈 뒤 과정(주제마다 `rag.search(top_k=15)` → 주제별 상위 3 을 번갈아 앞에 → 목록 모드 → 비교 분리 · 판정 건너뜀)은 그대로다. 앞단만 바꿨다 — `agent_nodes.py`:

1. **파서(`_parse_subtopics`)** — 번호 없는 줄도 읽는다. 설명 줄(`Note…` · `:` 로 끝나는 머리말)은 빼고, 빈 줄 뒤에 같은 목록을 한 번 더 쓰면 첫 덩어리만.
2. **직접 적은 항목은 LLM 없이(`_explicit_subtopics`)** — 영어 키워드 쉼표 줄 · 따옴표 항목 셋 이상 · 번호 항목. 번호 항목에 지시문("…정리해줘") · 조건("서베이 제외" · "2024년 이후" · "다섯 편")이 하나라도 끼면 항목을 믿지 않고 LLM 으로 넘긴다.
3. **1단계 후보(`topic_split_candidate`)** — 괄호 안 쉼표는 안 센다. 쉼표 목록은 영어 줄 · 따옴표 항목 셋 이상이거나, 마지막 항목 뒤가 일반 꼬리("관련" · "다룬" · "쪽" · "에 대한" · "분야" · "각각" · 짧은 "… 논문/연구")일 때만 후보다. "…를 합친 RAG 연구" 는 한 주제다.
4. **한국어 항목 → 영어 키워드(`_subtopic_keywords`)** — 기존 검색어 추출 대신 전용 프롬프트. 번호 항목 **앞 글**만 맥락으로 준다(120자). 맥락이 없으면 '가지치기(pruning)' 가 정원 가지치기가 되고, 맥락에 다른 항목이 들어가면 그것까지 옮긴다.
5. **RAG 맥락** — 프롬프트의 "such as RAG" 예시를 뺐다. 질문에 RAG 가 없으면 줄의 RAG 를 지우고, 있으면 없는 줄에 붙인다. "RAG를" 처럼 조사가 붙으면 `\b` 로 못 찾던 버그, `storage` 를 RAG 로 보던 버그를 고쳤다.
6. **LLM 프롬프트 v3** — 예/아니오 물음 대신 "하위 주제를 줄마다 적어라".

대가: 직접 적은 영어 항목은 LLM 호출 0, 한국어 항목은 항목마다 1회(~2s), 그 밖의 후보는 1회 + 한국어 줄마다 1회. 후보가 아닌 질문은 코드 경로가 같다.

## 4. 판정

| 지표 | 기준 |
|---|---|
| **주:** 문항별 **덮은 하위 주제 수** | 처리가 더 많은 문항 > 더 적은 문항, **부호 검정 양측 p < 0.05** |
| 보호 1: 주제 밖 문서 비율(라벨 `-` 편수 / 전체 편수) | 처리 − 대조 **≤ +10%p** |
| 보호 1b: 대조는 3편 이상인데 처리만 3편 미만으로 준 문항 | **≤ 4** (1103 의 3/30 을 40문항으로 비례) |
| 보호 2: 단일 주제 held-out([`foundation_1031/heldout.tsv`](../foundation_1031/heldout.tsv) 90)에서 나뉜 문항 | **≤ 4**. 나뉜 문항은 두 조건 검색 → 정답 `ok` 잃은 문항 ≤ 1 |
| 보호 2b: 쉼표 · 번호가 있는 단일 주제 15 에서 나뉜 문항 | **≤ 3** |
| 보호 3: 나뉜 문항의 검색 ~ 거르기 단계 중앙값 증가 | **≤ +60s** |
| 보고 | 다 덮은 문항 수 · 덮은 주제 합계 · 나뉜 문항 수(꼴별) · 최종 편수 |

**필요 문항 수(§2.5):** dev 는 동점 아닌 문항 60% · 비율 5:1. 새 문항에서 줄어든다고 보고 3:1 을 가정하면 동점 아닌 17 필요 → 40문항이면 ~24 예상. **동점 아닌 문항이 12 미만이면 "검정력 부족"으로 적고 채택하지 않는다.**

채택이면 **사용자 승인 후** 운영 `.env` `RAG_TOPIC_SPLIT=1` · 봇 재시작.

여기서 재지 않는 것: 답 단계 — 나뉜 질문은 목록 모드 번호 칸 템플릿으로 답하고 판정을 건너뛴다. 평가 행에 답이 남으니 채택 전에 나뉜 문항 답을 표본으로 읽어 보고한다(기준 아님). 거르기가 여러 주제 목록에서 주제를 통째로 빼는 문제(dev 진 3문항의 원인)는 다음 후보로 남긴다.
