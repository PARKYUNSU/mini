# penalty_1113 — 반복 억제 설정이 한국어 깨짐을 만드는가

## 배경
judge_v2_1113 held-out 블라인드 9 쌍에서 반복된 용어가 비슷한 다른 글자로 바뀌는 깨짐이 여러 답에 나왔다("홉"→"홠프", "하이퍼그래프"→"하이퍼그래드", "에이전트"→"에지트", "온톨로지"→"온톨로리", "스캐폴드"?→"스크래프트"). 운영 답변 호출은 `repeat_penalty=1.18`(`core/llm/agent_llm.py`) 이고, `presence_penalty` 는 넘기지 않아 v13 모델 파일 기본값 **1.5** 가 적용된다. 27b 모델 파일은 `presence_penalty 0 · repeat_penalty 1`.

## 설계 (`run.py` → `answers.jsonl`)
- 문항: 깨짐 있던 5(H_D11 · H_A28 · H_H06 · G06 · G19) + 멀쩡했던 4(G01 · G07 · G12 · H_A02). held-out 대조(hj_ctl) 의 답 입력을 다시 만들어 v13 으로 답만 다시 낸다.
- 조건: `ops`(rp 1.18 · pp 1.5) · `rp1`(rp 1.0 · pp 1.5) · `pp0`(rp 1.18 · pp 0) · `off`(rp 1.0 · pp 0). 운영 샘플링(temperature 0.2 · top_p 0.8), seed 0–2 세 번.
- G06 의 "MPC" 는 반복 용어가 아니라 약어 착오일 수 있어 기준에서 뺀다.

## 판단 기준 (결과 보기 전 고정, 11-13)
실행은 이미 시작했지만 결과 파일은 이 기준을 적기 전까지 열지 않았다.
- **깨짐 해결:** 깨짐 있던 4 문항(H_D11 · H_A28 · H_H06 · G19) 각각에서, 그 조건 3 번 실행 중 깨진 단어가 나온 실행이 0–1 번. 4 문항 모두 만족하면 해결. 깨짐 = 질문 · 컨텍스트에 있는 용어가 답에서 한두 글자 바뀐 비단어(사람이 본다) 또는 KS X 1001 완성형 2,350자 밖 한글.
- **부작용 없음:** 멀쩡한 4 문항 12 실행에서 같은 문장 · 구절 되풀이(같은 8 어절 이상이 두 번 이상) 0, 답 길이 중앙이 같은 문항 `ops` 대비 ±20% 안.
- **채택 순서:** 두 기준을 다 통과한 조건 중 바꾸는 폭이 작은 것 — `pp0` → `rp1` → `off`. `ops` 가 이미 깨짐 기준을 통과하면(재현 안 됨) 판단 불가.
- 통과해도 이건 9 문항 진단이다. 운영 반영은 120 문항 재실행으로 깨짐 빈도와 보호 지표를 본 뒤 승인 요청한다.

## 기록
- 판정 재생(judge_v2_1113 §6) 의 v13 조건은 pp 1.5, 27b 조건은 pp 0 이었다 — 조건이 달랐다. llama.cpp 의 반복 억제는 최근 `repeat_last_n`(기본 64) 토큰을 보므로 프롬프트 끝의 판정 형식 예시 토큰도 깎일 수 있다(확인 안 함).

- 운영 설정이 이미 깨짐 기준(3 번 중 0–1)을 통과한다 → 사전 기준대로 **판단 불가**. 단독 재생에서는 깨짐이 3 번에 1 번꼴로 드물다. held-out 전체 실행에서는 5 문항 각각 두 실행 중 한 번(hj_ctl 3 · hj_new 2) 깨졌다 — 실제 경로(결론 다시 쓰기 등 다른 호출 포함)가 더 잘 깨질 수 있다.
- pp0 도 `홠` 이 나왔다 → presence 만 끄는 것으로는 없어지지 않을 수 있다. rp1 · off 는 0 이지만 n=3.
- 되풀이 · 길이: 멀쩡한 4 문항 모든 조건에서 8 어절 되풀이 0. 길이 중앙은 아래 2 차에서 함께 본다.
- 자동 검출: `홠` 은 KS X 1001 완성형 2,350 자 안에 있어 '희귀 글자' 검사로 안 잡혔다. 깨짐 검출은 사람 확인 또는 알려진 용어 대조가 필요하다.

## 2 차 (사전 고정, 결과 보기 전 · 11-13) — `run2.py`
- 문항: H_D11 · G19 (1 차에서 깨짐이 나온 둘). 조건 ops · rp1 · pp0 · off, seed 0–19 (각 20 번, 총 160).
- 깨짐 = 질문 · 컨텍스트 용어가 한두 글자 바뀐 비단어. 알려진 형태(`홠` · `하이퍼그래드` · `온톨로리` · `온톨로를`) 자동 + 한 번만 나온 3 글자 이상 한글 단어를 사람이 확인.
- **판단:** 두 문항 합쳐 ops 깨짐 실행 수를 기준으로, 어떤 조건이 ops 보다 깨짐이 적고 부호 검정(seed 짝, 한쪽만 깨진 짝) p < 0.05 이면 그 조건이 원인을 줄인다고 본다. ops 깨짐이 40 중 4 미만이면 판단 불가(너무 드묾).
- 부작용: 같은 160 에서 8 어절 되풀이 0, 길이 중앙 ops ±20%.

### 정정 (11-13 15:00) — 1 차 · 2 차 초반은 운영과 다른 프롬프트였다
답 입력 지문(`answer_input`, system + user 의 sha1)으로 대조해 보니, 깨졌던 5 문항(H_D11 · H_A28 · H_H06 · G06 · G19)은 held-out 대조에서 판정이 '없음' 이라 system 에 `NO_DOC_HINT` 가 붙어 있었다. `run.py` 는 이를 빼고 base system 만 썼다(user 부분은 일치). 멀쩡했던 4 문항은 판정 '있음' 이라 일치. 그래서 **결과 1 의 깨짐 문항 수치는 운영과 다른 프롬프트 결과**다.
- 고침: 대조 판정이 '없음' 이면 `NO_DOC_HINT` 를 붙이고, 지문이 저장값과 같은지 assert 한다(`run.py` · `run2.py`).
