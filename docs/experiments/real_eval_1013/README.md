# 실제 사용형 평가셋 — 수치 · 비교 · 주제 목록 · 실제 질문 (사전 등록, 2026-10-13)

> 측정 **전에** 쓴다. 채택 판정이 아니라 **위치 측정**이다. 기존 162문항은 거의 전부 "이런 논문 있어?" 찾기형이라, 실제로 묻는 유형(수치·비교·동향·연구 빈틈)에서 운영 봇이 어떤지 모른다.

## 1. 문항 (40개, `questions.tsv` · `gold.jsonl` · `spec.jsonl`)

| 유형 | 수 | 만든 방법 | 정답 |
|---|---|---|---|
| **N** 수치 | 15 | 기존 평가셋 정답이 아닌 논문 중 초록에 수치(%·배)가 있는 것을 시드 1013 으로 뽑아, 그 수치를 묻는 질문을 씀 | 논문 1편 + 기대 수치 문자열(모두 등장해야 함) |
| **C** 비교 | 11 | 같은 제목 키워드(speculative decoding, KV cache 등)의 두 논문 | 논문 2편 |
| **T** 주제 목록·동향 | 8 | 주제 키워드 | 코퍼스에서 **제목에 키워드가 든 논문 전부**(11~29편; T06 은 'reward model' 로 넓혀 12편) |
| **R** 실제 질문 | 6 | 봇 로그(`bot_ai_worker.log` 등)의 실제 논문 질문 전부 | 없음(판정만) |

질문 문장은 Claude 가 사용자 말투로 썼다. N·C 는 방법 이름을 넣은 문항과 뺀 문항이 섞여 있다.

## 2. 실행

- `eval_e2e_ko.py --answer --save-context --questions docs/experiments/real_eval_1013/questions.tsv --gold docs/experiments/real_eval_1013/gold.jsonl`
- 라벨 `real_v13`(운영 설정 그대로) · 부(참고) `real_v13_detail`(`RAG_ANSWER_DETAIL=1`, answer_detail_1013 의 처리).
- answer_detail_1013 의 두 실행이 끝난 뒤, 같은 Chroma(HF 백필 일시정지)로 연달아 실행.

## 3. 지표 (유형별 비율 + Wilson 95% CI)

| 유형 | 검색 | 답변 |
|---|---|---|
| N | 정답 논문이 컨텍스트에 있음 | **수치 정답** = 기대 수치가 모두 답에 등장 **그리고** 정답 논문을 인용 (자동). 다른 논문의 수치를 정답 논문에 붙였는지는 Claude 가 확인 |
| C | 두 논문 모두 컨텍스트에 있음 (한 편만도 따로 보고) | Claude: 두 논문을 모두 짚었나, 차이 설명 correct/partial/wrong, 날조 |
| T | 컨텍스트 안 정답(키워드) 논문 수 | 답이 인용한 논문 중 주제에 맞는 수(정답 집합은 자동, 밖은 Claude 판정). **통과 = 주제에 맞는 논문 ≥ 3** |
| R | — | Claude: 유용성 1~3, 날조 여부 |

판정은 모델 이름을 모르는 상태로 `real_v13` 만 한다. `real_v13_detail` 은 자동 지표(N 수치 정답, T 개수)만 비교해 서술한다.

**예상:** N 은 검색만 되면 수치를 잘 옮긴다(수치 정답 ≥ 60%). C 는 두 논문이 같이 검색되는 비율이 낮다(≤ 50%) — 질문 하나로 두 논문을 끌어와야 해서. T 는 통과하지만 동향 서술은 얕다. R 의 연구 빈틈 질문은 근거 없는 제안이 많다.
