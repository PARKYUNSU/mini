# 실험 노트 — yunsur_v9: 코딩을 학습에서 뺀다

- 시작일: 2026-09-27
- 선행: [`../baseline_0926/`](../baseline_0926/) (코딩에서 파인튜닝이 base 보다 유의하게 나쁨, McNemar **p=0.004**) · [`../yunsur_v8/`](../yunsur_v8/) (디코딩으로 못 고침)
- **범위: 순수 감산.** v6 학습 데이터에서 코딩 300건만 뺀다. 남은 1,100건은 v6 와 **바이트 단위로 같다** ([`scripts/gen_v9_dataset.py`](../../../scripts/gen_v9_dataset.py) `--build` 가 동일성을 검증한다)
- 데이터: 1,100건 — RAG 400 / 잡담 300 / 계획 400
- 하이퍼파라미터는 v3~v9 계속 고정. 스텝만 1,100/8 = **138** 로 줄어든다 (v6 는 175)

## 1. 왜 빼는가

네 라운드(v5~v8)를 모으면 슬롯별 결론이 갈린다.

| 슬롯 | 파인튜닝 효과 | 근거 |
|---|---|---|
| RAG | **유지 또는 개선** | 네 라운드 모두 0%. v6 만 literal `\n` 을 내지 않아 운영에 반영했다 |
| 잡담 | 동률 | base 와 불일치 0개 |
| 계획 | 동률 | v5 에서 16.7% → 4.2% 개선, 이후 0% |
| **코딩** | **유의하게 나쁨** | McNemar **p=0.004**, base 만 실패한 코딩 문항 **0개**, 4라운드 일관 |

그리고 세 가지가 겹친다.

1. **디코딩으로 고칠 수 없다.** `D_greedy` 가 장황함을 거의 없앴는데도(timeout 18→6, 시간 중앙 120→19.9초) 9문항 중 2개만 살았다. 모델이 그 문항들의 **코드를 못 쓰는** 것이고 장황함은 동반 증상이었다 ([`../yunsur_v8/05_conclusion.md`](../yunsur_v8/05_conclusion.md)).
2. **데이터 필터로도 못 잡는다.** v6 라운드의 소급 감사에서 자기 수정 표현이 있는 코딩 샘플은 307건 중 1건이었다.
3. **운영은 로컬 코딩을 쓰지 않는다.** Executor 는 `get_coding_groq_llm`, 즉 Groq 이다 ([`../protocol.md`](../protocol.md) §2.2). 네 라운드 동안 가장 많은 시간을 쓴 슬롯이 운영에 없는 슬롯이다.

자기 증류(base 출력으로 학습)로는 base 를 넘을 수 없다 — v4 결론에 적었고 그 뒤 다섯 라운드가 모두 같은 방향이었다. 코딩에서는 넘지 못한 정도가 아니라 **base 아래로 내려갔다.**

### 의도적으로 포기하는 것 (기록)

코딩을 빼면 **"로컬이 Groq 을 대신할 수 있나" 라는 질문을 포기한다.** Groq 이 끊기거나 비용 문제가 생기면 로컬 대체가 없다. 지금 그 대체는 base 보다도 나쁘므로 잃을 것이 없지만, 이것은 **포기하는 선택**이며 나중에 되돌리려면 v6 데이터가 그대로 남아 있다.

## 2. 가설

- **H1 (주): 코딩을 빼도 잡담·계획·RAG 는 나빠지지 않는다.** 이 세 슬롯이 운영이 쓰는 전부다. 코딩 300건이 다른 슬롯에 기여하고 있었다면 여기서 드러난다.
- **H2: 코딩 슬롯은 base 쪽으로 이동한다.** 코딩 데이터가 열화의 원인이었다면, 빼면 코딩 실패가 줄어야 한다. → v9 만 실패하는 코딩 문항이 v6 의 **9개보다 적다**. (틀리면 코딩 데이터가 원인이 아니었다는 뜻이므로 그 자체로 중요하다.)
- **H3: 학습은 138 스텝으로 끝나고 loss 궤적은 v6 와 비슷하다.** 데이터가 21% 줄었을 뿐 구성이 같으므로.

## 3. 판정 (사전 선언 — 결과를 본 뒤 바꾸지 않는다)

[`scripts/eval_round.sh`](../../../scripts/eval_round.sh) `yunsur_v9` 로 v9 와 base 를 같은 세션에서 재고 짝지어 비교한다 (54문항 × 3회, sha256 `a94d4708f9b6`).

- **통과 → 운영 최종본으로 채택**: 잡담·계획·RAG 에서 **v9 만 실패한 문항이 슬롯 전체 합쳐 1개 이하** (base 와 사실상 동률) **and** 코딩에서 v9 만 실패한 문항이 **9개 미만**.
- **부분 통과**: 세 슬롯은 동률인데 코딩이 여전히 9개 이상 → 코딩 데이터가 원인이 아니었다는 뜻. 운영에는 영향이 없으므로 v9 를 채택하되, 코딩 열화의 원인은 미해결로 기록한다.
- **실패**: 잡담·계획·RAG 에서 v9 만 실패한 문항이 **2개 이상** → 코딩 300건이 다른 슬롯에 기여하고 있었다는 뜻. **v6 를 운영에 유지**하고 감산을 되돌린다.

코딩 슬롯은 **참고로만 본다.** 운영이 쓰지 않으므로 채택 판단의 주 근거가 아니다. 다만 H2 의 검증에는 쓴다.

부수 비교로 v9 vs v6 도 본다 ([`scripts/eval_pairwise.py`](../../../scripts/eval_pairwise.py) 로 [`../baseline_0926/target.jsonl`](../baseline_0926/target.jsonl) 과 짝지음). **다른 밤의 측정이므로** 판정에 쓰지 않고 방향 확인에만 쓴다.
