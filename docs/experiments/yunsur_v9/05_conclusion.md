## 코딩 데이터가 원인이었다 — 해를 피한 정도가 아니다

| | 코딩 strict | v6/v9 만 실패 문항 | base 대비 McNemar p | `timeout` |
|---|---|---|---|---|
| v6 (코딩 300건 포함) | 46.7% | **9개** | **0.004** (유의) | 35 |
| **v9 (코딩 제거)** | **21.1%** | **1개** | **1.000** (유의하지 않음) | 13 |
| base | 15.6% | — | — | 5 |

코딩을 빼자 코딩 실패가 46.7% → 21.1% 로 떨어져 **base 와 통계적으로 구분되지 않는다.** 불일치도 2쌍뿐이고 방향이 각 1개씩으로 대칭이다 — base 는 `coding_12`(3/3 `timeout`), v9 는 `coding_29`(2/3 `runtime`·`syntax`). 어느 쪽도 체계적이지 않다.

**즉 코딩 학습 데이터가 코딩 열화의 원인이었다.** v5~v8 네 라운드가 데이터 필터·문항 확장·판정기 정렬·디코딩으로 찾아다닌 것을, **그 데이터를 없애는 것**이 해결했다. [`../prior_work.md`](../prior_work.md) 의 문헌과도 맞는다 — 자기 증류는 해당 능력을 base 아래로 끌어내리며, 모델이 작을수록 심하다.

다만 완전히 같아진 것은 아니다. `timeout` 이 v9 13건 vs base 5건으로 남아 있다. 장황함이 크게 줄었지만 base 수준은 아니다. 문항 단위로는 유의하지 않으므로 판정에는 영향이 없다.

## H3 을 정정한다 — loss 는 애초에 비교 대상이 아니었다

H3 에 "loss 궤적이 v6 와 비슷하다" 를 넣었는데 빗나갔다. v9 는 전 구간에서 높다 (train_loss v6 1.2522 → v9 **1.331**, 첫 loss 1.5996 → 1.6919).

방향은 설명된다. 코딩은 가장 짧은 슬롯이었고(output 중앙값 98자) `print(sorted([3,1,2]))` 류가 많아 맞추기 쉬웠다. 그것을 빼면 남은 데이터의 평균 난도가 올라간다 — 토큰 중앙값이 672 → 686 으로 오른 것과 같은 방향이다.

**애초에 데이터 구성이 다르면 loss 는 비교 대상이 아니다.** 그것을 예측에 넣은 것이 설계 실수였다. 판정은 §3 의 짝지은 비교로 했고 그쪽은 영향받지 않았다.

## 운영 결정

- **로컬 기본은 base `qwen3.5:9b` 유지.** 전체 10.5% vs v9 11.7% 로 차이가 없고(구간이 겹친다), 슬롯별로도 불일치가 코딩 2쌍뿐이다. 파인튜닝 모델로 전면 교체할 근거는 없다.
- **RAG 답변 슬롯: `yunsur_v6` → `yunsur_v9` 로 교체할 것을 권한다.** 근거는 성능 우위가 아니라 **단순함과 위험 제거**다:
  - RAG 실패율은 v6·v9 모두 0% 로 같고, literal `\n` 도 둘 다 0/24 다 (v6 의 이스케이프 수정이 v9 에 보존됐다).
  - v9 는 코딩 데이터를 싣지 않아 코딩 열화라는 **알려진 부채가 없다.** RAG 답변에 코드가 섞이는 경우에도 장황해질 이유가 줄어든다.
  - 잡담·계획에서도 v9 는 0% 다.
  - **다만 RAG 슬롯만 놓고 보면 측정된 우위는 없다.** 교체하지 않고 v6 를 두는 것도 정당하다 — 이것은 성능 판단이 아니라 정리 판단이다.
- **코딩은 계속 Groq.** 로컬 파인튜닝으로 코딩을 개선하려는 시도는 여기서 접는다 (§ 다음).

## 이 프로그램에서 끝난 질문

**"로컬 파인튜닝으로 코딩을 base 보다 낫게 만들 수 있는가" — 아니다.** v4~v9 여섯 라운드의 결론이다.

- 데이터 재설계(v5), 이스케이프 수정(v6), 문항·판정기 교정(v7), 디코딩(v8) 모두 실패했다.
- 성공한 것은 **코딩 학습을 포기하는 것**(v9)이었고, 그 결과는 "base 만큼" 이다.
- 자기 증류로는 구조적으로 불가능하다는 것이 문헌과 우리 측정에서 일치한다.

되돌리려면 v6 데이터와 모델이 그대로 남아 있다.

## 남은 후보 (v10 — 착수하지 않음)

[`../prior_work.md`](../prior_work.md) §4 의 미시험 축이 남아 있다. 다만 **이제 겨냥할 대상이 없다** — 운영이 쓰는 세 슬롯은 이미 0% 이고 base 와 불일치가 0개다. 개선할 여지가 측정에 나타나지 않는다.

- 낮은 학습률: 데이터 비용 0, 학습 1회. 그러나 무엇을 개선할지 불분명하다.
- 일반 데이터 replay: 코딩을 다시 실으려 할 때만 의미가 있다.
- 더 강한 교사로 교차 증류(Gemini·Groq): 자기 증류의 상한을 깨는 유일한 방향. 코딩을 다시 시도할 근거가 생기면 여기서 출발한다.

**v10 을 열 근거가 현재 측정에는 없다.** 새 요구(새 슬롯, 새 도메인)가 생기면 그때 프로토콜([`../protocol.md`](../protocol.md))에 따라 연다.
