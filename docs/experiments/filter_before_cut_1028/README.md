# 관련 문서 거르기를 상위 5 자르기 앞으로 (사전 등록, 2026-10-28)

> 측정 **전에** 쓴다. 출발점: user_suite_1027 `cut_diag.py` — U1-4 정답 FactSelfCheck · Finch-Zk 는 운영 `rag.search(top_k=15)` 에서 8 · 12 위인데 `agent_nodes.py` 의 상위 5 자르기(`_rag_context_top_n_hits(n=5)`)에서 빠지고, 남은 5 편은 관련 문서 거르기가 1 편만 남겼다(5→1). 같은 거르기에 15 편을 주면 15→3 으로 정답 둘 다 남는다.

## 1. 바꾸는 것 — `RAG_FILTER_BEFORE_CUT=1` (기본 0, `RAG_RELEVANCE_FILTER=1` 일 때만)

`core/graph/agent_nodes.py` direct_answer 의 일반 경로(목록 · 단일 논문 · 이어지는 질문 재사용이 아닌 경우)에서:

- 대조: 15 편 → 상위 5 자르기 → `filter_relevant`(5 편).
- 처리: 15 편 → `filter_relevant`(15 편) → 남은 것 중 앞 5 편. 뒤의 거르기는 건너뜀(두 번 거르지 않음).
- 거르기가 못 읽음 · 없음 · 호출 실패면 15 편 그대로 → 앞 5 편(= 대조에서 거르기 실패와 같음).
- 목록 모드(10 편 검색 · 10 편 거르기)와 라우터 컨텍스트 재사용(5 편)은 바뀌지 않는다.

## 2. 방법 (맥미니, 검색 + 거르기 — `--answer` 없음, 운영 설정 그대로)

대조 `fb0_*` · 처리 `fb1_*`(`RAG_FILTER_BEFORE_CUT=1`): 정답 있는 세트 162 · real40 · real2 + held-out 30(H) · 직무 34(D) · 사용자 34(U). 스크립트 `.cron/run_fb.sh`.

- **관련성 판정(주 지표):** H · D · U 두 조건 컨텍스트 논문 중 아직 판정 안 된 쌍만 섞어 조건을 모른 채 0 · 1 · 2 판정(2 = 질문을 직접 다룸). 이미 판정된 쌍(corpus_seed `.cron/cs/judged_*` · query_norag_1027 · fusion_protect_1027)은 재사용. `pool.py` · `score.py`.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** H + D + U (98) — 질문별 컨텍스트 '2' 논문 수 | 처리 > 대조, 부호 검정(동점 제외) 양측 p < 0.05 |
| 보호: 정답 있는 세트 검색 ok (162 + real40 + real2) | 처리가 대조보다 3 이상 낮지 않음 |
| 보호: 질문별 '0' 논문 수(H + D + U 합) | 처리가 대조의 1.5 배 이하 |
| 보호: 문항당 시간 중앙값(H + D + U, 답변 스텁) | 처리 − 대조 ≤ 10 s |
| 보고: U1-4 정답 컨텍스트 여부 · 컨텍스트 편수 분포 · 거르기 상태(못 읽음 등) 수 | |

보호 미달이면 주 지표 판정 없이 기각. 채택이면 사용자 승인 후 운영 `.env` 반영 + 봇 재시작.

예상: 처리는 남는 편수가 늘어(대조는 5 편 중 거르기 뒤 1–3 편) '2' 가 늘 수 있지만 거르기가 15 편 중 관련 없는 것을 놓치면 '0' 도 는다. 거르기 입력이 3 배(약 600 자 × 15)라 호출 시간이 는다. 답변 품질은 재지 않는다 — 채택 전 실제 답 몇 개를 본다.
