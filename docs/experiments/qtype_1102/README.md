## 0. 왜

정답 유무 판정 · 목록 모드 · 비교 분리 세 게이트가 `core/llm/presence_judge.gate_types` 정규식으로 갈린다.

- 수치 · 비교 · 목록이면 판정을 건너뛴다(`RAG_PRESENCE_GATE`).
- 목록이면 10편 다시 검색 · 짧은 블록 · 번호 칸(`RAG_LIST_MODE`).
- 비교면 두 대상을 따로 검색해 앞에 붙인다(`RAG_COMPARE_SPLIT`).

실사용에서 말투가 바뀌면 틀렸다.

- 137 · 139: "모델과 … 다른 / 달라지는" → 비교 → "GPT-4" 한 단어를 따로 검색.
- 140(11-02 16:48): "1.0% vs 11.4%" → 수치 · 비교. "3가지 주제에 해당하는 최신 연구를 찾아주세요" 인데 목록 모드가 안 켜져 5편으로 답했다(`.bridge/rag_trace.jsonl` judge `gates: num, cmp`).
- 134–136: "…연구에 대해서 조사해줘" → 목록을 놓쳤다.

## 1. 라벨 — 측정 전

- 모은 것: 실사용 브리지 DB 140 job + 평가 질문 세트 36 파일. 같은 글은 하나로 했다(`collect.py` → `all.tsv`).
  - held-out(`foundation_1031/heldout.tsv` · `heldout_followup.tsv`) 100 은 test, 나머지 847 은 dev.
- 규칙: 질문의 **요청 부분**에 단다. 전제 · 배경 문장은 보지 않는다.
  - **L 목록 · 조사** — 여러 논문을 나열해야 맞는 요청.
    - 표지가 있다: …들 · N개 · N편 · 여러 · 목록 · 정리해 · 조사해 · 동향 · 트렌드 · 추천 · "연구 중 …만" · 연도 조건 + 분야.
    - 또는 분야 단위다("의료 분야에 RAG를 적용한 연구 찾아줘").
    - 또는 서로 다른 갈래 둘 이상이다("공격 기법이나 방어 기법 연구 알려줘").
  - **C 비교** — 두 대상을 서로 맞대 묻는다("A랑 B 차이가 뭐야" · "어떻게 달라" · "A vs B" · "A랑 B 중 뭐가 나아").
    - "…를 비교한 연구 있어/알려줘" 는 그 연구를 찾는 질문이라 C 가 아니다.
    - "차이가 얼마나" 는 N 이다.
  - **N 수치** — 답으로 숫자를 묻는다(몇 % · 몇 배 · 몇 개 · 얼마나 줄었어/빨라 · 얼마야).
    - 전제의 숫자, 방법 설명 속 "얼마나 일치하는지로" 는 N 이 아니다.
  - **F 이어짐** — 앞 답을 가리킨다(그거 · 그 중 · 두 번째 · 다른 논문도).
  - **'-'** — 특정 연구 · 개념 질문(판정 대상). 초안의 "특정 논문" · "개념" 은 어느 게이트도 가르지 않아 하나로 둔다.
  - **X** 질문 아님(날씨 · 인사 · 도구 · 영어 검색어 문자열), **?** 애매("…연구 찾아줘" 가 분야인지 특정 연구인지 못 가름). 둘 다 학습 · 평가에서 뺀다.
- dev 847: 쓸 것 769 = '-' 392 · L 251 · N 61 · C 49 · F 13(F- 10 · FL 3) · LN 3. 뺀 것 X 57 · ? 21.
- held-out 100(`test_labels.txt`, sha1 `f54951098aa1f5e03f0c42a07244e4f28cb18c5c`): '-' 50 · L 25 · N 10 · C 7 · F 5 · LN 1 · ? 2.
  - 분류기를 held-out 에 돌리기 **전에** 고정했다.
- 판정자 1명(Claude)이고 질문 작성자와 같다.

## 2. dev 진단 — 세트 하나씩 빼는 교차 검증(15 세트)

분류기는 글자 1–4 · 낱말 1–2 n-gram TF-IDF 로지스틱 회귀다(C=10, balanced). 6 변형(특징 3 × C 2) 중 골랐다.

| 유형 | 라벨 참 | 정규식 틀림(FP · FN) | 분류기 | 정규식 ∨ 분류기 |
|---|---|---|---|---|
| L 목록 | 257 | 53 (3 · 50) | 44 (5 · 39) | **34** (6 · 28) |
| C 비교 | 49 | 37 (35 · 2) | **11** (1 · 10) | 37 |
| N 수치 | 64 | 26 (20 · 6) | **15** (2 · 13) | 23 |
| F 이어짐 | 13 | **13** (12 · 1) | 9 (0 · 9) | 13 |

- 이어짐은 분류기가 13 중 9 를 놓친다. 놓치면 앞 대화를 못 쓰니 비싼 쪽 오류다 → 정규식(`is_followup`) 유지.
- 세 결정(판정 건너뜀 · 목록 · 비교 분리)이 바뀌는 문항은 87/769(11%)다.
  - 분류기 쪽만 라벨과 맞음 65 · 정규식 쪽만 19.
  - 꼴: 판정 켜짐 + 분리 꺼짐 30 · 목록 켜짐 24 · 판정 켜짐 18 · 분리만 꺼짐 12 · 기타 3.
- 정규식이 놓친 꼴: 조사해줘 · 연도 조건 목록 · N편 · 추천 · "연구 중 …만". 잘못 잡은 꼴: "비교한 연구", 주제 속 "수치" · "정확도가", 전제 속 %.
- 스크립트는 `diag.py`(결정별 오류 목록) · `diag2.py`(유형별 변형) · `diag3.py`(바뀌는 문항)이다.

### 4.1 1단계: 유형 정확도 (held-out 100)

- 문항마다 세 결정이 라벨과 모두 맞는지 정규식 · 분류기 각각 본다('?' 2 뺌).

### 4.2 2단계: 끝단 품질

- 문항: 세 결정이 바뀌는 held-out 문항 + 새 held-out 54(`heldout_new.tsv`) 중 결정이 바뀌는 문항.
  - 새 54 는 이 사전 등록과 같이 썼다. DB 는 보지 않았고 실사용 꼴이다.
  - 꼴: 전제 · 복합 12 · 여러 주제 목록 6 · 조사 말투 8 · "비교한 연구 있어?" 8 · 주제에 '수치 · 정확도가 · %' 6 · 목록 조건 · 추천 6 · 정규식에 없는 수치 말투 4 · 정규식에 없는 비교 말투 4.
  - 기존 질문 947 과 SequenceMatcher 0.75 미만이다(넘은 2문항은 바꿨다). 라벨은 `heldout_new_labels.txt`.
  - 이어지는 질문 쌍은 a · b 중 하나라도 바뀌면 `--keep-session` 으로 쌍째 돌리고 바뀐 쪽을 판정한다.
- 조건: 대조 `qt0_*`(`RAG_QTYPE_CLF=0`) · 처리 `qt1_*`(`=1`). 나머지는 운영 `.env` 그대로, `eval_e2e_ko.py --answer --save-context`.
- 판정: 문항마다 두 답을 A/B 무작위로 섞는다(열쇠는 판정 뒤 연다). 질문 · 두 답 · 각 답의 컨텍스트를 보고 아래 순서로 고른다.
  1. 사실 오류(인용 블록과 어긋나거나 블록에 없는 내용을 논문 결과로 쓴 문장)가 확연히 적은 쪽.
  2. 같으면 질문에 맞게 답한 쪽. 목록 요청엔 관련 논문 여러 편, 특정 연구 질문엔 그 연구(없으면 맞는 '없음' 고지), 수치 질문엔 문서의 수치(없으면 고지), 비교엔 양쪽.
  3. 같으면 인용 논문 관련성. 질문 주제를 바로 다룬 논문이 많고 무관한 논문이 적은 쪽.
  4. 그래도 같으면 동점.
  - 답마다 무관 인용 수('0')와 거짓 '없음'(컨텍스트에 찾는 연구가 있는데 없다고 함)도 같이 센다.

| 지표 | 기준 |
|---|---|
| **주:** 바뀐 문항 승패 | 처리 승 > 대조 승, 부호 검정(동점 제외) 양측 p < 0.05 |
| 보호 1: 무관 인용 '0' 합 | 처리 ≤ 대조 × 1.5 |
| 보호 2: 거짓 '없음' | 처리 ≤ 대조 + 1 |
| 보호 3: 응답 시간 중앙(바뀐 문항) | 처리 ≤ 대조 + 20s |
| 보고: 꼴별 승패 · 인용 편수 · '없음' 답 수 · 단계별 시간 | |

- 문항 수(§2.5): held-out 바뀜 ~11(dev 비율) + 새 54 중 ~40 → ~50. 동점이 ~30% 면 동점 뺀 ~35 다. 2:1 효과면 37 에 조금 모자라고 3:1 이면 넉넉하다.
- 채택: 1단계 관문 · 주 지표 · 보호 1–3 을 모두 넘으면 **사용자 승인 뒤** 운영 `.env` `RAG_QTYPE_CLF=1` + 봇 재시작.
- 라운드 뒤: 새 54 는 dev 로 옮긴다. 판정에 쓴 held-out 문항은 실패를 보고 고치지 않으면 그대로 둔다(protocol §2.5).
