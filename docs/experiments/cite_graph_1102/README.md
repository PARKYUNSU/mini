# 인용 그래프로 원논문 빈칸 미리 채우기 — R2 (사전 등록, 2026-11-02)

> 측정 **전에** 쓴다. 후보 목록도 이 문서를 커밋한 **뒤에** 만든다.
>
> 출발점: 10-31 방향 초안의 R2. 실사용 job 137–139(10-30)가 물은 원논문(G-Eval · FActScore · MT-Bench 판정)이 DB 에 없었다. 그래서 답이 엉뚱한 논문에 질문 전제를 붙였다. [corpus_llmeval_1030](../corpus_llmeval_1030/README.md) 은 그 분야만 채웠다. R2 는 분야를 가리지 않고 같은 빈칸을 **미리** 채운다. DB 논문들이 많이 인용하는데 DB 에 없는 논문을 넣는다.
>
> held-out 에도 같은 빈칸이 있다. '이름으로 묻기' 14문항 중 5문항의 정답이 DB 에 없다: Toolformer · RankGPT · BGE M3 · Medusa · FlashAttention.

## 0. 사전 조사 (읽기만 · 후보 목록은 보지 않음)

- **OpenAlex `referenced_works`**(초안의 방법)는 쓰지 않는다.
  - DB 무작위 50편(시드 1101)을 arXiv DOI 로 한 번에 찾았다. 49편이 나왔지만 참고문헌이 있는 것은 7편이었다(중앙 0).
  - arXiv 판 레코드에는 참고문헌이 거의 없다. 인용이 많은 고전은 학회판과 합쳐져 arXiv DOI 로 안 찾히기도 한다. 원논문 확인 때 HyDE · Reflexion · vLLM 등 9편이 그랬다.
- **DB 본문에서 뽑는다.** JSONL `content` 에는 참고문헌이 남아 있다.
  - 같은 50편 중 40편에서 arXiv ID 인용이 잡혔다(논문당 중앙 8). 외부 호출이 없다.
  - 한계: arXiv ID 없이 학회 이름으로만 적힌 인용은 못 센다.
- **OpenAlex 비용:** 필터 조회는 1회 $0.0001 이다(하루 $1 = 10,000회). 검색 1회($0.001)보다 싸다. 이번 라운드는 원논문 ID 확인에 1회만 썼다.
- **분야:** 초안은 '분야별 상위 N'이었다. 하지만 DB 논문 7,797편 중 6,448편(83%)에 분야 꼬리표(`target_topic`)가 없다. 그래서 전체 순위로 고르고, 분야(arXiv 주 분류)는 보고만 한다.
- **`.bridge/external_candidates.jsonl`**(초안의 두 번째 출처)은 쓰지 않는다.
  - 평가 실행도 이 파일에 쌓는다(1,483줄, held-out 질문 포함).
  - 그대로 쓰면 판정 세트에 맞춰 고르는 셈이다. 후보와 겹치는 수만 보고한다.

## 1. 바꾸는 것 — 코퍼스에 논문 추가 (코드 · 설정 변경 없음)

**후보 규칙** (`candidates.py` — 측정 전 고정, 손으로 고르지 않는다)
1. DB 논문은 운영 Chroma 의 paper_id 7,797편이다. BM25 와 같다(chroma_gap_1101 뒤 빠짐 0).
2. 논문마다 JSONL 본문에서 arXiv ID 를 뽑는다.
   - `arxiv` · `abs/` · `corr` 뒤에, 숫자 없이 25자 안에 오는 새 꼴 ID(0704~2611)만 센다.
   - 자기 ID 는 뺀다.
3. 외부 논문마다 **그것을 인용한 DB 논문 수**를 센다.
4. 이미 DB 에 있는 논문을 뺀다. 인용 수 내림차순으로(같으면 ID 순) **N = 200편**을 고른다.
   - arXiv API 에 없는 ID 는 건너뛰고 다음 순위로 채운다.
5. 결과는 세 파일이다: `candidates.json`(순위 · 인용 수 · 제목 · 초록 · 분류) · `candidates.yaml`(수집 입력) · `ranked_top1000.tsv`.

N = 200 인 이유:
- 시간: 수집은 논문당 약 30~40초라 200편이면 약 2시간이다. 임베딩 캐시 재생성도 약 2시간 걸린다(11-01 6,928초). 여기에 전 · 후 측정(각 약 3.5시간)까지 01:00 수집 사이 하루 안에 들어가는 크기다.
- 검정력: 원논문이 DB 에 없는 held-out 17문항만 늘어날 수 있다(§3). 목록을 보기 전이라 그중 몇 편이 상위 N 에 드는지 모른다. N 이 작으면 늘어남이 관문(§4)에 못 미칠 수 있다.

**수집** (사용자 승인 뒤 — 후보 목록을 보고 따로 받는다)
- `ingest.sh` 가 순서대로 돈다:
  1. 수집 전 측정이 끝나기를 기다린다.
  2. `apps.backfill.ingest_classics --yaml candidates.yaml` 로 수집한다. 매일 수집과 같은 경로라 운영 Chroma 와 JSONL 에 쓰고, 쓰기 잠금을 건다.
  3. 임베딩 캐시를 다시 만든다(`scripts/build_emb_cache.py`).
  4. 수집 후 측정을 한다.
- 받지 못한 논문은 기록만 한다.
- 봇 BM25 는 프로세스가 시작할 때 JSONL 을 한 번만 읽는다. 운영 봇이 새 논문을 BM25 · 이름 찾기로 보려면 재시작이 필요하다(따로 승인). 측정은 새 프로세스라 재시작과 상관없다.

## 2. 측정 — 검색만(`--save-context`, 운영 경로)

- 라벨: 수집 전 `cg0_*` · 수집 후 `cg1_*`.
- 세트: held-out 90 · 162 · real40 · real2 (`run.sh 0|1`). 조건마다 약 3.5시간 걸린다.
- 같은 코퍼스: 전 · 후 측정을 **같은 01:00 수집 사이**에 끝낸다.
  - 전 측정은 11-02 01:00 수집과 캐시 재생성이 끝난 뒤 시작한다(`wait_run0.sh`).
  - 후 측정이 다음 01:00 을 넘기면 둘 다 다시 잰다.
- 실행마다 앞뒤로 쓰기 잠금과 청크 수를 본다. 같은 조건 안에서는 청크 수가 같아야 한다.

## 3. 원논문 정답 — `orig.jsonl` (후보 목록을 만들기 전에 고정)

- B(이름으로 묻기) 14문항: `heldout_gold.jsonl` 그대로 쓴다.
- A(특정 연구 찾기) 24문항 중 16문항: 원논문이 한 편(또는 동시 제안 한 묶음)으로 정해지는 문항에 arXiv ID 를 붙였다.
  - 뺀 8: A05 표→SQL · A06 프롬프트 압축 · A15 데이터 오염 · A16 웹 에이전트 벤치마크 · A17 장기 기억 · A20 하위 질문 멀티홉은 원논문이 여럿이다. A23 · A24 는 DB 밖 주제다.
  - 묶음 3: A11 speculative decoding(2211.17192 · 2302.01318) · A21(RepoCoder · Repository-Level Prompt Generation) · A22(ColPali · Document Screenshot Embedding).
- ID 는 arXiv API · OpenAlex 제목으로 확인했다.
- 지금 DB 상태로 나누면:
  - 원논문이 DB 에 있는 문항 13: 줄어듦만 가능하다.
  - 없는 문항 17: 늘어남만 가능하다. B06 · B09 · B11 · B12 · B13 · A01 · A02 · A04 · A08 · A09 · A10 · A11 · A12 · A13 · A14 · A19 · A21.
- held-out 은 판정 전용이다. 이 정답은 측정 전에 붙였고, 실패를 보고 고친 것이 아니다.
- 질문 작성(10-31) 때는 DB 를 보지 않았다. 정답을 붙인 Claude 는 DB 고전 목록(`apps/backfill/classics.yaml` 29편)과 위 30편의 DB 유무를 보았다. 후보 목록은 보지 않았다.

## 4. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** held-out 원논문 30문항 — 컨텍스트에 원논문이 든 문항 | 늘어남 > 줄어듦, 부호 검정(동점 제외) 양측 p < 0.05 |
| 보호 1: 검색 ok 162 · real40 · real2 | 각 세트 후가 전보다 3 이상 낮지 않음 |
| 보호 2: held-out 90 수집 후 컨텍스트에 든 수집 논문 자리 — 관련성 '0' 비율 | 1/3 이하 (제목 + 초록으로 0 · 1 · 2, 판정자 Claude 1명) |
| 보고 | 후보 수 · 수집 성공 · 실패 · 세트별 수집 논문 자리 · 경로 다름 · 컨텍스트 바뀜 · 시간 · 검색 중앙 · 분류 분포 · 원논문 17편 중 후보에 든 수 · external_candidates 겹침 |

- §2.5 문항 수: 늘어날 수 있는 문항은 17이다.
  - 줄어듦이 0이면 늘어남 6 이상이어야 통과한다(6 : 0, p 0.031).
  - 줄어듦이 1이면 8 이상(8 : 1, p 0.039), 2이면 10 이상(10 : 2, p 0.039)이어야 한다.
  - 효과는 한쪽으로 크게 기울 것으로 본다. 4 : 1 이상이면 동점 뺀 12문항이면 된다.
- 채택: 수집분을 그대로 두고, 봇 재시작을 따로 묻는다.
- 기각: 수집분을 지울지 사용자와 정한다. 지우기도 운영 쓰기다.

예상:
- B 5문항은 후보에 들면 이름 찾기(`RAG_NAME_LOOKUP`)로 거의 확실히 들어온다.
- A 는 9B 영어 검색어가 분야 용어를 만드느냐에 달렸다.
- 위험은 인용이 많은 넓은 논문(모델 기술 보고서 등)이 다른 질문의 컨텍스트를 차지하는 것이다. 보호 1 · 2 가 이를 본다.
