> 측정 **전에** 쓴다. dev 전용이다(판정 아님). 출발점: [allenai/asta-paper-finder](https://github.com/allenai/asta-paper-finder) 코드 비교(11-04). 그쪽은 문서마다 초록 1,500자 + 매칭 청크를 보고 판정한다. 우리 거르기(`core/llm/relevance_filter.py` `_brief`)는 제목 + 본문 앞 600자만 본다.
>
> - 저장된 답 3세트의 초록 있는 블록 520 중 420(81%)은 초록이 600자를 넘는다(초록 길이 중앙 1,194자). 이 블록들은 초록 뒷부분과 매칭 청크를 거르기가 못 본다.
> - [list_findings_1023](../list_findings_1023/README.md) 에서 초록 앞 500자는 배경 문장뿐이라는 것을 봤다. 목록 모드는 이미 `brief_findings` 를 쓴다. 일반 경로 거르기는 아직 앞부분을 본다.
> - [topic_filter_1104](../topic_filter_1104/README.md): 9B 거르기 정밀도 49.3% · 재현율 82.6%. 라벨로 완벽하게 거르면 주제 밖 문서가 27.7% → 3.0% 다.
>
> 사용자 결정(11-04): 이 측정을 먼저 한다.

## 1. 바꾸는 것 — `RAG_FILTER_FINDINGS=1` (기본 0)

`_brief` 의 본문을 `[초록] ` + `brief_findings(초록, 595)` 로 바꾼다. 제안 · 결과 · 대상 문장을 원래 순서로 고른다. 길이 상한 600자 · 프롬프트 · 호출 횟수 · `num_predict` 는 그대로다. 초록이 없는 블록은 지금처럼 앞 600자를 쓴다. 단일 변수다.

## 2. 방법 ([`run.py`](run.py))

- **문항:** real40 · real2 · H · D · U · HU40 · HT30(모두 dev)에서 일반 경로 155문항(17 · 14 · 25 · 19 · 19 · 36 · 25). 목록 경로는 입력이 이미 요지 문장이고, 비교 경로는 대상 검색이 더 붙어서 뺀다. 단일 경로는 거르기를 안 탄다.
- **문항마다:** `_extract_english_rag_query` → `rag.search(top_k=15, name_query=질문)` 한 번으로 15편을 고정한다 → 두 조건으로 `filter_relevant`(운영 답 모델, temperature 0, seed 0) → `_rag_context_top_n_hits(n=5)`. 조건 순서는 문항마다 바꾼다.
- **대조 재실행:** 4문항마다 대조를 한 번 더 돌려 같은 입력에서 최종 5편이 얼마나 바뀌는지 잰다.
- **라벨:** 두 조건의 최종 5편이 다른 문서만 단다. `run.py packet` 이 조건을 적지 않고 seed 1104 로 섞어 내고, 라벨을 다 달기 전에는 어느 조건 문서인지 보지 않는다. 제목 + 초록 앞 1,500자를 보고 [topic_judge_1024](../topic_judge_1024/README.md) 등급으로 매긴다: **2** 질문에 직접 답하는 연구(여러 주제 질문은 하위 주제 하나를 직접 다루면 2) · **1** 같은 주제지만 질문의 조건 · 대상과 다름 · **0** 무관.
- **기존 라벨을 안 쓰는 이유:** `labels_hu` · `labels_pool` 은 앞 320~500자를 보고 달았다. 앞부분을 보는 대조에 유리하다.
- **한계:** 라벨은 Claude 혼자 단다. 운영 코드 경로를 그대로 부르지 않고 같은 함수를 순서대로 부른다(라우터 · 판정 · 답 없음). 비교 · 목록 경로는 이 dev 에서 재지 않는다.

**문항 수 (protocol §2.5):** 예상 효과 3:1, 예상 동점 70%. 155문항이면 동점 뺀 문항이 약 46이고, 2:1(37 필요)까지 잡는다.

## 3. dev 관문 — 측정 전 고정

| 지표 | 기준 |
|---|---|
| **주:** 문항별 최종 5편의 '2' 수 | 처리 > 대조, 부호 검정(동점 제외) **양측 p < 0.05** |
| 보호 1: 최종 5편의 '0' 문서 합 | 처리 ≤ 대조 + 2 |
| 보호 2: 정답이 최종 5편에 든 문항(real40 · real2 · H · D · U) | 처리 ≥ 대조 − 2 |
| 보호 3: 대조 3편 이상인데 처리 3편 미만인 문항 | ≤ 4 |
| 보호 4: 거르기 `못 읽음` · `호출 실패` | 처리 ≤ 대조 + 2 |
| 보호 5: 거르기 호출 시간 중앙 | 처리 ≤ 대조 + 2s |
| 신뢰 조건: 대조 재실행에서 최종 5편이 달라진 문항 | ≤ 10% — 넘으면 이 비교를 믿지 않는다 |

- 모두 통과하면 held-out(`foundation_1031/heldout.tsv`)을 따로 사전 등록하고 사용자 결정을 받는다. dev 통과는 채택 근거가 아니다.
- 미달이면 접는다. 플래그는 기본 0 그대로 두고, 문서당 판정 라운드는 새 맥미니 뒤로 미룬다.

재지 않는 것: 답 단계. 운영 `.env` · 봇은 건드리지 않고 Chroma 는 읽기만 한다.
