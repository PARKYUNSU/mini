# 결론 문장 대조 검사 — 1단계 오프라인 선별 (사전 등록, 2026-11-01)

> 측정 **전에** 쓴다. 출발점: answer_review_1030 §6 — 10-31 재질문에서 결론 다시 쓰기("바꿈")가 질문 전제를 논문 결과처럼 썼고(137), 논문 내용을 뒤집었다(139 3건). answer_judge_1024 기준선: 결론 주장의 정확 51%, 사실 오류 16% · 과장 8%(본론 84%). 지금 결론 검사(`check_conclusion`)는 인용 · 길이 · 한자 · 숫자만 본다. 형태 규칙(묶음 · 일반화 · 이름 오귀속)은 기각 · 중단됐다 — 옳은 문장과 틀린 문장을 형태로 못 가른다(conclusion_drop2_1025 · conclusion_overgen_1025 · conclusion_misattr_1025). 이번에는 **9B 가 문장 내용을 인용 블록과 대조**한다. 1단계는 이미 판정한 문장으로 검사기가 오류를 가려내는지만 잰다.

## 1. 검사기 (오프라인만 — 운영 코드 · `.env` 변경 없음)

- 결론 문장마다 그 문장이 인용한 논문 블록(컨텍스트 원문, 블록당 2,500자 — 결론 다시 쓰기의 `_BLOCK_MAX`)만 보여 주고 9B 에게 **같음 · 다름 · 없음**을 묻는다. 모델은 운영 보조 모델 `RAG_HELPER_MODEL`(yunsur_v13, 답변 모델과 같아 교체 없음), temperature 0 · seed 0.
- **질문은 보여 주지 않는다** — 질문 전제에 끌리지 않게(137 의 새어 듦).
- 다름 · 없음이면 지울 문장으로 친다. 못 읽거나 호출이 실패하면 남긴다.
- 프롬프트 두 가지를 둘 다 잰다(`offline.py`, 측정 전 고정):
  - **V1 판정만** — 출력 한 줄 `판정: …` (num_predict 12).
  - **V2 원문 먼저** — 뒷받침하는 원문 구절을 영어 그대로 옮긴 뒤 판정 (num_predict 200).
- **인용 없는 문장**("두 방법은 … 결과가 달라진다" 류)은 같은 결론이 인용한 블록 전부와 대조한다 — **보고만**. 결론에 인용이 하나도 없으면 건너뛴다.

### 5.4 판정

고친 V1 이 두 주 기준을 넘었다 → §3 대로 **2단계를 따로 사전 등록할 후보**. V2 는 기각. 운영 코드 · `.env` 는 바뀌지 않았다.

그대로 받아들이기 어려운 점 — 2단계 설계에 넣는다:
- 여유가 0이다. 오류 하나나 O 하나만 라벨이 바뀌어도 미달이다. 중복 문장 65 중 14 가 라운드마다 다른 라벨을 받았을 만큼 라벨 잡음이 있고, 통과는 결과를 보고 고친 실행에서 나왔다.
- 지운 문장 33 중 오류 18 · O 14 · ? 1 — 지운 문장 둘 중 하나 가까이가 맞는 문장이다. O 가 오류보다 4배 많아 "O 지움 ≤ 10%" 가 이 비용을 작게 보이게 한다.
- 검사기는 문장을 지우기만 하므로 답마다 결론 E + X 수는 늘 수 없다(인용 문장이 다 지워져 다시 쓰기 전 결론으로 돌아갈 때만 빼고). §3 에 적은 2단계 주 지표(E + X 수 부호 검정)는 한쪽으로 기운다 → 2단계 주 지표는 **지운 문장 중 오류 대 정확**처럼 잃는 것까지 세야 한다(지운 문장과 남긴 문장을 섞어 눈가림 판정).
- 실제로 문제였던 뒤집기(R_139 3건)를 못 잡는다(§5.5).

## 6. 2단계 문항 수 추정 (11-01, 사용자 "2단계 등록" 뒤 — 등록 전 검토)

2단계 주 지표를 **답마다 결론 오류 비율** (E + X + U) / (O + E + X + U) 의 전 · 후로 잡는다. 정확한 문장을 지우면 비율이 올라가므로 한쪽으로 기울지 않는다(§5.4). 1단계 표본 결론 106개에 고친 V1 판정을 그대로 대 보면:

| 결론 | 수 |
|---|---|
| 인용 문장 없음 (검사 안 함) | 16 |
| 인용 문장이 다 지워짐 → 다시 쓰기 전 결론으로 (라벨 없음) | 2 |
| 좋아짐 | 10 |
| 나빠짐 | 5 |
| 같음 (지운 것 없음 · 오류 없는 결론에서 O 만 지움 등) | 73 |

- 효과 2:1(10:5, p 0.30), 동점 아닌 결론 17%. protocol §2.5(2:1 효과면 동점 뺀 37)를 채우려면 검사 대상 결론이 ~220개 필요하다. held-out 90문항이면 동점 아닌 결론이 ~10개뿐이라 판정이 안 난다.
- 제대로 하려면: held-out 질문을 ~220 더 쓴다(held-out 은 90뿐이고, dev 세트는 1단계 라벨 · 버그 수정에 쓰여 판정에 못 쓴다). 맥미니 ~7시간 걸린다. 지운 문장이 있는 답과 같은 수의 미끼 답 ~110개(~440문장)를 판정한다.
- 이득 추정: 검사 대상 결론 100개 중 좋아짐 ~11 · 나빠짐 ~6 — 순 ~5개. 답마다 +9.1s 걸리고, 뒤집기(R_139)는 못 잡는다.
