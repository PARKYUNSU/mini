# 실험 노트 — yunsur_v8: 디코딩으로 "종료하지 못하는 행동" 을 억제할 수 있는가

- 시작일: 2026-09-26
- 선행: [`../baseline_0926/`](../baseline_0926/) — 출력 상한을 운영과 정렬한 뒤에도 v6 는 코딩에서 base 보다 유의하게 나쁘다 (v6만 실패 9문항, base만 0, McNemar **p=0.004**).
- **범위: 학습 없음.** 디코딩 설정만 바꿔 측정한다. 모델·학습 데이터·문항 집합은 그대로다
- 측정: [`scripts/eval_decoding_sweep.sh`](../../../scripts/eval_decoding_sweep.sh), 표적 9문항 × 3회 × 5팔

## 1. 문제 정의

v6 의 코딩 실패 42건 중 **35건이 `timeout`** 이다 (120초 안에 답을 못 끝냄). base 는 6건이다.

출력 상한을 800 → 4096 으로 5.1배 줬을 때 일어난 일이 진단을 확정했다.

| | 상한 800 | 상한 4096 |
|---|---|---|
| v6 코딩 실패 | 36건 — `syntax` 24 · `runtime` 10 | 42건 — **`timeout` 35** · `runtime` 5 |
| 펜스 미닫힘(잘림 신호) | 16건 | **2건** |

`syntax` 가 `timeout` 으로 **라벨만 옮겨갔다.** 토큰이 모자라서가 아니라 모델이 멈추지 않는다 — 벽을 옮겨주면 새 벽까지 쓴다.

이 행동은 학습 데이터에 없다. v6 라운드의 소급 감사에서 자기 수정 표현이 있는 코딩 샘플은 307건 중 1건이었다 ([`../yunsur_v6/README.md`](../yunsur_v6/README.md) §4). 데이터 필터로 잡을 대상이 없으므로 **생성 시점** 을 본다. 디코딩은 학습이 필요 없어 가장 싸다.

## 2. 실험 설계

표적은 `baseline_0926` 에서 **v6 만 실패한 코딩 9문항**이다: `coding_07` `coding_19` `coding_21` `coding_22` `coding_25` `coding_26` `coding_27` `coding_28` `coding_30`. 전체 30문항 대신 이 9개만 재서 비용을 1/3.3 로 줄인다.

| 팔 | 설정 | 무엇을 시험하는가 |
|---|---|---|
| `base_ref` | base 모델, 현행 디코딩 | 표적 문항이 망가지지 않았는지 — base 는 정의상 9문항을 통과해야 한다 |
| `A_control` | t0.2 p0.8 rp1.18 | `baseline_0926` 을 만든 설정. 재현 확인 |
| `B_rp135` | rp **1.35** | 자기 수정 서술은 반복적이다 — 반복 페널티를 올리면 루프가 끊기는가 |
| `C_narrow` | t **0.1** p **0.5** k **20** | 샘플링을 좁히면 헤매지 않는가 |
| `D_greedy` | t **0.0** | **진단용**: 그리디에서도 멈추지 않으면 샘플링의 흔들림이 아니라 **모델의 최빈 경로 자체**가 장황하다는 뜻이다 |

`D_greedy` 가 이 스윕에서 가장 정보량이 많다. 결과가 어느 쪽이든 원인을 좁힌다.

## 3. 예측 (사전 선언 — 결과를 본 뒤 바꾸지 않는다)

- **P1**: `base_ref` 는 9문항을 전부 통과한다 (과반 실패 0개). 실패하면 문항 쪽 문제이므로 스윕 해석을 보류한다.
- **P2**: `A_control` 은 `baseline_0926` 을 재현한다 — 9문항 중 **7개 이상** 과반 실패. 크게 벗어나면 표적 문항이 불안정하다는 뜻이다.
- **P3**: `D_greedy` 도 멈추지 않는다 (과반 실패 **6개 이상**). 근거: 이 행동은 세 라운드에서 같은 문항에 재현됐고, 학습 데이터에 없는데도 일관되게 나온다 — 샘플링 우연이라면 그렇게 재현되지 않는다.
- **P4**: 어느 팔도 과반 실패를 **4개 이하**로 낮추지 못한다. 즉 디코딩만으로는 못 고친다.

## 4. 판정 규칙 (사전 선언)

- **성공**: 어느 팔이 과반 실패 문항을 **4개 이하**로 낮춘다 → 전체 30문항으로 확인하고, 채택 전에 **잡담·계획·RAG 도 그 설정으로 재측정**한다 (디코딩은 슬롯 전역에 영향을 주므로 코딩만 보고 채택하면 안 된다).
- **부분 성공**: **5~6개** → 방향은 있으나 부족. 다른 값으로 한 번 더 좁힌다.
- **실패**: 모든 팔이 **7개 이상** → 디코딩으로는 못 고친다. 다음 레버는 학습 데이터의 길이·종료 패턴이다 (v9).

P3·P4 가 맞으면(= 예측대로 실패하면) 그것은 **유용한 음성 결과**다. "디코딩으로 고칠 수 있다" 를 배제하면 남는 후보가 줄어든다.

## 5. 이 실험의 한계

- 표적 9문항은 v6 가 실패한 문항으로 **골라낸** 것이다. 어느 팔이 이 9개를 개선해도 전체 30문항에서 같은 효과가 난다는 보장은 없다 — 그래서 §4 가 전체 확인을 요구한다.
- 팔마다 조건이 하나가 아니다 (`C_narrow` 는 세 값을 동시에 바꾼다). 효과가 나오면 어느 값 때문인지 따로 갈라야 한다.
- 디코딩을 바꾸면 운영 전체가 바뀐다. 코딩 슬롯은 운영에서 로컬을 쓰지 않으므로([`../protocol.md`](../protocol.md) §2.2), **코딩을 위해 디코딩을 바꾸면 정작 그 슬롯은 운영에 없고 다른 슬롯만 영향을 받는다.** 채택 판단에서 이 비대칭을 반드시 감안한다.
