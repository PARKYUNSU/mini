## 3. 그런데 **가설 셋이 다 틀렸다**

H1·H2·H3 는 **전부 "이탈이 base 에서 올라간다"** 를 가정했다. 실제는 **먼저 내려간다** — base 6/24 에서 **0/24**(step 15·18)로, 즉 **파인튜닝이 잠깐 템플릿 준수를 base 보다 좋게 만든다.** 그 다음 6스텝 만에 0 → 10 → 21 로 무너진다.

내 가설 공간에 이 모양이 없었다. "H1 (점진)" 이라는 꼬리표는 규칙을 기계적으로 적용한 결과일 뿐이고, **실제 모양은 "개선 구간 뒤의 급변"** 이다. 사전 등록이 *"비단조가 나오면 그 사실을 적는다"* 고 해 둔 것이 이 자리에서 값을 했다 — 그 조항이 없었다면 "점진적으로 나빠진다" 로 적었을 것이다.

## 4. 실제 발견 — 실패가 **두 종류**다

이탈한 응답이 학습 데이터의 형식(`서론`/`본론`/`결론`)인지 세어 보면 갈라진다:

| | 이탈 | 그중 서론/본론/결론 |
|---|---|---|
| base | 6/24 | **0** |
| s003 · s006 · s009 · s012 | 3 · 5 · 2 · 1 | **0** |
| s015 · s018 | **0** | — |
| s021 | 10/24 | **10 (전부)** |
| s024 | 21/24 | **21 (전부)** |
| **v9** | 24/24 | **24 (전부)** |
| **v10** | 10/24 | **10 (전부)** |

**두 실패는 다른 것이다.**

1. **누락형** (base·step 3~12): 섹션을 그냥 빼먹는다. 에세이가 아니다. 학습이 이것을 **줄인다** — 6 → 0.
2. **형식 탈취형** (step 21 이후): 모델이 `서론`/`본론`/`결론` 을 내놓는다. **시스템 프롬프트의 템플릿을 학습된 형식이 덮어쓴다.** step 18(0)과 step 21(10) 사이에서 **갑자기** 나타나고, 나타난 뒤에는 **100% 이 형태다.**

그래서 "지시 따르기가 점점 나빠진다" 가 아니다. **특정 경쟁 형식이 이기는 것**이고, 그 전환은 급격하다.

## 5. 원인 — 학습 데이터가 운영 프롬프트와 **정면으로 충돌한다**

v9 학습 데이터의 RAG 예시 400건을 세어 봤다:

| | |
|---|---|
| 템플릿 섹션(`선별 논문`·`부족 논문`·`Research Gap`) 포함 | **0건 (0%)** |
| `서론`/`본론`/`결론` 중 둘 이상 포함 | **385건 (96%)** |

운영 시스템 프롬프트(`RAG_OUTPUT_TEMPLATE_MULTI_STRICT`)는 *"아래 뼈대를 그대로 따라 값만 채우세요"* 라고 지시하는데, **학습 데이터는 그 뼈대를 한 번도 보여주지 않고 다른 형식을 400번 보여준다.**

이것은 [`../protocol.md`](../protocol.md) §3 의 확립된 결론과 **같은 모양**이다 — 코딩 학습 데이터가 코딩 열화의 원인이었고, 빼니 해결됐다. 여기서도 원인은 모델이나 lr 이 아니라 **데이터**다. lr 인하(v10)는 곡선 위에서 **덜 간 지점에 머무는 것**일 뿐 탈취를 막지 못한다 (v10 도 이탈 전부가 에세이다).

## 6. 운영에 실제로 걸려 있는 것

`.env` 의 `RAG_ANSWER_MODEL="yunsur_v9"` — **운영 RAG 슬롯이 v9 이고, v9 은 템플릿을 24/24 전부 이탈한다.** 즉 운영에서 그 템플릿은 **한 번도 지켜지지 않는다.**

**기능이 깨지는 것은 아니다.** 템플릿 섹션 이름을 파싱하거나 검사하는 코드는 프롬프트 정의 밖에 **없다**(`grep` 확인). 그래서 조용한 불일치다. 대가는 둘:

1. **프롬프트 토큰 낭비** — 템플릿 블록(few-shot 포함 ~1,000자)이 매 RAG 호출에 들어가는데 출력에 반영되지 않는다.
2. **문서와 행동의 괴리** — 프롬프트를 읽은 사람은 출력이 템플릿을 따른다고 믿는다.

**어느 쪽이 맞는지는 측정이 답할 수 없다.** 에세이 형식이 사람이 읽기에 더 나을 수도 있다. 선택은 둘이다:
- **프롬프트를 행동에 맞춘다** — 템플릿 블록을 빼거나 `서론`/`본론`/`결론` 로 바꾼다. 즉시 토큰이 절약되고 괴리가 없어진다.
- **데이터를 프롬프트에 맞춘다** — RAG 학습 타깃을 템플릿 형식으로 다시 만든다. 다음 학습 라운드의 일이고, §3 의 코딩 사례가 그 방식이 듣는다는 선례다.

## 9. 다음

**측정은 여기서 닫힌다.** 더 촘촘히 재도(step 19·20 등) 얻는 것은 전환점의 좌표 한 자리이고, 원인(§5)은 이미 데이터로 확인됐다.

할 일은 측정이 아니라 **결정**이다 — §6 의 두 선택지 중 하나를 고르는 것. **프롬프트를 행동에 맞추는 쪽이 싸다**(즉시, 토큰 절약, 위험 없음). 데이터를 고치는 쪽은 학습 라운드가 따르고, 그때는 "RAG 타깃을 템플릿 형식으로 재생성하면 탈취가 사라지는가" 를 사전 등록해 물을 수 있다 — §3 의 코딩 사례와 같은 구조의 질문이다.
