# 단일 경로(`prefer_single_hit`) — SINGLE 템플릿은 죽어 있었다 (2026-10-06~07)

운영 경로(`direct_answer_node`)로 질의 10개 × 2회. **사전 등록 라운드가 아니라 현황 측정**이고, 표본 2건으로 운영 코드를 고치지 않기 위해 MULTI 때와 같은 순서(먼저 재고 그 뒤 정렬)를 따랐다.

평가기로는 볼 수 없다 — 평가기는 항상 MULTI 템플릿을 쓰고 컨텍스트 필터를 돌리지 않는다. SINGLE 템플릿과 심층 접미사는 `direct_answer_node` 에서만 쓰인다.

**이 경로는 예외가 아니다**: `len(질의) <= 44` 이고 `요약|알려줘|설명해` 가 있으면 단일 경로다 — 짧은 질문의 가장 흔한 모양이다.

**그냥 무시하는 것이 아니라 출력을 오염시켰다.** `핵심 주제`·`주요 방법론`·`결론 및 의의` 가 5·5·10회 나왔는데 섹션 제목이 아니라 **에세이 본문의 항목 이름**으로 쓰였다 — `1. **핵심 주제**: …`. MULTI 경로에서 같은 자리는 `1. **Hyper-RAG**: …` 처럼 실제 접근 이름이다. 죽은 템플릿이 토큰만 쓰는 것이 아니라 **항목 이름을 상투어로 만들었다.**

## 바꾼 것

사용자 결정은 **"심층 기능을 되살리되 에세이 형식에 맞게 다시 쓴다"**(2번)였다.

- 템플릿 분기 삭제 — 단일·다중 모두 에세이 템플릿. `top-1` 필터는 **검색 결정**이라 유지했다.
- `RAG_OUTPUT_TEMPLATE_SINGLE_STRICT`(1,091자)와 레거시 별칭 `RAG_OUTPUT_TEMPLATE_STRICT` 삭제. 참조 0건 확인.
- `DIRECT_ANSWER_RAG_DEPTH_SUFFIX` 재작성 — 옛 것은 `<b>📄 …</b>` 줄과 `1.~3.` 제목을 전제했고 그 줄이 0/20 이었다. 새 것은 뼈대를 유지한 채 **본론 항목을 5~6문장**으로, (수치·메커니즘·명시된 기여와 한계)를 넣게 한다. **"문서에 없는 내용으로 길이를 늘리지 마세요"** 를 같이 넣었다 — 길게 쓰라고만 하면 환각으로 채울 유인이 생긴다.
- 시스템 프롬프트의 SINGLE 전용 문구 4곳 정리. 그중 하나는 측정이 드러낸 문제를 직접 겨냥한다 — 항목 이름에 상투어를 쓰지 말고 실제 접근 이름을 쓰라고 못 박았다.

## 심층 모드는 **아직 판정 못 했다**

처음 "심층/일반 길이비 1.00배 → 효과 없음" 으로 적었다. **그 결론은 틀렸다** — `wants_depth` 시행이 **4개뿐**이고 조건이 섞여 있었다:

| 심층 시행 | 문서 수 | 길이 |
|---|---|---|
| 리랭커… 구체적으로 | 1 | **849** |
| 리랭커… 구체적으로 | 1 | **717** |
| RAG 환각… 자세히 | 2 | 593 |
| RAG 환각… 자세히 | 2 | 557 |

일반 시행은 **전부 문서 1편**이고 중앙값 652자다. **조건을 맞추면(문서 1편) 심층 두 시행이 717·849 로 둘 다 더 길다.** 문서 2편인 두 시행이 짧아 중앙값이 가려졌다.

**측정 설계에 구멍이 있다**: 이 스크립트는 `rag_context` **길이를 기록하지 않는다.** 심층 경로는 `_rag_context_same_paper_all_chunks`(상한 8000자)를 타므로 문서 **수**가 아니라 **텍스트 양**이 달라지는데, 그것을 재지 않았다.

**다음**: 심층/일반을 **짝지어** 재야 한다 — 같은 질문의 `자세히` 유무 쌍 6개 × 3회 = 36시행, 그리고 `rag_context` 길이를 기록한다. 그때까지 심층 기능의 효과는 **미정**이다.
