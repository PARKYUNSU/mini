# 프롬프트 교체와 세 번의 측정 (2026-10-06)

[`../05_conclusion.md`](../05_conclusion.md) §6 의 두 선택지 중 **"프롬프트를 행동에 맞춘다"** 를 택했다. 사용자 결정.

**사전 등록 라운드가 아니다** — 운영 코드 수정과 그 검증이다. 다만 고치고 나서 재지 않으면 같은 괴리를 다시 만드는 셈이므로 판본마다 24시행(RAG 8문항 × 3회, `yunsur_v9`)을 쟀다.

## 바꾼 것

`RAG_OUTPUT_TEMPLATE_MULTI_STRICT` 만 교체했다 (1,006 → 약 540자). **`SINGLE_STRICT` 는 건드리지 않았다** — v9 이 그것을 이탈하는지 측정한 적이 없으므로 추측으로 고치지 않는다.

템플릿 상수에 묶여 있던 주변 문구도 같이 맞췄다. 이것이 더 성가셨다:
- `direct_answer_rag_user()` 의 빈-문서 안내가 `📄·📅·🔗` 칸을 가정하고 있었다 → 두 템플릿 모두에 맞게 일반화
- `DIRECT_ANSWER_RAG_SYSTEM_BASE` 의 "이모지·HTML `<b>`", "💡 [심층 분석] 섹션" 이 전역처럼 적혀 있었다 → **"단일 논문 템플릿이면"** 으로 한정해 SINGLE 동작 보존
- 플레이스홀더 금지 목록에 새 템플릿의 중괄호 추가
- `tests/unit/test_lang_guard.py` 에 새 형식 케이스 추가 (영문 시스템 이름이 굵게 들어가 `english_ratio` 오탐이 나기 쉬운 자리)

### v1 의 실패 — 자리표가 출력에 새어나왔다

뼈대 줄 끝에 `[n]` 을 넣었더니 **16/24 가 그것을 그대로 베꼈다** (예: `…신뢰도를 높여야 합니다 [n].`). `[n]` 은 **유효한 값이 아니라 메타 자리표**라서 복사되면 쓰레기가 된다. 시스템 프롬프트의 플레이스홀더 금지 조항은 괄호·중괄호만 열거해 대괄호를 잡지 못했다.

**교훈**: 자리표를 뼈대에 넣지 말고 **구체 예시를 규칙에 적는다.** 베껴도 유효한 값이 되는 형태여야 한다.

### 분석 오류 하나를 정정한다

v1 측정 뒤 "인용 지시는 효과가 없다" 고 적었다. **틀렸다.** 옛 프롬프트(17)와 v1(16)을 비교했는데, 옛 프롬프트는 `발행일·출처·Distance` 를 요구하고 있어 그 자체로 인용을 밀어붙이는 조건이었다. 지시 효과를 보려면 **다른 조건이 같은 v1(16) vs v2(4)** 를 봐야 했고 그것은 **+12** 다. 틀린 짝을 비교했다.

## 출력 자체는 바뀌지 않았다

**v9 의 행동은 그대로다.** 옛 프롬프트에서도 `서론`/`본론`/`결론` 을 썼고(그것이 이탈이었다) 새 프롬프트에서도 같이 쓴다. 바뀐 것은 **프롬프트가 그것을 요구하게 된 것**이다. 얻은 것은 토큰 절약과 문서·행동 일치이고, **출력 품질이 좋아진 것이 아니다.** (인용은 17 → 24/24 로 실제로 늘었다.)

## v4 — arXiv ID 인용 교정 ([`v4_citation_fix.jsonl`](v4_citation_fix.jsonl))

[`../../protocol.md`](../../protocol.md) §5.4 의 결함을 고쳤다. [`core/llm/citation_fix.py`](../../../../core/llm/citation_fix.py) 를 운영과 평가기 양쪽에 배선했다 — **코퍼스가 아니라 그 답변의 컨텍스트**(논문 3편)와 대조한다.

**출력의 무효 ID 가 0 이다.** 그런데 내역이 진단을 뒤집었다: 그대로 둠 27 · **교정 1** · **삭제 15**(고유 8). **삭제 8개 중 7개는 코퍼스에도 없다** — 전사 오류가 아니라 **날조**다. 그래서 이 모듈은 수리가 아니라 **피해 억제**다. 자세한 것은 §5.4.

## v5 — 번호 인용 + 결정적 펼침 ([`v5_numbered_citation.jsonl`](v5_numbered_citation.jsonl))

v4 는 무효 ID 를 0 으로 만들었지만 **인용 35% 를 삭제**했다. 모델이 12자 숫자열을 날조하므로 **전사를 시키지 않는** 쪽으로 바꿨다 — 컨텍스트에 `[문서 N]` 라벨을 붙이고 번호만 인용하게 한 뒤 후처리가 ID 로 펼친다.

| | 고유 ID | 무효 | 펼침 | 삭제 |
|---|---|---|---|---|
| v3 교정 없음 | 20 | 4 | — | — |
| v4 ID 교정 | 15 | 0 | 0 | **15** |
| **v5 번호 인용** | **20** | **0** | **40** | **0** |

세 섹션 24/24 · 품질 24/24 · `[문서 N]` 잔존 0 · **그 답변 컨텍스트에 없는 인용 0건**. 자세한 것은 [`../../protocol.md`](../../protocol.md) §5.4.

## 곁가지 — arXiv ID 변형

인용 ID 중 코퍼스에 없는 것이 옛 36%(4/11) · v3 20%(4/20) 다. 전부 실제 ID 의 자릿수 변형이고 없는 논문을 지어낸 것은 아니다. **기존 결함이며 이 변경이 만든 것이 아니다** — [`../../protocol.md`](../../protocol.md) §5.4 에 올렸다.
