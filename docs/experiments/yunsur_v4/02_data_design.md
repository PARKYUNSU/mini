|---|---|---|---|---|
| RAG | 400 | `train_data_v3_clean.jsonl` 무작위 샘플 | `DIRECT_ANSWER_RAG_SYSTEM_BASE` | 기존 서론/본론/결론 유지 |

## v3 대비 핵심 변경 3가지

1. **슬롯 균형** — 단일 슬롯 100% → RAG 36% / 잡담 32% / 계획 23% / 코딩 9%.
2. **system 정합** — 학습 레코드의 `system` = 운영 봇이 그 슬롯에 실제로 주입하는 프롬프트 상수. 노트북의 `SYSTEM_PERSONA` 단일 덮어쓰기는 폐기하고 레코드별 system을 그대로 사용한다 (03 참조).
3. **형식 자동 검증** — output을 평가 스크립트와 **같은 판정기**(`core/llm/lang_guard.py`, `core/llm/code_extract.py`, `_parse_planner_llm_lines`)로 걸러 통과한 것만 학습. "학습 데이터가 평가 기준을 만족한다"를 보장. 학습용 영어 비율 상한(30%)은 평가(45%)보다 엄격.

## 생성 방법 — [`scripts/gen_v4_dataset.py`](../../../scripts/gen_v4_dataset.py)

1. **시드**: `finetune_datasets/v4/seeds/{chat,planner,coding}.txt` — 사람이 슬롯당 30개+ 직접 작성 (텔레그램에 실제로 칠 법한 문장).
2. **증폭**: 시드 1개 → 베이스 Qwen(temperature 0.9)에게 같은 종류의 변형 8개를 JSON 배열로 생성. 목표의 1.6배까지 instruction 확보(거절률 감안).
3. **평가 누수 차단**: 시드·증폭 문장 모두 평가 30문항과 정규화 문자열 유사도(SequenceMatcher) ≥ 0.72면 제외 → `rejected.jsonl` (`reason=eval_similar`).
4. **응답**: 베이스 Qwen(temperature 0.3, reasoning off)에 봇 프롬프트 그대로 호출.
5. **검증·거절 기록**: 규칙 위반은 사유와 함께 `rejected.jsonl`. 거절률 자체를 데이터 품질 지표로 기록.
6. **조립**: instruction 중복 제거 → 슬롯별 목표 수만큼 → RAG 샘플 합류 → 셔플 → `train_data_v4.jsonl`.

## 알려진 한계 (정직하게)

- RAG 슬롯의 instruction은 논문 컨텍스트 없는 순수 질문이라, 운영에서 봇이 주는 user 프롬프트(검색 컨텍스트 + 출력 템플릿)와 **user 쪽은 여전히 다르다**. system만 맞췄다. v5에서 컨텍스트 포함 형태로 재구성할 여지.
- 자기 증류이므로 v4의 잡담·계획 상한은 "베이스 Qwen 수준"이다. 목표는 베이스를 넘는 게 아니라 **v3에서 잃은 것을 되찾으면서 RAG 서식·윤수르 페르소나를 유지**하는 것.

### 생성 중 발견해 규칙에 추가한 것 (모두 `gen_v4_dataset.py`에 반영, 기존 생성분에 소급 적용)

1. **`input()` 요청** — 증폭기가 "입력받은 정수를…" 류를 만들고 모델이 `input()`을 쓰면 검증 샌드박스가 8초 타임아웃. 운영(E2B)에도 stdin이 없어 분포에 맞지 않음 → 증폭 힌트에서 배제 + 코드에 `input(` 있으면 즉시 거절.
2. **한자(중국어) 누출** — `犒劳`, `定时任务`, `每晚` 등 Qwen 특유의 CJK 혼입이 잡담 4/258·계획 9/250. 영어 비율 검사로는 안 잡히므로 `[\u4e00-\u9fff]` 거절 규칙 추가.
3. **`[주의] .env에 API 키` 보일러플레이트** — 플래너 프롬프트의 지시문("외부 API 키가 필요하면 마지막에 [주의]…")을 모델이 23%(58/250)에서 근거 없이 붙임(사진 중복 제거에도 API 키 요구). 학습하면 v4가 이 습관을 배우므로, 요청에 API·키·토큰 언급이 없으면 제거하고 있으면 번호 없는 꼬리줄로만 유지 → 최종 9건.
4. **토큰 경계 띄어쓰기** — `10 개`, `8 시`, `URL 을`, `Python 의` (베이스 Qwen 습관) → 숫자+단위, 영단어+조사 공백 정규화. 최종 잔여 0건.
5. **잡담 영어 상한** — "네, anytime 입니다!"가 30% 상한을 통과 → 잡담만 15%로 강화.

### 남은 편향 (기록)

- 계획 단계 수가 2~3단계에 98% 집중 (2: 71, 3: 174, 4: 4). 베이스 모델 성향이며 프롬프트가 3~5단계를 요구해도 3에 몰림. v4가 "항상 3단계"를 배울 수 있음.
- 잡담 output에 `**굵게**`·`---` 같은 경량 마크다운은 허용함(헤더·펜스만 금지). 텔레그램 표시엔 문제없음.
- 코딩 문자열 리터럴 안의 `"2024 년은"` 같은 공백은 코드라 정규화하지 않음.
