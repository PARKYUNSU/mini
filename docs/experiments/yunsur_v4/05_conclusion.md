## 판정 (README §3 사전 선언 기준)

| 기준 | 결과 |
|---|---|
| 통과: 모든 슬롯 base+5%p 이내 **and** RAG < base | ❌ 잡담 +8, 플래너 +29, 코딩 +28 |
| 부분 통과: 잡담·플래너 v3 대비 절반 이하 개선 | ✅ 잡담 29→8% (−72%), 플래너 62→33% (−47%), 전체 26→17% |
| 실패: 어느 슬롯이든 v3보다 악화 | 없음 — 코딩만 v3 6% → v4 28%로 악화 (아래) |

**→ 부분 통과.** 코딩 슬롯은 v3보다 나빠졌으므로 엄밀히는 "실패" 조항에도 걸린다. 종합: **데이터 재설계는 유효했으나(전 슬롯 v3 대비 개선·속도 2~4배), 무학습 베이스를 넘는 범용 모델은 만들지 못했다. RAG 슬롯에서만 학습이 베이스를 이겼다(0% vs 12%).**

## 해석

1. **데이터 구성이 결과를 결정했다.** 하이퍼파라미터·베이스·양자화를 고정하고 데이터만 바꿨는데 전체 26% → 17%. v3의 실패 원인으로 진단했던 "단일 슬롯·단일 서식·system 불일치"가 맞았다는 근거.
2. **양자화는 변수가 아니었다.** v3 q4 26% ≈ v3 q8 24%. 어제 "v3가 q8이라 불공정"이라는 우려는 기우.
3. **학습이 겨냥한 슬롯(RAG)에서만 베이스를 이긴다.** base의 RAG 실패 3건은 전부 반복 붕괴(repetition)인데 v4는 0건 — RAG 400건의 서식 학습이 억제 효과를 냈다. 속도도 base와 같다(33s; v3는 59~82s).
4. **자기 증류의 상한.** 잡담·계획·코딩은 base 출력으로 학습했으므로 base를 넘을 수 없고, 실제로는 base보다 나쁘다. 1,099건 1 epoch로는 "base처럼 답하기"를 완전히 흡수하지 못했다.

## 운영 결정

- **운영 로컬 모델은 base `qwen3.5:9b` 유지** (전체 4%).
- 선택: **RAG 답변 슬롯만 `yunsur_v4`** 로 분리하면 논문 답변 품질(0% vs 12%)을 얻고 속도 손해 없음. 슬롯별 모델 설정(`RAG_ANSWER_MODEL` 등) 코드 추가 필요.

## 실험 과정에서 얻은 교훈 (실패 기록)

- **GGUF는 파일명이 아니라 메타데이터로 검증한다.** `llm/Qwen3.5-9B.BF16.gguf`는 이름과 달리 `general.name=Yunsur_V3_Model`(v3 머지본)이었고, 그 위에 v4 어댑터를 머지해 80% 실패하는 깨진 모델을 만들었다. `qwen35-merged-f16.gguf`(4월 2일)는 v2였다. 잘못된 측정은 [`04_eval_v4/bad_merge_record/`](04_eval_v4/bad_merge_record/)에 보관.
- **어댑터는 머지보다 `ADAPTER` 런타임 적용이 안전하다.** 베이스와 가중치·템플릿을 완전히 공유해 비교가 깨끗하고, 18GB 베이스 재다운로드도 필요 없다.
- **금지어를 나열한 프롬프트는 9B 모델을 오히려 프라이밍한다** (01_baseline의 banlist 라운드, 26%).
- **평가 문항은 학습 데이터에서 격리**하고(유사도 필터), 성공 기준은 결과를 보기 전에 적는다.
