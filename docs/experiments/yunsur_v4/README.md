# 실험 노트 — yunsur_v4: 학습 데이터 재설계로 슬롯 과적합 해소

- 시작일: 2026-09-18
- 베이스 모델: `Qwen/Qwen3.5-9B` (Ollama `qwen3.5:9b`)
- 비교 대상: `yunsur_v3:latest` (v3 데이터 1,073건 LoRA SFT), `qwen3.5:9b` (무학습)
- 측정 도구: [`scripts/eval_local_llm_failure.py`](../../../scripts/eval_local_llm_failure.py) — 고정 30문항 × 3회 (n=90), 로컬 1차 호출만, API 폴백 없음
- 실패 정의
  - **hard**: 타임아웃 / 빈 답 / 플래너 단계 형식 파싱 실패 / 코드 문법·실행 오류
  - **quality**: 한국어 기대 슬롯의 영어 혼입(라틴 비율 > 45%, 코드·URL·영문 논문 제목 제외) / `<think>` 유출 / 같은 줄 3회 반복 / 잡담에 코드 펜스 / 코딩 출력 형식 드리프트
  - 보고 숫자는 **hard + quality 합산(strict)** 기준, hard 단독은 괄호로 병기

## 1. 문제 정의

운영 봇(텔레그램 `mini`)의 로컬 LLM 슬롯은 4개다: 잡담(A), RAG 답변(B), 실행 계획(Planner), 코딩(Executor 로컬 대체 측정).
v3 파인튜닝 모델은 **학습이 겨냥한 RAG 슬롯에서는 베이스와 동률**이었지만, 나머지 슬롯에서 크게 뒤졌고 응답 속도도 3~4배 느렸다.

| 슬롯 | yunsur_v3 (운영 프롬프트) | qwen3.5:9b (베이스) | 비고 |
|---|---|---|---|
| 잡담 | 25% (hard 0%) · 중앙값 15s | **0%** · 6s | v3 실패 6건 중 5건이 영어 혼입 |
| 플래너 | 13% (hard 4%) · 19s | **0%** · 5s | v3: 영어 추론 섹션 → 파싱 실패 |
| RAG | **0%** · 82s | 8% (반복 2건) · 30s | hard 기준 동률 |
| 코딩 | 17% (hard 6%) | 11% (hard 6%) | 둘 다 형식 드리프트 |
| **전체** | **13%** (hard 2%) | **4%** (hard 1%) | |

원본: [`01_baseline/`](01_baseline/) — `yunsur_v3_prompt_old_summary.json`(v2 라운드), `qwen35_9b_base_summary.json`.
`yunsur_v3_prompt_banlist_summary.json`(v3 라운드)은 프롬프트에 금지어를 나열한 실험으로, 9B 모델이 금지어를 그대로 따라 써서 **26%로 악화** — 프라이밍 부작용의 기록으로 보관.

## 2. 원인 진단

[`finetune_datasets/train_data_v3_clean.jsonl`](../../../finetune_datasets/train_data_v3_clean.jsonl) 1,073건을 확인한 결과:

1. **단일 슬롯 100%** — 전부 "논문을 비판적으로 분석하는 논술형 Q&A". 잡담·계획·코딩 샘플 0건.
2. **단일 서식 강제** — 모든 output이 `### 서론 → ### 본론 1.2.3. → ### 결론`. 모델이 "무슨 요청이든 ### 헤더 + 번호 목록"으로 답하게 됨 (통과한 잡담조차 `### 📌 Short Response` 헤더를 붙임).
3. **system 불일치** — 학습 노트북은 레코드의 system을 버리고 `SYSTEM_PERSONA`("마스터의 전속 비서 윤수르… 반드시 서론/본론/결론") 하나로 덮어씀. 운영 봇은 슬롯마다 다른 system 프롬프트를 쓰므로 **학습 때 본 system과 운영 때 받는 system이 다름** → 학습 효과가 운영에 전이되지 않고, "윤수르 = 항상 논문 서식"만 각인.

결론: 데이터 **양**이 아니라 **구성**의 문제. 재학습은 데이터 재설계가 핵심이며, 하이퍼파라미터는 v3와 동일하게 고정해 "데이터만 바꾼 효과"를 분리한다.

## 3. 성공 기준 (사전 선언 — 결과를 본 뒤 바꾸지 않는다)

같은 30문항 × 3회, 같은 프롬프트(2026-09-18 롤백된 긍정형 버전), 세 모델(v4 / v3 / base)을 같은 밤에 재측정한 결과에서:

- **통과**: yunsur_v4가 **모든 슬롯**에서 base 대비 strict 실패율 **+5%p 이내**이고, **RAG 슬롯**에서는 base보다 **낮다**.
- **부분 통과**: 잡담·플래너가 v3 대비 절반 이하로 개선됐으나 base를 넘지 못함 → "데이터 재설계는 유효, 학습 자체의 부가가치는 미입증"으로 기록.
- **실패**: 어느 슬롯이든 v3보다 나빠짐 → 원인 분석 후 기록. 운영 모델은 base 유지.

속도(중앙값)는 판정 기준에 넣지 않되 표에 병기한다.

## 6. 재측정 · 결론 — **부분 통과**

| 슬롯 | base | **v4** | v3 (q4 / q8) |
|---|---|---|---|
| 잡담 | **0%** | 8% | 29% / 38% |
| 플래너 | **4%** | 33% | 62% / 42% |
| RAG | 12% | **0%** | 0% / 8% |
| 코딩 | **0%** | 28% | 6% / 6% |
| **전체** | **4%** | **17%** | 26% / 24% |

데이터만 바꿔 v3 대비 전체 26%→17%, 잡담 −72%·플래너 −47%, 속도 2~4배 개선 → **데이터 재설계 유효**. 그러나 무학습 base를 넘지 못했고, 학습이 겨냥한 RAG에서만 base를 이김(0% vs 12%). 운영 모델은 base 유지, RAG 슬롯 분리 적용은 선택. 상세·실패 분석·v5 계획: [`05_conclusion.md`](05_conclusion.md), 원본 [`04_eval_v4/`](04_eval_v4/).
