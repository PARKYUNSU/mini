> 측정 **전에** 쓴다. 출발점: 사용자가 "성능이 안 좋다"고 했고, 실사용 업무 질문 10개(작업 111 · 112 · 118 · 132 · 135 · 137–141)를 지금 파이프라인으로 다시 돌려 답을 읽었다(`.cron/work_1111/`, 질문 원문은 저장소에 넣지 않는다). 거르기를 통과한 문서가 4~5편이어도 본론은 1~2편만 썼다 — 작업 118 은 관련 4편 중 2편, 작업 139 는 5편 중 1편. 예전 답 10개도 모두 본론 2항목이었다.

## 1. 바꾸는 것 — `RAG_DOC_SLOTS=1` (기본 0, 4f7c758)

- 일반 답 틀은 예시 칸이 3개이고 "2~4개" 규칙인데, v13 은 거의 늘 2개만 채운다. 목록 모드에서는 문서마다 번호 칸을 주자 인용이 31 → 59 로 늘었다(`list_slots_1016`).
- 같은 번호 칸 틀을 일반 질문에도 쓴다. 조건: 거르기 뒤 문서 3편 이상 · 목록 모드 아님 · 판정 '없음' 아님 · 항목별 판정 아님.
- 칸은 5개까지, 칸마다 1~2문장이다(컨텍스트가 목록 모드처럼 짧지 않아 n_ctx 4096 안에 넣으려는 것). 관련 없는 문서의 칸은 빼라고 지시한다.
- 검색 · 거르기 · 판정 호출은 그대로다. 판정 뒤에 답 호출의 틀만 바꾼다(단위 테스트 `tests/unit/test_doc_slots.py`).
- 질문 유형을 추측하지 않는다. `survey_gate_1030` 은 질문 문구 정규식으로 목록 모드를 켰는데, 실사용 10개 중 2개만 걸렸다.

**보고:**
- 칸 틀이 적용된 문항은 canon 22/40 · 162 표본 15/39 · real40 수치/비교 5/26. 적용된 22문항의 본론 항목은 64 → 83, 전체 인용은 99 → 117편이다. 늘어난 인용은 대부분 '1'(관련은 있지만 직접은 아님)이다: '1' 합 31 → 44.

- 수치가 빠진 1문항(N12)은 문서가 2편이라 칸 틀이 적용되지 않았다. 같은 입력에서 답이 달라진 것이다(생성 흔들림).

**해석:** 해는 없고 방향은 좋아지는 쪽이지만 효과가 작다(40문항에서 '2' 가 6편 늘었다). "v13 이 늘 2항목만 쓴다"는 실사용 10개에서 본 것이고, 짧은 한 주제 질문(canon)에서는 그 정도가 아니었다. 실사용 질문은 길고 여러 요소인데, 그런 꼴의 새 문항으로는 재지 못했다. 새 기기에서 답 모델을 비교할 때 이 플래그를 한 팔로 다시 잰다.
