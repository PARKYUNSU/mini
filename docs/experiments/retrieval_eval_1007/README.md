# 검색 평가셋 v2 — 25문항에서 189문항으로 (사전 등록)

- 시작일: 2026-10-07
- 비용: 학습 0 · 측정 1회 (맥미니 CPU, 임베딩 + Chroma, Ollama 안 씀)
- **이 라운드는 판정이 없다.** 앞으로의 검색 비교(임베더 교체, 하이퍼볼릭 헤드 등)가 쓸 **자**와 그 자로 잰 **기준선**을 만든다.

## 1. 왜 지금 이것인가

하이퍼볼릭 임베딩을 RAG 에 쓰자는 제안을 검토하면서 막힌 지점이 측정이다. 문헌에서 기하 효과는 작다 — HypRAG(ICML 2026)는 같은 레시피의 유클리드 기준선 대비 MTEB 평균 +0.46(사전학습 사영) ~ +2.3(완전 쌍곡)점이다. 기존 [`scripts/eval_rag_hybrid.py`](../../../scripts/eval_rag_hybrid.py) 는 25문항이라 1문항이 4%p 이고, 짝지은 McNemar 로 p<0.05 를 얻으려면 불일치 6개가 전부 한쪽이어야 한다. **그 크기의 효과는 원리적으로 잴 수 없다.**

같은 이유로 임베더 교체(all-MiniLM-L6-v2 → 다른 모델)도 지금은 판정할 수 없다. 2026-04 의 [`eval_embedding_models.py`](../../../scripts/eval_embedding_models.py) 는 정답 1개 대 쉬운 오답 1개 비교라 6개 모델이 전부 정확도 1.0 이었다.

[`protocol.md`](../protocol.md) §1 의 교훈을 그대로 적용한다 — **유효 표본은 문항 수다.**

|---|---|---|---|---|

### 2.1 만든 규칙

- **A**: 코퍼스(JSONL 5,758편) 중 초록 ≥400자·본문 ≥5,000자인 5,750편을 `paper_id` 순으로 정렬하고 `random.seed(20261007)` 로 120편을 뽑았다. 주제 필터 없이 뽑았으므로 코퍼스의 주제 분포(RAG 비중 포함)를 그대로 따른다. 질의는 초록을 읽고 **제목의 고유 단어·약어를 피해** 무엇을 했는지로 썼다. 제목과의 내용어 Jaccard 가 0.55 를 넘은 8개는 측정 전에 다시 썼다(최대 0.75 → 0.545).
- **B**: [`eval_rag_hybrid.py`](../../../scripts/eval_rag_hybrid.py) 의 `EVAL_DATA` 25개를 그대로 옮겼다.
- **C1**: 제목에 survey·review·overview·tutorial 이 든 153편 중 주제별로 묶을 수 있는 것을 골라 질의 24개를 만들었다. **정답은 그 주제의 survey 전부**다 (예: graph RAG survey → 2편).
- **C2**: [`apps/backfill/classics.yaml`](../../../apps/backfill/classics.yaml) 의 고전 27편 중 20편. 질의는 제목이 아니라 기여 내용으로 썼다 ("original architecture replacing recurrence entirely with self attention").
- 질의는 전부 **영어 키워드형**이다. 운영에서는 한국어 질문을 `_extract_english_rag_query`(LLM)가 영어 키워드로 압축한 뒤 검색하므로, 이 평가는 **그 압축 이후의 검색만** 잰다. LLM 단계를 빼서 측정이 결정적이고 Ollama 를 쓰지 않는다.
- 모든 정답 논문이 JSONL 코퍼스에 있음을 확인했다.

### 2.2 알려진 한계 (측정 전에 적는다)

1. **A 의 정답은 1편이다.** 같은 내용을 다룬 다른 논문이 상위에 오면 미스로 센다. 질의를 그 논문만의 내용으로 좁게 써서 줄였지만 0은 아니다 → 미스 분석 때 상위 5편을 사람이 확인해 "정답 누락"을 따로 센다.
2. **C1 의 정답은 제목 기준이다.** 제목에 survey 류 단어가 없는 리뷰는 정답에서 빠진다 (예외로 `2508.01781` taxonomy 보고서는 넣었다). 정답 집합은 하한이다.
3. **B 는 오염됐다.** 2026-04 에 이 25문항으로 하이브리드 가중치 그리드를 골랐다. 그래서 **주 지표에서 뺀다** (§4).
4. **질의 작성자가 한 명(Claude)이다.** 문체 편향이 있을 수 있다. 실제 사용자 RAG 질의 로그는 2건뿐이라 대체할 수 없었다.
5. 이 셋으로 **튜닝하지 않는다.** 가중치·임계값을 이 셋에서 고르면 그 순간 비교용 자로서 쓸모가 없어진다. 튜닝이 필요하면 A 를 나눠 held-out 을 따로 만든다.

## 3. 측정

[`scripts/eval_retrieval.py`](../../../scripts/eval_retrieval.py), 맥미니에서:

```bash
.venv/bin/python scripts/eval_retrieval.py --label minilm 2>&1 | tee .cron/eval_retrieval_minilm.log
```

| 갈래 | 정의 |
|---|---|
| `vector` | Chroma 벡터만. `fetch_n` 청크를 가져와 **논문 단위로 중복 제거** (옛 baseline 은 청크 k개를 그대로 세서 논문 수가 k 보다 적었다 — 정의가 다르다) |
| `bm25` | BM25 만 |
| `production` | 운영 랭킹과 같은 경로 `hybrid_retrieve_paper_ids_for_eval` |

옛 스크립트의 레거시 가중치 그리드는 넣지 않는다 (§2.2-5).

### 3.1 제외 규칙 (결과를 보기 전에 적용)

정답 논문이 **Chroma 에 없는** 문항은 측정 전에 뺀다. JSONL 은 5,758편이지만 마지막 재구축(2026-05-20)은 5,628편이었다. 스크립트가 제외 목록을 출력하고 `summary.json` 에 남긴다. 정답이 여럿인 문항은 남은 정답만으로 잰다.

### 3.2 출력

`results/<label>/{vector,bm25,production}.jsonl` — 문항당 한 줄, [`eval_pairwise.py`](../../../scripts/eval_pairwise.py) 형식(`id`·`slot`=층·`model`·`ok`=Recall@5 적중). 그리고 `summary.json` (층별 Recall@5·Recall@10·MRR@10).

## 4. 이 자로 하는 비교의 규칙 (다음 라운드부터)

- **주 지표: A + C1 + C2 (164문항)의 Recall@5**, 짝지은 McNemar 정확검정 (`eval_pairwise.py --rule any`). B 는 연속성 확인용으로만 따로 보고한다.
- 층별 결과는 보고하되 **층별 검정은 사전에 지정한 가설이 있을 때만** 한다 (예: 하이퍼볼릭 가설은 C1·C2 를 겨냥하므로 그 라운드에서 미리 선언).
- 해상도: 164문항에서 1문항 = 0.61%p. p<0.05 에 필요한 불일치 분할은 **6:0 · 8:1 · 10:2 · 12:3 · 13:4 · 15:5**. 25문항 때와 같은 분할이 필요하지만 불일치가 생길 문항이 6.6배 많다.
- 같은 측정을 두 번 하면 결과가 같아야 한다 (결정적). 다르면 그 차이부터 원인을 찾는다.

## 5. 예상 (판정 아님 — 기록만)

결과를 본 뒤 맞춰 고치지 않도록 지금 적는다.

- E1: A 에서 `production` ≥ `vector`. 2026-04 의 25문항에서 벡터 단독이 가장 약했다 (Recall@5 0.28).
- E2: `bm25` 는 A(제목 단어를 피한 질의)에서 B(제목형 질의)보다 크게 떨어진다.
- E3: C2(기초 논문)는 `vector` 가 `bm25` 보다 낫다 — 제목 단어가 없어서.
- E4: C1(survey)은 세 갈래 모두에서 A 보다 Recall@5 가 높다 — 정답이 여럿이고 질의에 주제어가 있다. 그런데도 낮다면 일반성 불일치(넓은 질의에 좁은 논문)가 실재한다는 신호다.
