# num_absent_1107: 답에 있는데 근거 블록에 없는 숫자 진단 (dev, 오프라인)

> 측정 **전에** 쓴다. 저장된 답만 읽는다. LLM · Chroma 호출과 운영 변화는 없다. 출발점: [`unit_check_1106`](../unit_check_1106/README.md) 에서 범위 밖으로 둔 '숫자 없음' 칸이다. 사용자 요청(11-07).

## 1. 왜

[`core/llm/body_numbers.py`](../../../core/llm/body_numbers.py)는 **본론의 번호 항목**만 검사한다. 결론 다시 쓰기에도 숫자 검사가 있지만, 서론과 번호 없는 본론 문단은 검사하지 않는다. 지어낸 숫자는 RAG 답에서 가장 나쁜 오류이므로, 검사 밖에서 얼마나 나오는지 잰다.

## 2. 입력

`unit_check_1106` 과 같은 답 249개다(`weekly_20261101` · `pl0_dev` · `qt0_s2` · `ogb0_s2` · `ans_hu` · `sg0_new` · `sg0_old` · `nk1` · `us_1027`, held-out 제외, id 겹침 제거).

## 3. 규칙 ([`run.py`](run.py), 측정 전 고정)

답을 `서론` · `본론` · `결론` 으로 나누고 줄마다 숫자를 뽑는다.

- **뺀다:** `📎 DB 밖` 구역, `※ 요청한` 안내 줄, 줄 머리 항목 번호, 한 자리 정수, 연도(1900–2099 정수), 그 문항의 질문에 있는 숫자.
- **원문 쪽:** 깨진 소수점(`87 _._ 5`)은 고쳐 비교한다. 숫자 안의 쉼표는 지우고 값으로 비교하며, 이름 속 숫자(`BM25`)도 있는 것으로 친다.

| 칸 | 뜻 |
|---|---|
| 있음 | 그 줄이 인용한 블록(인용이 없으면 컨텍스트 전체)에 같은 값이 있다 |
| **A 다른 블록** | 인용 블록에는 없고 같은 컨텍스트의 다른 블록에 있다 |
| **B 어디에도 없음** | 컨텍스트 전체에 없다 |

## 4. 라벨

A · B 후보를 Claude 가 답 문장과 원문을 보고 나눈다. 후보가 80건을 넘으면 seed 1107 로 80건만 읽고 비율로 보고한다.

- **X:** 근거가 없다. 지어냈거나 잘못 옮겼거나 다른 문서의 값을 붙였다.
- **O:** 문제없다. 맞는 변환(0.85 → 85%) · 반올림 · 맞는 계산 · 문서와 무관한 말(예: 3단계로 나눠 설명)이다.
- **?:** 원문만으로 가릴 수 없다. 블록이 잘려 근거를 볼 수 없는 경우도 여기에 넣는다.

대조 조건이 없어 가릴 것은 없다.

## 5. 기준 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| 빈도: X | ≥ 5건 (읽은 비율로 환산) |
| 정밀도: X / (X + O) | ≥ 60% |

- **둘 다 통과:** 숫자 검사를 서론 · 번호 없는 문단까지 넓히는 라운드를 따로 사전 등록한다.
- **빈도만 통과:** 규칙으로 자동 삭제하지 않고, 오류 유형을 보고 다른 처리(문구 · 판단 호출)를 생각한다.
- **빈도 미달:** 코드를 만들지 않고 진단으로 끝낸다.
- 구역별 · 칸별 분포와 X 의 유형을 보고한다.

## 6. 한계

라벨은 Claude 한 명이 단다. 답은 11-07 이전 운영 조건이고, 원문에 있는 숫자를 틀린 사실에 붙인 오류는 이 규칙으로 보이지 않는다. 컨텍스트 밖 지식으로 맞게 쓴 숫자도 X 로 본다. 근거 없이 답한 것이기 때문이다.
