## v4 대비 무엇이 실제로 바뀌었나

1. **계획 슬롯의 개발 도구 커버리지** — 신규 151건 중 93건(62%)이 API 서버·조인/집계·검색·DB·JSON/로그 요청. v4분 249건은 59건(24%). 전체 400건 기준 38%. v4 실패 planner_06/07/08(Tavily·pandas 조인·FastAPI) 유형이 이제 학습 분포 안에 있다 (H1).
2. **코딩 주석 습관 제거** — `comment_heavy` 30건 거절. 거절 예: `print(lst[0]) # 첫 번째 원소 (1) 가 출력됨: lst.pop(0), del lst[:], 또는 슬라이싱 사용 가능하지만…` 처럼 한 줄 코드에 긴 설명 주석을 다는 패턴이 v4 실패(토큰 상한 잘림)의 원인이었고, v5 데이터에는 없다 (H2).
3. **코딩 비중 3배** — 100 → 300, 종류도 날짜·정규식·포매팅·자료구조·클래스·JSON으로 확장.
4. **`plan_n:0` 거절 7건은 v4 실패 양상 그 자체** — 베이스 모델도 "업로드한 이미지 크기 알려주는 API 엔드포인트" 같은 요청에서 `N단계:` 번호 없이 산문으로 쓴다(약 4%). 판정기가 걸러서 학습 데이터에는 번호 형식만 남았다.

## 남은 편향 (정직하게)

- **4~5단계 계획은 만들지 못했다.** 복합 시드("가져와서 정리하고 저장한 뒤 텔레그램으로 보내줘") 유래 38건 중 4단계 이상은 1건. 베이스 모델이 프롬프트의 "3~5단계"에도 불구하고 2~3단계로 접는다. v5는 여전히 "거의 항상 3단계"를 배운다. 개선하려면 자기 증류가 아닌 다른 생성원(더 큰 모델 또는 사람 작성)이 필요 — v6 과제.
- RAG instruction은 여전히 논문 컨텍스트 없는 순수 질문 (v4와 같은 한계).
- 잡담 300건 중 299건이 v4 raw 재사용 — 잡담은 v4와 사실상 같은 데이터에서 50건 줄인 것.
