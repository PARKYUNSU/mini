## 1. 작업 ① Semantic Scholar 기준 수집 보강

### 1.1 판단
- 대표 논문 누락은 실제 문제(11-10 점검: 주제별 인용 상위 5 편 중 DB 에 34%, 2023년 이전 2.4%). 다만 RankGPT · AWQ 는 고쳤으니, **누락률 재측정이 먼저**(현재 값이 34% 보다 낮을 수 있음).
- S2 를 쓰는 이유가 "영향력 인용 수 · 서베이 참고문헌" 이면 S2, "인용 수 상위" 만이면 키가 이미 있는 OpenAlex 로 같은 일을 할 수 있다. 권고: 후보 고르기는 S2(influential · 참고문헌), 메타데이터는 S2/arXiv 중 있는 쪽.
- 수집이 "바꿔 끼움"(collect_1113)이 되지 않게, 별도 DB 로 먼저 쌓고 **합치기 전에** 검색 보호 지표를 별도 DB 를 붙인 복제본으로 잰다.

### 1.2 S2 API (공식 문서 확인분 · 재확인 필요분)
- 공식 제품 페이지: 키 없는 호출은 모든 비인증 사용자가 **초당 1,000 회를 공유**(혼잡 시 더 제한). 키는 **처음 받으면 모든 엔드포인트 1 RPS**, 더 높은 한도는 심사. 대량은 Datasets 다운로드 권장.
- `POST /graph/v1/paper/batch` 요청당 ID **500 개**는 제3자 문서 기준 — 착수 때 공식 API 문서(api.semanticscholar.org/api-docs/graph)에서 다시 확인해 사전 등록에 적는다.
- 키: `.env` 에 아직 없음. 이름은 `S2_API_KEY`(환경변수로만, 출력 · 로그 · 커밋 금지; 요청 헤더 `x-api-key`). 키 발급 신청은 사용자가 직접.
- 1 RPS 기준 예상: 후보 5,000 편 메타데이터 = batch 10 회(500 개씩) 정도로 수 분, 참고문헌 확장(서베이 50 편 × 1 회)도 수 분. 키 없이 공유 한도로 돌리면 429 가 잦을 수 있어 재시도 · 백오프 필수.

### 1.3 무엇을 모을지 (후보 규칙 — 손으로 안 고름)
1. 씨앗: (a) 실패가 확인된 사례(2025 딥 리서치 · 11-10 점검에서 없던 상위 논문) (b) `external_candidates.jsonl` 의 1 질문 꼬리 1,013 편 (c) 운영 DB 안 서베이 논문(제목 survey/review)의 참고문헌.
2. 각 후보의 S2 `citationCount` · `influentialCitationCount` · `year` · `venue` · `externalIds`(ArXiv · DOI) · `abstract` · `title`.
3. 거르기: 분야(11-10 점검의 10 주제 + 사용자 직무 주제)에 맞는지는 초록 · 제목으로 27B 가 판정(doc_judge 프롬프트 재사용) · 연도별 상한(최근 쏠림 반대로 2023년 이전 몫을 둠) · 분야별 influential 상위 N.
4. 중복 제거: arXiv ID(버전 떼고) → DOI → 정규화 제목 순으로 운영 DB · JSONL 과 대조.
5. 초록 없는 논문(S2 는 일부 초록이 비어 있음)은 arXiv 초록으로 채우고, 없으면 뺀다.

### 1.4 쌓는 곳 — 별도 DB (기계에 안 묶이게)
- 원본: `data/s2_collect/papers.jsonl`(한 줄 한 논문, 원본 응답 필드 그대로 + 수집 시각). 이것이 진실의 원천 — 언제든 여기서 다시 짓는다.
- 색인: 별도 Chroma 폴더 `data/s2_collect/chroma/`(운영과 같은 임베더 · 같은 청크 규칙), 경로는 환경변수(`S2_COLLECT_DIR`)로만. 절대 경로 · 호스트 이름 하드코딩 금지 → M2 맥미니로 옮길 때 폴더 복사 + 환경변수만.
- 운영 DB 와 합치기는 실험이 없는 시점에 한 번, 승인 뒤. 합치기 전 운영 Chroma 스냅샷(내장 디스크).

### 1.5 효과 측정 (기준은 착수 때 결과 보기 전에 고정)
- 주: 11-10 대표 논문 점검(`audit_1110` §: 10 주제 × 인용 상위 5 = 50 편, 같은 OpenAlex 질의 · 같은 판정 규칙)을 **합친 복제본**에서 다시 돌려 DB 포함률 34%(→ 착수 시 재측정값)에서 얼마나 오르는지. 기준 후보: 포함률 +20%p 이상 · 그중 검색 상위 5 에 들어오는 비율도 보고.
- 보호(collect_1113 와 같은 세트): 162 · real40 · real2 · held-out 검색 ok 가 각 3 이상 안 떨어짐 · 대상 질문에서 이미 있던 관련 논문이 빠진 질문 20 이하.
- 인용 수를 추천형 질문 순위에 반영하는 것은 별도 실험(이 작업에서는 메타데이터로 저장만).

## 2. 작업 ② 답 뒤 문장 단위 근거 검증 (27B)

### 2.1 무엇을 하나
- 최종 답 본문(본론 · 결론)에서 인용 `[ID]` 가 붙은 문장을 나누고, 문장마다 인용 논문의 초록(+ 답 입력에 들어간 그 논문 청크)과 대조해 **지지 / 부분 지지 / 근거 없음** 판정. 한 답의 문장들을 한 번에 넣어 27B 1 회 호출(doc_judge 와 같은 JSON 스키마 방식).
- 대상 오류(blind_check_1113 · 사용자 평가): 출처 혼동(B05 RankGPT 항목에 APEER 인용, B21 설계 비교 연구를 Survey 로, B23 OmniBench 가 지적한 기존 연구 한계를 OmniBench 한계로), 과장(B20).

### 2.2 근거 없음일 때 처리 후보
| 처리 | 장점 | 단점 |
|---|---|---|
| 문장 삭제 | 틀린 주장이 사라진다 | 잘못 지우면 맞는 정보가 사라짐(11-01 9B 에서 지운 문장의 42% 가 맞는 문장). 문단 흐름이 끊김 · 항목이 비면 형식 깨짐 |
| 표현 완화(27B 가 초록 범위로 다시 씀) | 정보는 남기고 과장만 줄임 | 다시 쓰기가 새 오류를 만들 수 있음(결론 v3 · v4 에서 사실 오류 증가) · 호출 1 회 더 |
| 표시만(문장 끝 "(원문 확인 필요)") | 지우는 위험 0, 구현 단순 | 틀린 문장이 그대로 남음 · 표시가 많으면 읽기 나쁨 |
| 인용 고치기(다른 문서가 지지하면 그 ID 로) | 출처 혼동(B05 · B23)에 딱 맞음 | 같은 컨텍스트 안에 지지 문서가 있어야 함 |
- 권고: dev 에서 "표시만" 으로 판정 정확도부터 재고(처리 효과와 판정 정확도를 섞지 않기), 관문 통과 뒤 처리는 **인용 고치기 → 안 되면 완화**, 삭제는 판정 정밀도가 아주 높을 때만.

### 2.3 붙이는 자리 · 충돌
- 순서(지금 운영): 답 생성 → 항목 다시 쓰기 → 결론 다시 쓰기 → 인용 정리 → 형식 다듬기 · '없음' ID 정리 → 결론 수치 맞추기 → 텔레그램 링크. 검증은 **결론 수치 맞추기 뒤, 링크 앞**(최종 문장을 본다).
- 판정 집계(`RAG_JUDGE_AGG`) · 답 칸(`RAG_AGG_SLOTS`)과는 입력이 겹치지 않는다(그쪽은 답 전, 이쪽은 답 뒤). 단 칸 틀의 `(관련 연구)` 항목은 "부분 지지" 가 정상이므로 그 칸 문장은 '근거 없음' 일 때만 처리.
- "힌트 답 형식 강제" 실험과 같은 함수(`agent_nodes` 답 후처리)를 건드릴 수 있다 → 그 실험이 끝나고 병합된 뒤 착수.

### 2.4 메모리 · GPU
- 지금 상주: v13 4.8GB(ollama ps) + 27B 17GB(판정 때 올라옴). 여기에 chatbot 의 35B(`qwen3.6:35b-a3b-q4_K_M` 23GB)가 겹치면 모델 가중치만 ≈ 45GB + 컨텍스트 KV(8192 × 3 모델).
- 맥미니 64GB, `iogpu.wired_limit_mb` = 0(기본값 — macOS 기본 GPU 상한은 전체의 약 70–75%, ≈ 45–48GB). 세 모델이 동시에 오면 상한에 닿아 Ollama 가 모델을 내리고 다시 올린다(지연 수십 초). 동시 상주를 보장하려면 상한 올리기(`sysctl iogpu.wired_limit_mb`, **시스템 설정 변경 — 사용자가 직접**) 또는 chatbot 사용 시간과 겹침 허용. 착수 때 `ollama ps` 로 실제 크기를 다시 잰다.
- 시간: 27B 판정 1 회 ≈ 5–15s(답 문장 10–20 개 기준, doc_judge 가 문서 5 편에 ≈ 10s). 사용자 허용 범위.

### 2.5 측정 (기준은 착수 때 결과 보기 전에 고정)
- dev: B05 · B20 · B21 · B23 답 + 그 밖 blind_check_1113 의 맞는 답 문장(잘못 지움 측정용). 라벨은 판정자가 모델 출력 보기 전에 단다(문장마다 지지/부분/없음).
- held-out: 새 질문 30(업무형, 코퍼스 있음/없음 섞음)의 답 문장 전부를 판정자가 라벨링 → 모델 판정과 비교.
- 지표: 틀린 문장 잡은 비율(재현율), **맞는 문장을 '근거 없음' 으로 본 비율(오탐 — 더 무겁게)**, 추가 시간. 관문 후보: 오탐 ≤ 5% · 재현율 ≥ 50% · 추가 시간 중앙 ≤ +20s. 처리를 붙인 뒤에는 블라인드 쌍 + 사실 오류 문장 수로 한 번 더.
