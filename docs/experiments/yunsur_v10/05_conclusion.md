## 기준선이 밤 사이 움직였다 — 라운드 간 비교를 하면 안 되는 이유

측정 도중 코딩 실패율만 보고 "v10 17.8% < v9 21.1% 이므로 base 쪽으로 이동했다" 고 읽고 싶어진다. **그 읽기는 틀렸다.**

| | 코딩 strict | 그 세션의 base |
|---|---|---|
| v9 (2026-09-27) | 21.1% [14.0, 30.6] | 15.6% [9.5, 24.4] |
| **v10 (2026-09-28)** | **17.8%** [11.2, 26.9] | **18.9%** [12.1, 28.2] |

**base 가 15.6% → 18.9% 로 움직였다.** 영향을 받을 수 없는 대조군이 3.3%p 움직였다는 것은 그 밤의 노이즈 크기를 직접 보여준다 ([`../protocol.md`](../protocol.md) §2.2 가 대조군을 같은 세션에서 재라고 요구하는 이유다). 같은 밤 안에서 보면 v10(17.8%)과 base(18.9%)는 사실상 같고, 그것이 유효한 비교의 전부다.

v7 에서 기준선이 노이즈로 움직여 판정이 흔들렸던 것과 같은 현상이고, §2.3 의 **"단일 측정값을 다음 라운드의 판정 문턱으로 고정하지 않는다"** 가 이번에도 맞았다. 이 노트의 초안이 실제로 "v9 의 21.1% 미만" 을 통과 조건에 넣었다가 착수 전에 고쳤는데, 그대로 뒀다면 **기준선 이동만으로 통과 판정이 났을 것이다.**

## 그래서 운영은

**기본값대로 v9 를 유지한다.** §3 에 미리 적어둔 대로, 통과는 해롭지 않음을 뜻할 뿐 v9 대비 우위가 아니다. v10 vs v9 직접 비교는 **다른 밤의 측정**이라 판정에 쓸 수 없고(위 표가 그 이유를 보여준다), 바꿀 이유가 따로 없다.

바꾼다면 근거는 "lr 5e-5 가 v9 와 같은 결과를 더 안전한 쪽(작은 갱신)에서 얻는다" 는 것이겠지만, 그것을 측정으로 뒷받침하려면 v9 와 v10 을 **같은 세션에서** 짝지어 재야 한다. 지금 그럴 이유는 없다 — 둘 다 base 와 구분되지 않는다.

## lr 축에서 얻은 것

- **하이퍼파라미터 축이 처음 움직였다.** v3~v9 동안 2e-4 로 고정했던 것을 1/4 로 내려봤고, **세 운영 슬롯에서 손해가 없다**는 것을 확인했다. 문헌이 주 레버로 지목한 축인데(§3-(2)), 적어도 이 규모에서는 결과를 바꾸지 않는다.
- **측정의 천장은 그대로다.** §2 에 미리 적은 대로 이 라운드는 열화만 탐지할 수 있었고, 실제로 열화가 없었다. 개선을 보려면 문항이 더 어려워야 하고 그것은 base·v6·v9 재측정이 따르는 별도 결정이다.
- **다음은 replay** ([`../prior_work.md`](../prior_work.md) §3-(1)). 일반 데이터 출처를 정하는 준비가 필요하다. 더 낮은 lr 로 한 번 더 가는 것은 §3 에서 미리 약속하지 않았고, 이 결과가 그것을 요구하지도 않는다 — 5e-5 에서 아무것도 나빠지지 않았지만 좋아지지도 않았다.
