# HyPE 논문 단위 색인 — 가상 질문 갈래 (사전 등록, 2026-10-14)

> 측정 **전에** 쓴다. 근거: [`lit_review_1014/`](../lit_review_1014/) — HyPE(2607.29402)는 청크마다 가상 질문을 색인해 검색을 질문↔질문 매칭으로 바꿔 recall 을 크게 올렸다. 우리 병목은 정답이 컨텍스트에 안 들어오는 24/162 (15%).

## 1. 바꾸는 것

1. **색인 (1회 + 매일 수집분):** Chroma 의 논문 7,004편마다 제목·초록으로 가상 질문 4개를 만든다. 각 질문마다 두 줄을 색인:
   - 영어 자연어 질문 1줄
   - 운영 검색어 추출기(`agent_nodes._extract_english_rag_query`)와 같은 형식의 **영어 핵심 키워드 3~5개** 1줄 — 운영 검색은 한국어 질문을 이 키워드로 바꾼 뒤 벡터·BM25 를 돈다.
   → 컬렉션 `paper_questions` (같은 Chroma, 임베더 같음), 메타데이터 `paper_id`·`kind`(question/keywords)·`qi`.
2. **검색 (`RAG_HYPE=1`, 기본 꺼짐):** `ChromaRAGTool.search` 에서 같은 검색어(멀티 쿼리 base)로 `paper_questions` 를 조회 → 논문별 최소 거리 `d_q` 상위 `HYPE_TOP_PAPERS=5`.
   - 후보 풀에 없는 논문: 그 논문 청크를 넣고(제목 주입과 같은 `_fetch_depth_chunks`) 거리를 `d_q` 로 둔다.
   - 후보 풀에 있는 논문: 그 논문 청크 거리를 `min(기존, d_q)` 로.
   - 이후 하이브리드 점수·논문 단위 재순위는 기존 코드 그대로.

질문 생성: RunPod H100 vLLM gpt-oss-120b (temperature 0.7, 논문당 1회 호출, JSON 출력) — 생성물은 `questions.jsonl` 로 커밋. 생성 실패·형식 오류 논문은 1회 재시도 후 제외(수 보고).

## 2. 측정

- 같은 Chroma(서버 모드, 측정 중 다른 쓰기 없음)에서 `RAG_HYPE=0/1` 두 번씩, 검색만(`eval_e2e_ko.py` 기본 모드).
- 세트: 기존 162문항 · HF 40문항(hf_coverage_1012) · 실제 사용형 40문항(real_eval_1013; N·C·T 의 정답).
- **지표:** 정답 논문이 컨텍스트에 있음(`ok`). C 는 두 편 모두, T 는 정답 집합 중 ≥1 (T 는 참고).

## 3. 채택 규칙

| 지표 | 기준 |
|---|---|
| **주:** 162 + HF40 합친 202문항 `ok` 짝 | 처리 > 대조, McNemar 양측 p < 0.05 |
| 각 세트(162 · HF40 · real40) | 처리가 유의하게 낮지 않음 (p ≥ 0.05 또는 처리 우위) |
| 지연 | 검색 단계 문항당 중앙값 +2s 이하 |

채택이면 **사용자 승인 후** 운영 `.env` `RAG_HYPE=1`, 일일 수집에 질문 생성 추가.

예상: 162 는 이미 85% 라 +3~6문항(유의 경계), HF40 은 29 → 31~33, real40 의 N(수치)·C(비교)에서 개선이 더 크다.
