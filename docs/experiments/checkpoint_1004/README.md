# 기전 라운드 — 변수는 **lr 크기**인가 **누적 갱신량**인가 (사전 등록)

- 시작일: 2026-10-04
- 선행: [`../yunsur_v11/05_conclusion.md`](../yunsur_v11/05_conclusion.md) (계단이다) · [`../length_mechanism_1003.md`](../length_mechanism_1003.md) (기전 탐색) · [`../protocol.md`](../protocol.md) §3
- **새 모델을 만들지 않는다.** v9 설정(lr 2e-4 · v9 데이터 · 시드 3407 · 138스텝)을 **그대로** 다시 돌리면서 중간 어댑터만 남긴다. 바뀌는 것은 `SAVE_STEPS` 하나이고, 이것은 학습을 바꾸지 않는다.
- 비용: 학습 1회(~$0.3) · 측정 1회(6모델 ≈ 8.5시간)

## 1. 묻는 것

[`../protocol.md`](../protocol.md) §3 이 올린 결론은 **계단**이다 — lr 2e-4(v9)와 1e-4(v11)는 계획 길이 제약에서 구분되지 않고, 5e-5(v10)만 떨어져 있다. 그런데 "lr" 은 두 가지를 동시에 뜻한다:

- **스텝당 갱신 크기** — 한 번에 얼마나 크게 움직이나
- **누적 갱신량** — 138스텝 동안 통틀어 얼마나 움직였나

둘은 v9·v10·v11 에서 **완전히 붙어 있다.** 스텝 수와 스케줄 모양이 같으므로 누적량 비는 peak 비와 똑같다 (v10 = v9의 1/4, v11 = 1/2). 지금까지의 세 라운드로는 **가를 수 없었다.**

가르는 방법: **한 학습 안에서 중간에 멈춰 본다.** lr 2e-4 로 달리다 누적량이 v10 의 총량과 같아지는 지점에서 어댑터를 꺼내면, **누적량은 v10 과 같고 스텝당 lr 은 v9 과 같은** 모델이 생긴다.

### 멈출 지점 계산

lr 스케줄은 warmup 10스텝(0→peak) 뒤 138스텝까지 선형 감쇠다. 세 모델이 **모양이 같고 peak 만 다르므로**, "v9 누적의 몇 %" 는 peak 와 무관한 스케줄의 성질이다. 정규화 누적을 수치적으로 적분하면:

| 목표 | 스텝 |
|---|---|
| v10(5e-5) 총 누적량 = v9 누적의 **25%** | **23** |
| v11(1e-4) 총 누적량 = v9 누적의 **50%** | **46** (정확히는 45, 아래 참조) |

lr 이 일정하다면 34·69 겠지만 감쇠 때문에 더 이르다 — 초반 스텝이 lr 이 높아 누적이 빨리 쌓인다.

`SAVE_STEPS=23` 하나로 23·46·69·92·115 에 저장된다. 45 대신 46 을 쓰는 오차는 누적 기준 3%이고(목표 34.50 → 실제 35.58, 45 는 34.85), **간격 하나로 두 정합 지점과 궤적용 여분까지 공짜로 얻는** 쪽을 택했다. 어댑터가 130MB 뿐이라 전부 남긴다.

## 2. 가설 — 두 쌍의 **정합 비교**

| 쌍 | 누적량 | 스텝당 lr |
|---|---|---|
| **ckpt23** vs **v10** | 같다 | 2e-4 ↔ 5e-5 |
| **ckpt46** vs **v11** | 같다 | 2e-4 ↔ 1e-4 |

- **H1 (누적량 가설)**: 행동은 통틀어 얼마나 움직였는지로 정해진다 → **ckpt23 이 v10 처럼 행동한다** (길이 제약을 잘 지키고 v9 을 이긴다).
- **H2 (lr 크기 가설)**: 스텝당 갱신 크기가 독립적으로 작용한다 → **ckpt23 이 v9 처럼 행동한다** (제약이 약하고 v10 에게 진다).
- **H3 (너무 이르다)**: ckpt23 이 **base 와 구분되지 않는다.** 23스텝에서는 아직 아무 성질도 생기지 않았다는 뜻이고, 그러면 이 설계로는 가를 수 없다.

**H1 과 H2 는 ckpt23 에 대해 정반대를 예측한다.** v10 은 16문항 중 15개, v9 은 7개를 통과했으므로(§3) 둘의 차이는 커서 쉽게 보인다.

## 3. 설계의 약점 — 먼저 적는다

**이 비교는 누적 갱신량과 데이터 커버리지를 분리하지 못한다.**

ckpt23 은 23 × 8 = **184 예시**만 봤다 (1,100건의 17%). v10 은 1,100건 전부를 봤다. 옵티마이저 모멘트 상태도 다르다. 그래서 결과의 해석력이 **한쪽으로만 강하다**:

| 결과 | 해석 |
|---|---|
| **ckpt23 ≈ v10** | **강하다.** 데이터의 17%만 보고도 v10 의 성질이 나왔다면, 커버리지는 변수가 아니고 **누적 갱신량이 변수**다 |
| **ckpt23 ≈ v9** | **약하다.** lr 크기 때문일 수도, 데이터를 덜 봐서일 수도 있다 — 가르지 못한다 |

이 비대칭을 미리 적는 이유: 두 번째 경우가 나왔을 때 "lr 크기가 변수다" 로 결론 내리고 싶어질 것이다. **그렇게 쓰지 않는다.** 그 경우는 "가르지 못했다" 로 적고, 커버리지를 맞추는 후속 설계를 따로 세운다 (예: 5e-5 로 552스텝 = 4에포크 — 다만 다중 에포크 암기가 새 교란으로 들어온다).

**단일 변수 설계가 없다는 것도 적어 둔다.** 스텝 수를 줄이면 커버리지가 줄고, 커버리지를 지키면 에포크가 늘고, lr 을 바꾸면 그게 원래 재려던 변수다. 셋을 동시에 고정할 수 없다. 그래서 이 라운드는 **한쪽 방향으로만 결정적**이고, 그 사실을 결론에 그대로 쓴다.

## 4. 측정

[`scripts/eval_multi_round.sh`](../../../scripts/eval_multi_round.sh) 로 **6모델을 같은 세션**에서 잰다 (150문항 × 3회, sha256 `967eeb460559`).

```bash
nohup caffeinate -i bash scripts/eval_multi_round.sh ckpt \
  yunsur_ckpt23 yunsur_ckpt46 yunsur_v9 yunsur_v10 yunsur_v11 > .cron/eval_ckpt.log 2>&1 &
```

6모델을 한 밤에 넣는 이유는 §2.2 다 — 정합 비교(ckpt23↔v10, ckpt46↔v11)가 **쌍 비교**이므로 한쪽이 다른 밤이면 성립하지 않는다. base 는 노이즈 자이자 H3 의 판정 대상이다.

**주 지표**: `planner_33`~`48` 16문항, 3회 다수결 — [`../yunsur_v11/README.md`](../yunsur_v11/README.md) 와 **같은 자**다. 바꾸지 않는다.

### 선행 확인 — 두 학습이 같은가

ckpt23·ckpt46 은 **새 학습(run B)** 에서 나오고 v9 은 **원래 학습(run A)** 의 산출물이다. 데이터·시드·스텝이 같아도 GPU 비결정성 때문에 똑같지는 않다. 측정 전에 **run B 의 최종 어댑터(step 138)와 v9 어댑터를 수치로 비교한다** — 텐서별 최대 절대차와 코사인 유사도.

- 사실상 같으면(코사인 > 0.999) 기존 `yunsur_v9` 모델을 그대로 쓴다.
- 눈에 띄게 다르면 run B 의 최종본도 머지해 **7번째 모델**로 같이 재고, 그 사실을 결론에 적는다.

이 확인은 측정이 아니라 **전제 점검**이므로 주 지표를 보지 않는다 (가중치만 본다).

## 5. 판정 (사전 선언 — 결과를 본 뒤 바꾸지 않는다)

### 5.0 문지기

**v9 vs v10 이 재현되어야 해석한다** — 여섯 번째 재현이다. 주 지표 16문항에서 불일치가 v10 쪽으로 쏠리고 McNemar **p < 0.05**. 깨지면 이 라운드는 **판정 불가**로 적고 "여섯 번째 세션에서 재현이 깨졌다" 를 결과로 남긴다.

### 5.1 주 판정 — ckpt23 은 누구를 닮았나

두 검정을 쓴다. 둘 다 주 지표 16문항 · 짝지은 McNemar 정확검정 · α = 0.05.

| | 검정 | 묻는 것 |
|---|---|---|
| T1a | ckpt23 vs v10 | 누적량이 같은 두 모델이 **다른가** |
| T1b | v9 vs ckpt23 | ckpt23 이 **v9 을 이기는가** |

**조합으로만 읽는다** (어느 한쪽을 독립된 발견으로 주장하지 않으므로 보정을 따로 걸지 않는다):

| T1a | T1b | 판정 |
|---|---|---|
| 비유의 | **유의** (ckpt23 쪽) | **H1 — 누적 갱신량이 변수다** (§3 대로 강한 결론) |
| **유의** (v10 쪽) | 비유의 | **H2 방향이지만 가르지 못했다** — lr 크기일 수도, 커버리지일 수도 (§3) |
| 유의 | 유의 | **중간** — ckpt23 이 v9 보다 낫지만 v10 에는 못 미친다. 부분적 누적량 효과로 적고 좌표를 더 찾지 않는다 |
| 비유의 | 비유의 | **판정 불가** (아래 H3 와 같이 읽는다) |

**H3 확인**: base vs ckpt23 이 비유의이고 **동시에** T1b 도 비유의면, 23스텝에서는 성질이 아직 없는 것으로 보고 **판정 불가**로 적는다. 그 경우 `SAVE_STEPS` 로 남겨 둔 **step 69·92·115** 로 같은 질문을 다시 물을 수 있다 — 재학습 없이.

**검정력 조항** (§2.3): 어느 검정이든 불일치 쌍이 **6개 미만**이면 그 검정은 **판정 불가**이고 "차이 없음" 으로 읽지 않는다.

### 5.2 두 번째 정합 지점 (확인용, 판정에 포함)

**T2a** ckpt46 vs v11 · **T2b** v9 vs ckpt46 — 같은 규칙. **T1 과 같은 방향이면 결론을 강화하고, 어긋나면 그 사실을 적는다.** 어긋남을 "잡음" 으로 처리하지 않는다.

### 5.3 참고 지표 (판정 아님 — 기록만)

- **RAG 템플릿 이탈 수.** v9 24/24 · v11 24/24 · v10 9/24 · base 5/24 였다 ([`../yunsur_v11/05_conclusion.md`](../yunsur_v11/05_conclusion.md) §3). ckpt23·ckpt46 이 어디 놓이는지 — 주 지표와 **독립된 두 번째 행동**이라 같은 계단이 나오면 해석을 떠받친다. RAG 는 §5.2 가 판정 사용을 금지한다.
- 계획 슬롯 실패율과 Wilson 구간 · 코딩 실패율(맞교환) · 계획 단계줄 길이 · 고정 슬롯당 길이.
- loss 궤적: 중간 체크포인트의 loss 를 v10·v11 최종 loss 와 나란히 적는다. v11 에서 **loss 는 단조인데 행동은 계단**이었으므로, loss 가 행동을 예측하지 못하는 것을 다시 확인한다.
