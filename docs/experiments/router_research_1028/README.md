# 라우터 3단계 질문도 15 편 다시 검색해 거르기 (사전 등록, 2026-10-28)

> 측정 **전에** 쓴다. 출발점: filter_before_cut_1028(운영 ON 10-28 20:10)은 direct_answer 가 `rag.search(top_k=15)` 를 부르는 경로에만 닿는다. 라우터 3단계 LLM 분류로 온 질문은 라우터가 찾은 5 편(`RAG_PAPER_BLOCKS=1`)을 그대로 쓴다(로그 `rag_context reused from router`). fb1 로그에서 이 경로가 H 20/30 · D 21/34 · U 20/34 · 162 35/162 — 실사용 job 134(10-28)도 이 경로.

## 1. 바꾸는 것 — `RAG_ROUTER_RESEARCH=1` (기본 0, `RAG_RELEVANCE_FILTER=1` · `RAG_FILTER_BEFORE_CUT=1` 일 때만)

`core/graph/agent_nodes.py` direct_answer: 라우터 컨텍스트를 재사용하지 않고 일반 경로처럼 `rag.search(top_k=15)` → 15 편 거르기 → 앞 5 편. 라우터는 그대로(분류용 5 편 검색 유지). 목록 모드 · 단일 논문 · 이어지는 질문 재사용은 그대로.

## 2. 방법 (맥미니, 검색 + 거르기 — `--answer` 없음)

대조 `rr0_*`(운영 `.env` 그대로 = 자르기 앞 거르기 ON) · 처리 `rr1_*`(`RAG_ROUTER_RESEARCH=1`): 162 · real40 · real2 · H · D · U. 스크립트 `.cron/run_rr.sh`.

관련성 판정: H · D · U 두 조건 컨텍스트 논문 중 아직 판정 안 된 쌍만 섞어 조건을 모른 채 0 · 1 · 2 판정. 기존 판정(corpus_seed · query_norag_1027 · fusion_protect_1027 · filter_before_cut_1028) 재사용. `pool.py` · `score.py`.

## 3. 판정 (측정 전 고정)

| 지표 | 기준 |
|---|---|
| **주:** H + D + U (98) — 질문별 컨텍스트 '2' 논문 수 | 처리 > 대조, 부호 검정(동점 제외) 양측 p < 0.05 |
